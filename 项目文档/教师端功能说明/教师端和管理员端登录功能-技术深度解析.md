# 教师端和管理员端登录功能 — 技术深度解析

## 一、功能概述

教师端和管理员端共用同一套登录体系，基于 Sa-Token 1.38 + BCrypt 构建，前端通过 vue-naive-admin 管理后台的登录页选择角色（教师/管理员）发起认证，后端通过统一认证端点完成密码验证、角色校验与令牌签发。

### 功能清单

| 功能 | 前端页面/组件 | 后端端点 | 认证要求 |
|---|---|---|---|
| 登录 | login/index.vue | `POST /api/auth/login` | 无（放行路径） |
| 获取验证码 | login/index.vue | `GET /api/auth/captcha` | 无 |
| 获取用户信息 | 路由守卫/权限加载 | `GET /api/auth/userinfo` | 需登录 ⚠ 后端路径无连字符，前端发 /user-info 会 404 |
| 登出 | UserAvatar.vue | `POST /api/auth/logout` | 需登录 |
| 刷新令牌 | Axios 拦截器 | `POST /api/auth/refresh-token` | 需登录 |
| 修改密码 | profile/index.vue | `POST /api/auth/change-password` | 需登录 |
| 检查用户名 | login/index.vue | `GET /api/auth/check-username` | 无 |
| 检查邮箱 | login/index.vue | `GET /api/auth/check-email` | 无 ⚠ 后端无此端点，调用会返回 404 |
| 忘记密码 | login/index.vue | `POST /api/auth/forgot-password` | 无 |
| 发送邮箱验证码 | login/index.vue | `POST /api/auth/send-email-code` | 无 |
| 更新资料 | profile/index.vue | `POST /api/auth/update-profile` | 需登录 |
| 绑定邮箱 | profile/index.vue | `POST /api/auth/bind-email` | 需登录 |
| 检查登录状态 | 自动 | `GET /api/auth/check-login-status` | 无 |

### 统一认证架构

所有角色（用户/教师/管理员）共用同一套认证端点 `/api/auth/**`，无独立的 `/api/admin/login` 或 `/api/teacher/login`。

```
┌─────────────────────────────────────────────┐
│           CompleteUnifiedAuthController       │
│         /api/auth/** （统一认证入口）          │
├─────────────────────────────────────────────┤
│  POST /api/auth/login        → 统一登录      │
│  POST /api/auth/register     → 统一注册      │
│  GET  /api/auth/captcha      → 图形验证码    │
│  POST /api/auth/logout       → 统一登出      │
│  POST /api/auth/refresh-token → 令牌刷新     │
│  GET  /api/auth/userinfo     → 用户信息      │
│  POST /api/auth/change-password → 改密码     │
│  ...其他端点                                 │
└─────────────────────────────────────────────┘
          │
          ▼
   UnifiedAuthServiceEnhanced.login()
   ├── 验证码校验（Redis）
   ├── 用户名查找
   ├── BCrypt 密码校验
   ├── 账户状态检查
   ├── 角色权限校验（role 参数）
   ├── StpUtil.login(userId)
   └── 返回 LoginResponse
```

### 数据库 RBAC 设计

```
user 表 ──(1:N)── user_role 表 ──(N:1)── role 表
  id              user_id                id
  username        role_id                role_name（中文名：管理员/教师/用户）
  password                               role_code（英文码：ADMIN/TEACHER/USER）
  name
  status
```

三表多对多设计，角色通过 `user_role` 中间表关联，`@SaCheckRole` 注解使用中文 `role_name`（"管理员"/"教师"/"用户"）进行鉴权。

#### 登录提交流程

```typescript
const handleLogin = async () => {
  // 1. 手动校验
  if (!username || !password) return $message.warning('请输入用户名和密码')
  if (!captcha) return $message.warning('请输入验证码')

  loading.value = true

  // 2. 调用登录 API
  const { data } = await api.login({
    username,
    password: password.toString(),
    captcha,
    captchaKey,
    role: activeTab.value   // '教师' 或 '管理员'
  })

  // 3. 记住我处理
  if (isRemember.value) {
    lStorage.set('loginInfo', { username, password, role: activeTab.value })
  } else {
    lStorage.remove('loginInfo')
  }

  // 4. 登录成功回调
  onLoginSuccess(data)
}
```

#### 登录成功处理

```typescript
const onLoginSuccess = async (data) => {
  const { token, expiresIn } = data

  // 1. 存储 Token
  authStore.setToken({ accessToken: token, expiresIn })

  // 2. 存储用户信息
  userStore.setUser(data)
  // data 包含: userId, username, nickname, phone, avatar, token, expiresIn, roles

  // 3. 跳转
  const redirect = route.query.redirect || '/'
  router.push(redirect)
}
```

### 2.3 Token 管理

#### Auth Store（Pinia + 持久化）

**文件**: `src/store/modules/auth.js`

```typescript
// State
{
  accessToken: undefined,      // Sa-Token 生成的 simple-uuid
  expiresIn: undefined,        // 令牌有效期（秒）
  tokenExpireTime: undefined,  // 过期时间戳(ms)
  userInfo: undefined
}

// Persist: pinia-plugin-persistedstate
// localStorage key: "vue-naivue-admin_auth"
```

**setToken 动作**:

```typescript
setToken({ accessToken, expiresIn }) {
  this.accessToken = accessToken
  this.expiresIn = expiresIn || 86400  // 默认 24 小时
  this.tokenExpireTime = new Date().getTime() + (this.expiresIn * 1000)
}
```

⚠ 前端默认 `expiresIn` 为 86400（24 小时），但后端 Sa-Token 配置 `timeout: 2592000`（30 天），前后端过期时间默认值不一致。

#### Token 附加方式（Axios 拦截器）

**文件**: `src/utils/http/interceptors.js`

```typescript
// 请求拦截器 reqResolve
if (config.needToken === false) {
  // 跳过 Token 附加
} else if (token) {
  // 检查是否即将过期（<30分钟）
  if (isTokenExpiringSoon()) {
    // 尝试静默刷新 Token
    await authStore.refreshToken()
  }
  // ⚠ 以 Bearer 格式附加到 Authorization 头
  config.headers.Authorization = `Bearer ${accessToken}`
}
```

**⚠ 前后端 Token 传递方式不一致**：

> 各端 Token 传递方式详见 [公共参考-前端 Token 传递方式](../../公共参考/公共数据模型与基础配置.md#二认证与权限体系sa-token)

vue-naive-admin 仅发送 `Authorization: Bearer` 头，未发送 Sa-Token 默认的 `mqxqtoken` 头或 Cookie，需后端额外配置才能识别 Bearer 格式。

#### Token 刷新机制

```
请求拦截器检测 Token 即将过期（<30分钟）
│
├── isRefreshing === false → 发起刷新
│   ├── authStore.refreshToken()
│   │   → POST /api/auth/refresh-token
│   │   → 返回新 token + expiresIn
│   ├── setToken(newToken)
│   ├── 重放队列中的请求（requestsQueue）
│   └── isRefreshing = false
│
├── isRefreshing === true → 排入队列等待
│   └── requestsQueue.push(resolve)
│
└── 刷新失败 → authStore.logout() → 跳转登录页
```

防并发刷新：`isRefreshing` 标志 + `requestsQueue` 请求队列，确保同时只有一个刷新请求。

#### 401/4004 响应处理

```typescript
// 响应拦截器 reqReject
if (response.status === 401 || response.data?.code === 4004) {
  // Token 无效/过期
  if (!isRefreshing) {
    isRefreshing = true
    try {
      await authStore.refreshToken()
      // 重放队列请求
    } catch {
      authStore.logout()  // 刷新失败 → 登出
    }
  }
  return new Promise(resolve => requestsQueue.push(resolve))
}
```

## 三、后端执行流程

### 3.1 Sa-Token 认证架构

> Sa-Token 认证架构详见 [认证系统指南](../公共参考/认证系统指南.md) 及 [公共参考-认证与权限体系](../../公共参考/公共数据模型与基础配置.md#二认证与权限体系sa-token)

**登录模块鉴权特殊性**：`/api/auth/**` 路径在 SaInterceptor 中整体放行，导致 `change-password`、`update-profile`、`user-info` 等需登录端点不经过拦截器的登录检查，其认证保护完全依赖控制器方法级别的 `@SaCheckLogin` 注解或服务层手动调用 `StpUtil.checkLogin()`。

### 3.3 登录端点（`POST /api/auth/login`）

```
请求体: LoginRequest {
  username: String (@NotBlank),   ⚠ 无 @Size 约束，实际仅有 @NotBlank
  password: String (@NotBlank),   ⚠ 无 @Size 约束，实际仅有 @NotBlank
  captcha: String (@NotBlank),   ⚠ 无 @Size 约束，实际仅有 @NotBlank
  captchaKey: String (@NotBlank),
  role: String (可选, 指定登录角色)
}
│
┌─ 步骤1: 验证码校验
│  ├── Redis 读取 key = "login_captcha:{captchaKey}"
│  ├── 比对 captcha（忽略大小写）
│  ├── ⚠ 验证码使用后立即删除（Redis DEL）
│  └── 不匹配 → MyException("验证码错误")
│
┌─ 步骤2: 用户名查找
│  ├── userDao.selectByUsername(username)
│  │   SQL: SELECT ... FROM user WHERE username = #{username} LIMIT 1
│  └── null → MyException("用户名错误")
│
┌─ 步骤3: 密码校验（BCrypt）
│  ├── SaUtil.isBc(password, user.getPassword())
│  │   → BCrypt.checkpw(oriPassword, encode)
│  └── false → MyException("密码错误")
│
┌─ 步骤4: 账户状态检查
│  ├── user.getStatus() == 0 → MyException("账户已被禁用")
│  └── status == 1 → 正常
│
┌─ 步骤5: 角色校验（仅当 role 参数非空时）
│  ├── userService.getUserRoleNames(user.getId())
│  │   SQL: SELECT r.role_name FROM user_role ur
│  │        LEFT JOIN role r ON ur.role_id = r.id
│  │        WHERE ur.user_id = #{userId} ORDER BY r.role_name
│  ├── 检查返回的 role_name 列表是否包含 request.getRole()
│  └── 不包含 → MyException("无权限访问")
│  ⚠ role 值为中文角色名（"管理员"/"教师"），非 role_code
│
┌─ 步骤6: Sa-Token 登录
│  ├── StpUtil.login(user.getId())
│  │   → 以 user.id (Integer) 作为 loginId
│  │   → 生成 simple-uuid Token
│  │   → 写入 Redis（Sa-Token 会话存储）
│  │   → is-concurrent=false → 踢出同账号旧会话
│  └── StpUtil.getTokenValue() → 获取生成的 Token
│
┌─ 步骤7: 更新用户最后登录时间
│  └── user.setUpdateTime(new Date()) → userDao.update(user)
│
└─ 返回 Result<LoginResponse>
    字段: userId, username, nickname, phone, avatar,

```

### 3.12 密码处理

**SaUtil** 工具类：

```java
// 加密
public static String toBcPassword(String password) {
    return BCrypt.hashpw(password, BCrypt.gensalt());
}

// 校验
public static boolean isBc(String oriPassword, String encode) {
    return BCrypt.checkpw(oriPassword, encode);
}
```

| 场景 | 密码处理 |
|---|---|
| 登录校验 | `BCrypt.checkpw(输入明文, 数据库hash)` |
| 注册 | `BCrypt.hashpw(明文, gensalt())` → 存储 hash |
| 管理员重置 | 重置为 `"123456"` → `BCrypt.hashpw("123456", gensalt())` 存储 |
| 修改密码 | 校验旧密码 + `BCrypt.hashpw(新密码, gensalt())` 更新 |

## 五、已知问题与风险点

> 跨模块系统级问题见 [公共参考-系统级已知问题与风险清单](../../公共参考/系统级已知问题与风险清单.md)，此处仅列本模块独有问题。

| # | 问题 | 严重度 | 说明 |
|---|---|---|---|
| 1 | **前端 Token 传递方式与 Sa-Token 默认不匹配** | 高 | vue-naive-admin 发送 `Authorization: Bearer <token>`，Sa-Token 默认从 `mqxqtoken` 头或 Cookie 读取，需后端额外配置才能识别 Bearer 格式 |
| 2 | **默认凭据硬编码在前端** | 高 | 登录页 Tab 切换自动填充 `teacher1/123456` 和 `admin/123456`，攻击者可直接获取默认账号 |
| 3 | **权限树前端硬编码** | 高 | 管理员/教师权限树在 `settings.js` 静态定义，无后端动态获取（`getRolePermissions` API 已注释），前端修改可绕过权限 |
| 4 | **StpInterfaceImpl 返回空权限列表** | 中 | `getPermissionList()` 返回空列表，`@SaCheckPermission` 注解不可用，所有权限控制仅到角色级别 |
| 5 | **`/api/auth/**` 全路径放行** | 中 | 拦截器排除整个 `/api/auth/**`，`change-password`、`update-profile` 等需登录端点依赖方法级注解，若遗漏则无认证保护 |
| 6 | **前端 expiresIn 默认值不一致** | 低 | 前端 `setToken` 默认 expiresIn=86400（24小时），后端 Sa-Token 配置 timeout=2592000（30天），仅当后端返回 expiresIn 时覆盖 |
| 7 | **角色切换 API 已注释** | 中 | `switchCurrentRole` API 在 `api/index.js` 中被注释，多角色用户切换仅前端状态变更，后端不知晓当前角色 |
| 8 | **验证码一次性使用** | 低 | 验证码校验后立即从 Redis 删除，输入错误需重新获取，体验略差但安全性合理 |
| 9 | **注册无法创建管理员** | 低 | 注册仅可创建 USER 或 TEACHER 角色，ADMIN 必须由管理员手动创建，设计合理但应文档化 |
| 10 | **角色使用中文名鉴权** | 中 | `@SaCheckRole("管理员")` 使用中文角色名，依赖 `role_name` 而非 `role_code`，数据库角色名变更会导致鉴权失效 |
| 11 | **无登录失败次数限制** | 高 | 登录端点无失败计数与锁定机制，可被暴力破解（虽有验证码缓解，但验证码可被 OCR 破解） |
| 12 | **管理员重置密码为固定值** | 中 | 重置密码统一为 `"123456"`，安全性低，应生成随机密码或要求用户首次登录修改 |
| 13 | **前端无正式表单验证** | 低 | 登录表单使用手动 `if` 检查，无 Naive UI `n-form` 验证规则，无法提供精确错误提示 |
| 14 | **角色删除不检查用户关联** | 中 | 除系统角色(ADMIN/USER/TEACHER)外，自定义角色删除时不检查 `user_role` 关联，可能产生孤立记录 |
| 15 | **前后端角色状态不同步** | 中 | 前端 Pinia 存储的角色信息在登录后不再更新，后端角色变更后前端仍使用旧角色 |
| 16 | **is-concurrent=false 静默踢出** | 中 | 新登录踢出旧会话无通知机制，被踢用户下次请求才收到 401，无实时推送 |
| 17 | **check-email 幽灵端点** | 高 | 前端 api.js 定义了 `GET /api/auth/check-email`，但后端 CompleteUnifiedAuthController 无此映射，调用必返回 404 |
| 18 | **change-password/update-profile HTTP 方法不匹配** | 高 | 前端 api.js 用 PUT 发送请求，后端控制器用 @PostMapping，请求会被 405 Method Not Allowed |
| 19 | **LoginRequest 无长度约束** | 中 | LoginRequest 仅有 @NotBlank，无 @Size 注解，可提交超长字符串（如 username 10000 字符），无服务端长度保护 |
| 20 | **验证码类型描述错误** | 低 | 文档原描述为"图片验证码（简单字符）"，实际为 Kaptcha 算术表达式（如 `3+5=?`），用户需计算而非识别字符；MIME 类型为 image/jpeg 非 image/png |
| 21 | **loginInfo 默认值与实际代码不符** | 低 | 文档原描述 loginInfo 为 reactive() 且字段默认空值，实际为 ref() 且默认填充 teacher1/123456；isRemember 默认 true（非 false），localStorage key 为 'isRemember'（非 'loginInfo-isRemember'） |
| 22 | **Token 刷新机制描述错误** | 中 | 文档原写 StpUtil.refreshToken()，实际调用 StpUtil.renewTimeout(getTokenTimeout())，为续期当前 Token 而非生成新 Token；前端期望返回新 token，但 renewTimeout 不改变 Token 值 |
