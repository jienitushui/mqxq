# 教师端作业功能 — 技术深度解析

## 一、功能概述

教师端作业模块提供作业发布/管理、作业提交管理、作业批改、数据统计四大功能，涉及前端四个页面组件、三个后端控制器及两套 Service/DAO 体系。

### 功能清单

| 功能 | 前端页面/组件 | 后端端点 | 认证要求 |
|---|---|---|---|
| 作业列表（分页） | homework/index.vue | `GET /api/teacher/homework/list` | `@SaCheckRole("教师")` |

### 控制器分工

| 控制器 | 基础路径 | 职责 |
|---|---|---|
| CourseHomeworkTeacherController | `/api/teacher/homework` | 作业 CRUD + 提交查询 + 批改(方式一) |
| CourseHomeworkManageController | `/api/teacher/homework-manage` | 批量操作 + 复制 + 统计 + 导出 + 延期 |
| HomeworkSubmissionTeacherController | `/api/teacher/homework-submission` | 提交管理 + 批改(方式二) + 统计 + 导出 |

### 作业状态枚举

| 状态值 | 含义 | 说明 |
|---|---|---|
| 0 | 未发布/草稿 | 创建后默认状态 |
| 1 | 已发布 | 学生可见，可提交 |
| 2 | 已结束 | 仅前端 statistics 页面使用，后端无此状态定义 |

### 提交批改状态枚举

| 状态值 | 含义 |
|---|---|
| 0 | 待批改 |
| 1 | 已批改 |

#### 数据加载流程

```
onMounted → loadData()
│
├── api.getHomeworkList(params)
│   → GET /api/teacher/homework/list?page=1&pageSize=10&courseId=&title=&status=
│   → 赋值 tableData + pagination.itemCount
│
└── api.getCourses(params)（首次加载）
    → GET /api/teacher/course/simple
    → 赋值 courseOptions（课程选择缓存）
```

#### 新增/编辑作业流程

```
用户点击"发布作业"或"编辑"按钮
│
├── 新增: 重置 formData → 打开弹窗
├── 编辑: api.getDetail(id) → 回填 formData → 打开弹窗
│
├── 表单校验规则:
│   courseId: 必选 (type: number)
│   title: 必填, 2-200 字符
│   content: 必填
│   score: 必填, >= 1 (type: number)
│   startTime: 必填 (type: number, 时间戳)
│   endTime: 必填 (type: number, 时间戳)
│
├── 提交:
│   ├── 新增: api.create(formData) → POST /api/teacher/homework
│   └── 编辑: api.update(id, formData) → PUT /api/teacher/homework/{id}
│
└── 成功后 → loadData() 刷新列表
```

#### 数据加载流程

```
onMounted → loadCourses() → 赋值 courseOptions
│
├── 用户选择课程
│   └── loadHomeworks(courseId)
│       → GET /api/teacher/homework/list?courseId=xxx&status=1
│       → 仅加载已发布作业 → 赋值 homeworkOptions
│
├── 用户选择作业
│   └── loadHomeworkSubmissions(homeworkId)
│       → GET /api/teacher/homework-submission/list/{homeworkId}
│       → 全量获取该作业提交数据
│       → 前端做 studentName/gradeStatus 过滤
│       → 前端手动分页（非远程分页）
│
└── 批改操作
    ├── api.getSubmissionDetail(id) → 查看详情
    └── api.gradeSubmission(id, gradeForm) → PUT /api/teacher/homework/submission/grade
```

#### ⚠ 前端过滤 + 手动分页

grade 页面在选定作业后，通过 `loadHomeworkSubmissions` **全量获取**该作业所有提交记录，然后在前端做：
1. `studentName` 模糊过滤（前端 JS 实现）
2. `gradeStatus` 状态过滤
3. 手动计算分页（`Math.ceil(filtered.length / pageSize)`）

当某作业提交数很大时，全量加载可能导致性能问题。

## 三、后端执行流程

### 3.1 Sa-Token 认证架构

> Sa-Token 认证架构详见 [认证系统指南](../公共参考/认证系统指南.md) 及 [公共参考-认证与权限体系](../../公共参考/公共数据模型与基础配置.md#二认证与权限体系sa-token)

**三层控制器 + 类级别鉴权**：

```
├── 控制器类级别注解
│   ├── CourseHomeworkTeacherController → @SaCheckRole("教师")
│   ├── CourseHomeworkManageController → @SaCheckRole("教师")
│   └── HomeworkSubmissionTeacherController → @SaCheckRole("教师")
│
└── Service 层手动权限校验
    ├── CourseHomeworkServiceImpl.checkTeacherHomeworkPermission()
    │   → 验证作业存在 + createUser == teacherId
    ├── CourseHomeworkServiceImpl.updateHomework()
    │   → StpUtil.hasRole("管理员") 可跳过教师校验
    └── HomeworkSubmissionServiceImpl.gradeHomeworkSubmission()
        → 验证提交记录的 maxScore 上限（⚠ 未验证教师归属）
```

| 端点 | 类注解 | Service校验 | 实际认证 |
|---|---|---|---|
| `PUT /api/teacher/homework-submission/grade/{submissionId}` | `@SaCheckRole("教师")` | ⚠ **缺失** TODO | 仅教师角色 |
| `PUT /api/teacher/homework-submission/batch-grade/{homeworkId}` | `@SaCheckRole("教师")` | `checkTeacherHomeworkPermission` | 教师+作业归属 |

```
submission-manage 页面 → 选择多行 → 点击"批量批改" → 填写统一分数和评语 → 提交
│
├── PUT /api/teacher/homework-submission/batch-grade/{homeworkId}
│   body: { gradings: [{ studentId, score, teacherComment }, ...] }
│   └── 后端: checkTeacherHomeworkPermission → 逐个处理 → 返回成功/失败统计
│
└── 成功 → loadSubmissions() + loadStatistics() 刷新
```

## 五、已知问题与风险点

> 跨模块系统级问题见 [公共参考-系统级已知问题与风险清单](../../公共参考/系统级已知问题与风险清单.md)，此处仅列本模块独有问题。

| # | 问题 | 严重度 | 说明 |
|---|---|---|---|
| 1 | **批改权限校验缺失** | 高 | `PUT /api/teacher/homework-submission/grade/{submissionId}` 端点控制器层有 TODO 注释，未调用 `checkTeacherHomeworkPermission`，仅验证 maxScore 上限，任意教师角色可批改他人作业的提交 |
| 2 | **分数上限不一致** | 高 | CreateDTO score @Max(100) vs UpdateDTO @Max(1000)；CourseHomeworkGradeDTO @DecimalMax("1000") vs HomeworkSubmissionGradeDTO @DecimalMax("100")。两套 DTO 体系对分数约束互相矛盾 |
| 3 | **批量操作性能差** | 中 | `batchPublishHomework` 和 `batchDeleteHomework` 逐条查询+更新/删除，未使用批量 SQL，大量作业时效率低 |
| 4 | **未提交学生信息不完整** | 中 | `getUnsubmittedStudents` 返回的 `studentName` 未填充（TODO），前端无法显示学生姓名 |
| 5 | **grade 页面全量加载** | 中 | `loadHomeworkSubmissions` 全量获取某作业所有提交后前端过滤+手动分页，提交量大时性能差且浪费带宽 |
| 6 | **两套批改体系** | 中 | `CourseHomeworkTeacherController` 和 `HomeworkSubmissionTeacherController` 各有一套批改端点，逻辑和权限校验程度不同，容易混淆 |
| 7 | **批量批改分数无上限** | 中 | `HomeworkSubmissionBatchGradeDTO.gradings[].score` 无 @DecimalMax 约束，仅依赖 Service 层 maxScore 校验 |
| 8 | **批量批改评语无长度限制** | 中 | `HomeworkSubmissionBatchGradeDTO.gradings[].teacherComment` 无 @Size 约束，`HomeworkSubmissionGradeDTO.teacherComment` 也无长度限制 |
| 9 | **发布作业不校验时间** | 中 | `publishHomework` 仅检查 title/endTime 非空，不校验 startTime 是否已过期，可发布已过期的作业 |
| 10 | **Entity 与 VO 类型不一致** | 低 | CourseHomework.score(BigDecimal) → VO(Integer)；submissionCount(String) → VO(Integer，parseInt catch=0) |
| 11 | **统计子查询性能** | 低 | `getHomeworkStatistics` 使用 3 个相关子查询统计提交/批改数，应改为 JOIN 聚合 |
| 12 | **前端死代码** | 低 | homework/api.js 中 `publishHomework`、`getHomeworksByCourse` 已定义但未被调用；后端批量操作/复制/延期接口也未对接前端 |
| 13 | **作业状态"已结束"** | 低 | 前端 statistics 页面使用 status=2 表示"已结束"，但后端无此状态定义，状态值 2 不存在于数据库 |
| 14 | **导出无参数校验** | 低 | `exportHomeworkData` 的 courseId 和 status 参数无 `@Min` 校验，可能传入负值 |
| 15 | **tryResetLearningStatus 副作用** | 低 | 创建作业时自动将已完成学员重置为"学习中"，此副作用无前端提示，学员无法感知 |
| 16 | **课程归属未校验** | 低 | 创建作业时仅校验 courseId 非空，未校验课程是否属于当前教师，理论上可为他人课程创建作业 |
