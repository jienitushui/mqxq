# 教师端数据大屏功能 — 技术深度解析

## 一、功能概述

教师端数据大屏模块是教师登录后的**默认首页**（`path: '/'`），提供核心指标概览、课程/学员/作业/收入四大维度统计卡片、7个 ECharts 图表（饼图×2 + 折线图×3 + 柱状图×2），以及数据统计、课程浏览统计、收入管理三个辅助页面。

#### 数据加载流程

```
onMounted → refreshData()
│
└── Promise.all([
     api.getOverview(),                        → GET /api/teacher/dashboard/overview
     api.getCourseStatusDistribution(),         → GET /api/teacher/dashboard/course-status-distribution
     api.getStudentStatusDistribution(),        → GET /api/teacher/dashboard/student-status-distribution

     api.getCourseCompletionRanking({ limit }), → GET /api/teacher/dashboard/course-completion-ranking?limit=10
   ])
```

8 个 API 请求并行发出，全部完成后渲染。

#### ECharts 图表配置

使用 **ECharts 按需引入 + vue-echarts (VChart)**：

```javascript
import { BarChart, LineChart, PieChart } from 'echarts/charts'
import { GridComponent, LegendComponent, TooltipComponent } from 'echarts/components'
import * as echarts from 'echarts/core'
import { CanvasRenderer } from 'echarts/renderers'
import VChart from 'vue-echarts'

echarts.use([TooltipComponent, GridComponent, LegendComponent, BarChart, LineChart, CanvasRenderer, UniversalTransition, PieChart])
```

**饼图** — courseStatusOption / studentStatusOption：
- `radius: '50%'`，`emphasis` 带 `shadowBlur` 动画
- formatter: `'{a} <br/>{b}: {c} ({d}%)'`

**折线图** — courseViewTrendOption / revenueTrendOption / studentGrowthTrendOption：
- `smooth: true`，`areaStyle: {}`（带面积填充）
- 数据映射：`data.map(item => item.date)` 做 xAxis，`data.map(item => item.count/item.amount)` 做 series
- 收入趋势 tooltip 和 yAxis 有 `¥` 前缀格式化

**横向柱状图** — topCoursesOption / completionRankingOption：
- `xAxis: value`，`yAxis: category`
- `label.show: true`，带格式化前缀（¥ 或 %）
- 完成率排行 `xAxis.max = 100`

所有 option 均为 `computed` 属性，通过 `<VChart :option="xxxOption" autoresize />` 渲染。

所有方法均通过 `SaUtil.getLoginId()` 获取 teacherId 传入 Service。

### 3.3 数据大屏概览（`GET /api/teacher/dashboard/overview`）

```
│
┌─ Sa-Token 校验: @SaCheckRole("教师")
├── teacherId = SaUtil.getLoginId()
│
┌─ 步骤1: 课程指标（⚠ 全量查询 + Java过滤）
│  ├── courseDao.queryAllByLimit(condition={teacherId})
│  ├── Java Stream 统计:
│  │   totalCourses, publishedCourses(status=1), unpublishedCourses(status=0/null)
│  │   totalViews = sum(course.getViewCount())
│  ├── courseCommentDao.queryAllByLimit(commentCondition={teacherId})
│  │   → totalComments, avgRating
│  └── ordersDao.getRevenueByTeacherId(teacherId)  ✅ SQL聚合
│      → totalRevenue (SUM(goods_price) WHERE status='DONE')
│
┌─ 步骤2: 收入指标（⚠ 极低效：全量订单 + Java逐条过滤）
│  ├── calculateTodayRevenue(teacherId)
│  │   ├── 查全部订单 → 遍历: status='DONE' 且 payTime 是今天
│  │   └── 逐条查 courseDao.queryById(goodsId) 验证 teacherId ⚠ N+1
│  ├── calculateMonthRevenue(teacherId) — 同上，过滤本月
│  ├── calculateTodayOrderCount(teacherId) — 同上，计数
│  └── cumulativeRevenue = totalRevenue
│
┌─ 步骤3: 学员指标（⚠ 全量查询 + Java过滤）
│  ├── myCourseDao.queryListByConditions(params={teacherId})
│  │   → 计算 uniqueStudents, studyingStudents(status=1),
│  │     completedStudents(status=2), joinedStudents(status=0)
│  └── completionRate = completedStudents / uniqueStudents * 100
│
┌─ 步骤4: 作业指标
│  ├── courseHomeworkDao.queryByParams(params={createUser=teacherId})
│  │   → totalHomeworks, publishedHomeworks(status=1)
│  ├── homeworkSubmissionDao.queryAllByLimit(...)
│  │   → pendingGradingCount(status=0), gradedCount(status=1)
│  └── avgHomeworkScore
│
└─ 返回 TeacherDashboardOverviewVO (21个字段)
```

**性能问题**：概览接口内部调用约 **5-8 次 DAO 查询**，其中 3 次"今日/本月/订单数"计算采用"查全表+Java过滤+N+1关联查询"模式，数据量增长后将成为严重瓶颈。

### 3.7 收入趋势（`GET /api/teacher/dashboard/revenue-trend`）

```
请求参数: days (默认30)
│
├── ordersDao.getTeacherRevenueTrend(teacherId, days)  ✅ 唯一使用SQL聚合的趋势查询
│
│   SQL:
│   SELECT DATE(o.pay_time) AS date, SUM(o.goods_price) AS revenue
│   FROM orders o INNER JOIN course c ON o.goods_id = c.id
│   WHERE c.teacher_id = #{teacherId}
│     AND o.status = 'DONE'
│     AND o.pay_time IS NOT NULL
│     AND DATE(o.pay_time) >= DATE_SUB(CURDATE(), INTERVAL #{days} DAY)
│   GROUP BY DATE(o.pay_time)
│   ORDER BY date ASC
│
└── 返回 List<TrendDataVO> [{ date, amount }]
    ⚠ pay_time 为 VARCHAR 类型，DATE() 函数对 VARCHAR 可能行为不一致
```

│   WHERE c.teacher_id = #{teacherId} AND o.status = 'DONE'

## 五、已知问题与风险点

> 跨模块系统级问题见 [公共参考-系统级已知问题与风险清单](../../公共参考/系统级已知问题与风险清单.md)，此处仅列本模块独有问题。

| # | 问题 | 严重度 | 说明 |
|---|---|---|---|
| 1 | **今日/本月收入 N+1 查询** | 高 | `calculateTodayRevenue` 查全部订单→逐条查course验证归属，应改为单条SQL聚合 |
| 2 | **订单详情无归属校验** | 高 | `OrdersTeacherController.getOrderDetail()` 有 TODO 注释，未验证订单是否属于该教师的课程，任意教师可查看他人订单 |
| 3 | **N+1 查询: 完成率排行** | 中 | `getTeacherCourseCompletionRanking` 遍历每门课程分别查询学员列表，应改为 JOIN + GROUP BY |
| 4 | **N+1 查询: 作业统计** | 中 | `getTeacherHomeworkStatistics` 遍历每门作业查询提交统计，应改为子查询或 JOIN |
| 5 | **N+1 查询: 平均评分** | 中 | `getTeacherCoursesStatistics` 遍历每门课程查 `getAverageRatingByCourseId` |
| 6 | **前端收入映射硬编码** | 中 | `monthlyRevenue` 直接取 `totalRevenue`，`pendingRevenue` 硬编码为 0，`settledRevenue` 等于 `totalRevenue`，后端未提供细分数据 |
| 7 | **statistics/api.js BASE_URL 未定义** | 中 | `getMyRatingStatistics` 和 `getMyCourseStatistics` 引用未声明的 `BASE_URL`，调用时将报 ReferenceError |
| 8 | **日期范围筛选未实现** | 低 | revenue 页面 `searchForm.dateRange` 在代码中有处理逻辑，但 UI 未渲染日期选择器 |
| 9 | **订单详情未完整实现** | 低 | `viewOrderDetail` 仅以 `message.info` 输出 JSON，无详情弹窗或跳转 |
| 10 | **旧首页冗余** | 低 | index.vue 已被 dashboard 替代但仍保留，含硬编码示例图表，settings.js 中注释保留旧配置 |
| 11 | **revenue 订单列表用 userId 作学生姓名** | 低 | 前端 `studentName: order.userId`，显示数字ID而非姓名，后端未返回学生姓名 |
| 12 | **api.js import 路径不统一** | 低 | revenue/api.js 用 `@/utils/http`，其他用 `@/utils`，实际引用同一实例但风格不一致 |
| 13 | **概览接口响应过重** | 低 | 单个 `/overview` 端点返回21个字段，内部涉及5-8次DAO查询+多次Java计算，应拆分或异步加载 |
| 14 | **旧首页加载数据但不渲染** | 低 | index.vue JS 中加载了 teacherStats/latestComments/topCourses 数据，但模板仅显示 vue-naive-admin 默认欢迎页面，功能表所列"热销课程排行"和"最新评论"实际不可见 |
| 15 | **浏览器识别 Edge 错误** | 低 | course-view 页面 Chrome 判断未排除 Edge（`ua.includes('Chrome')` 不检查 `!ua.includes('Edg')`），Edge 浏览器被错误识别为 Chrome |
| 16 | **course-view/api.js 孤儿函数** | 低 | `getCourseViews(courseId, params)` 指向不存在的后端端点 `/api/teacher/course-view/course/${courseId}`，`getMyCourses()` 已定义但 index.vue 未调用 |
