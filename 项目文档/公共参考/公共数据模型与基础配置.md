## 一、订单状态体系

### 状态定义

订单状态以**字符串 VARCHAR** 存储（非整数枚举），共 5 种：

| 状态值 | 含义 | 触发条件 |
|--------|------|----------|
| `NOT_PAY` | 待支付 | 创建订单后初始状态 |
| `DONE` | 已完成 | 支付宝回调验签成功 |
| `CANCEL` | 已取消 | 用户主动取消（仅 NOT_PAY 状态可取消） |
| `REFUND_DONE` | 已退款 | 退款成功 |
| `COMMENT_DONE` | 已评价 | 用户完成评价 |

### 状态流转

```
创建订单 → NOT_PAY（待支付）
│
├── 支付宝回调成功 → DONE（已完成）
│   ├── 用户评价 → COMMENT_DONE（已评价）
│   └── 用户退款 → REFUND_DONE（已退款）
│
├── 用户取消 → CANCEL（已取消）
│
└── ⚠ 超时未支付 → 无自动取消机制
```

### 前端状态映射不一致问题

后端 `@Schema` 注解声明 5 种状态，但前端各组件各自定义了不同的映射：

| 状态值 | OrderList | OrderDetail | MessageContent(AI) | 数字状态 |
|--------|-----------|-------------|-------------------|----------|
| `NOT_PAY` | 待付款 | 待付款 | 待支付 | 0 |
| `DONE` / `PAID` | 已完成 | 已支付 | 已完成 | 1 |
| `CANCEL` / `CANCELLED` | 已取消 | — | 已取消 | 2 |
| `REFUND_DONE` / `REFUNDED` | 已退款 | — | 已退款 | 3 |
| `COMMENT_DONE` | — | — | — | — |
| `REFUND_PENDING` | — | — | 退款中 | — |

⚠ `OrderConstants` 类为空（仅有注释"待扩展"），所有状态字符串硬编码分散在各处。前端每个状态映射函数均有 `typeof string` / `typeof number` 两套分支，反映后端 API 返回格式不一致。

## 二、认证与权限体系（Sa-Token）

### 技术栈

- **框架**: Sa-Token 1.38.0
- **加密**: BCrypt（密码存储）
- **Token 格式**: simple-uuid（如 `a1b2c3d4e5f6...`）
- **有效期**: 30 天（2592000 秒）

### Sa-Token 配置

```yaml
sa-token:
  token-name: mqxqtoken        # Token 名称（Cookie/Header 头名）
  timeout: 2592000             # 30 天（秒）
  active-timeout: -1           # 无活动超时（永不清退）
  is-concurrent: false         # 不允许并发登录（新登录踢出旧会话）
  is-share: true               # 并发时共享 Token
  token-style: simple-uuid     # Token 格式
  is-log: true                 # 输出操作日志
```

### 关键行为

- `is-concurrent: false`：同一账号在新设备登录时，旧设备的 Token 自动失效（被踢下线）
- 前端默认 `expiresIn` 为 86400（24 小时），后端 `timeout: 2592000`（30 天），前后端过期时间不一致

### 角色体系

三表多对多设计，角色通过 `user_role` 中间表关联：

| 角色名 | role_id | 使用端 |
|--------|---------|--------|
| 管理员 | 1 | vue-naive-admin |
| 教师 | 2 | vue-naive-admin |
| 用户 | 3 | mqxq-front（学生端） |

`@SaCheckRole` 注解使用中文 `role_name`（"管理员"/"教师"/"用户"）进行鉴权。

### 前端 Token 传递方式

| 端 | Header 传递 | 说明 |
|----|-------------|------|
| 学生端（mqxq-front） | `satoken` + `token` + `mqxqtoken` + `Authorization: Bearer` | 四个头部确保后端识别 |
| 教师/管理员端（vue-naive-admin） | `Authorization: Bearer` | ⚠ 未发送 Sa-Token 默认的 `mqxqtoken` 头或 Cookie |

### 拦截器配置

```java
registry.addInterceptor(new SaInterceptor(handle -> StpUtil.checkLogin()))
    .addPathPatterns("/**")
    .excludePathPatterns("/api/auth/**")       // 认证端点全部放行
    .excludePathPatterns("/api/public/**")      // 公共端点放行
    .excludePathPatterns("/api/alipay/**")      // 支付回调放行
    .excludePathPatterns("/api/embedding/**")   // 向量化端点放行
```

⚠ `/api/auth/**` 整体放行意味着认证端点的保护完全依赖方法级别的 `@SaCheckLogin` 注解。

## 三、数据大屏共享 VO 定义

教师端与管理员端数据大屏共用同一个 `DashboardServiceImpl`，共享以下 VO 类：

### DistributionDataVO（饼图）

| 字段 | 类型 | 描述 |
|------|------|------|
| name | String | 分类名 |
| value | Long | 数值 |
| percentage | Double | 百分比 |

### TrendDataVO（折线图）

| 字段 | 类型 | 描述 |
|------|------|------|
| date | String | 日期（yyyy-MM-dd） |
| count | Long | 数值 |
| amount | BigDecimal | 金额（用于收入趋势） |
| percentage | Double | 百分比 |

### RankingDataVO（柱状图/排行）

| 字段 | 类型 | 描述 |
|------|------|------|
| rank | Integer | 排名 |
| id | Integer | ID |
| name | String | 名称 |
| imageUrl | String | 图片URL |
| count | Long | 数量 |
| amount | BigDecimal | 金额 |
| rating | Double | 评分 |
| completionRate | Double | 完成率 |
| extra | Object | 额外信息 |

### 端点差异概览

| 维度 | 教师端 | 管理员端 |
|------|--------|----------|
| 基础路径 | `/api/teacher/dashboard` | `/api/admin/dashboard` |
| 概览 VO | `TeacherDashboardOverviewVO`（20字段） | `AdminDashboardOverviewVO`（23字段） |
| 饼图数 | 2 | 6 |
| 折线图数 | 3 | 4 |
| 柱状图数 | 2 | 3 |
| 数据范围 | 仅个人课程数据 | 全平台数据 |

## 四、聊天/AI 对话共享模型

### SSE 事件类型

| 事件值 | 名称 | 说明 | eventData 类型 |
|--------|------|------|----------------|
| 1001 | DATA | AI 输出的文本内容（分块） | String |
| 1002 | STOP | 输出结束标记 | null |
| 1003 | PARAM | 工具调用返回的参数 | Object |

### ChatEventVO（SSE 响应事件）

```json
{
  "eventType": 1001,
  "eventData": "文本内容或参数对象"
}
```

### SessionVO（会话信息）

```json
{
  "sessionId": "uuid",
  "title": "会话标题",
  "describe": "AI助手描述",
  "examples": [{ "title": "示例标题", "describe": "示例描述" }]
}
```

### MessageVO（历史消息）

```json
{
  "type": "USER | ASSISTANT",
  "content": "消息内容",
  "params": { "courseId": 123, "courseName": "Java基础入门" }
}
```

### 三级持久化机制

```
用户发送消息 → Redis（ChatMemory，实时写入）
              ↓ 聊天完成时
              MySQL（chat_message 表，异步同步）
              ↓ 定时任务兜底
              每天凌晨1点补充同步增量数据
              ↓ 按需恢复
              Redis 无数据时从 MySQL 恢复
```

### Redis 存储格式

- **Key**: `CHAT:{userId}_{sessionId}`
- **Value**: Redis List，每个元素为 Message JSON 字符串

## 五、学习状态体系（my_course）

### 状态定义

学习状态以**整数**存储（my_course.status），共 3 种：

| 状态值 | 含义 | 触发条件 |
|--------|------|----------|
| `0` | 已加入 | 支付成功后创建 my_course 记录 |
| `1` | 学习中 | 首次观看课程或首次提交作业 |
| `2` | 已完成 | 至少观看过一次 + 完成所有课程作业 |

### 状态流转

```
支付成功 → 0(已加入)
│
├── 首次观看/首次提交作业 → 1(学习中)
│   └── 观看记录 + 全部作业完成 → 2(已完成)
│       ├── 课程新增章节 → 2→1 (批量重置)
│       ├── 课程新增小节 → 2→1 (批量重置)
│       └── 课程新增作业 → 2→1 (批量重置)
│
└── PUT /api/user/my-course/progress → 手动设置任意状态
```

### 触发点

| 流转 | 触发位置 | 自动/手动 |
|------|---------|----------|
| 0→1 | CourseViewServiceImpl、HomeworkSubmissionUserController | 自动 |
| 1→2 | HomeworkSubmissionUserController（提交作业后检查） | 自动 |
| 2→1 | ChapterServiceImpl、SectionServiceImpl、CourseHomeworkServiceImpl | 自动 |
| 任意 | `PUT /api/user/my-course/progress` | 手动 |
