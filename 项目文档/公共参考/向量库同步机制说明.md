# 向量库同步机制说明

课程向量库通过**实时同步**（主）和**定时任务同步**（补充）两种机制保证与课程数据的一致性。

> 定时任务总览详见 [公共参考-系统定时任务总览](系统基础设施配置汇总.md#三系统定时任务总览)

---

## 一、架构概览

```
┌─────────────────────────────────────────────────────────────┐
│                      MySQL (course表)                        │
└───────────────────────┬─────────────────────────────────────┘
                        │ 课程操作（增删改）
        ┌───────────────┴───────────────┐
        ▼                               ▼
┌──────────────────┐          ┌──────────────────────┐
│ CourseServiceImpl│          │ 定时任务触发          │
│  (实时同步)       │          │ (补充同步)            │
└────────┬─────────┘          └──────────┬───────────┘
         │                               │
         ▼                               ▼
┌─────────────────────────────────────────────────────┐
│      CourseVectorSyncService (统一同步服务)          │
│  - addCourseToVectorStore()                         │
│  - updateCourseInVectorStore()                      │
│  - deleteCourseFromVectorStore()                    │
└───────────────┬─────────────────────────────────────┘
                ▼
┌─────────────────────────────────────────────────────┐
│              向量库 (Elasticsearch)                  │
└─────────────────────────────────────────────────────┘
```

### 两种机制对比

| 维度 | 实时同步 | 定时任务同步 |
|------|---------|------------|
| 触发 | 课程操作时立即触发 | Cron 定时执行 |
| 特点 | 实时、精确（只处理变更数据） | 可靠、批量（兜底修复遗漏） |
| 延迟 | 无 | 全量每天凌晨2点，增量每小时 |
| 依赖 | 需在每个操作点调用 | 独立运行 |

### 核心原则

1. **只同步已发布的课程**：只有 status=1 的课程才添加到向量库
2. **实时优先**：课程变更时立即同步，无需等待定时任务
3. **容错处理**：向量库同步失败不阻塞主业务，只记录日志

## 二、实时同步（CourseVectorSyncService）

**位置**：`com.jieni.mqxq.service.infrastructure.CourseVectorSyncService`

### 1. 新增课程

**触发**：`CourseServiceImpl.createCourse()` / `createCourseByAdmin()`

```java
if (course.getStatus() == 1) {  // 已发布才同步
    courseVectorSyncService.addCourseToVectorStore(course);
}
```

### 2. 修改课程

**触发**：`CourseServiceImpl.updateCourse()` / `updateCourseByAdmin()`

```java
Course updatedCourse = courseDao.queryById(courseId);
courseVectorSyncService.updateCourseInVectorStore(updatedCourse);
// 内部：已发布→删除旧向量+添加新向量；未发布→从向量库删除
```

### 3. 发布课程

**触发**：`CourseServiceImpl.publishCourse()` / `publishCourseByAdmin()`

```java
courseVectorSyncService.addCourseToVectorStore(publishedCourse);
```

### 4. 取消发布

**触发**：`CourseServiceImpl.unpublishCourse()` / `unpublishCourseByAdmin()`

```java
courseVectorSyncService.deleteCourseFromVectorStore(courseId);
```

### 5. 删除课程

**触发**：`CourseServiceImpl.deleteCourse()` / `deleteCourseByAdmin()`

```java
courseVectorSyncService.deleteCourseFromVectorStore(courseId);
// 幂等操作，重复删除不报错
```

## 三、定时任务同步（CourseEmbeddingScheduledTask）

**位置**：`com.jieni.mqxq.common.scheduled.CourseEmbeddingScheduledTask`

定时任务已优化为复用 `CourseVectorSyncService`，消除了代码重复。

### 1. 全量同步

- **Cron**：`0 0 2 * * ?`（每天凌晨2点）
- **逻辑**：查询所有已发布课程，逐个调用 `addCourseToVectorStore()`（幂等覆盖）

### 2. 增量同步

- **Cron**：`0 0 * * * ?`（每小时整点）
- **逻辑**：查询所有已发布课程，逐个调用 `updateCourseInVectorStore()`（删除旧+添加新）

⚠ 当前实现查询所有已发布课程（可优化为只查询最近更新的），且定时任务已注释禁用，实时同步为主。

## 四、同步服务核心方法

### CourseVectorSyncService 方法

| 方法 | 说明 |
|------|------|
| `addCourseToVectorStore(Course)` | 将课程转为 CourseInfo 向量化并添加（仅已发布执行） |
| `updateCourseInVectorStore(Course)` | 已发布→删除旧+添加新；未发布→从向量库删除 |
| `deleteCourseFromVectorStore(Integer courseId)` | 按 `course_{id}` 文档ID删除（幂等） |

### 向量库文档格式

- **文档ID**：`course_{courseId}`（如 `course_1`）
- **元数据**：`{ courseId, courseName, type: "course" }`
- **文本内容**：包含课程标题/描述/价格/课时/时长/购买数/浏览量/状态/教师ID/分类ID

## 五、同步规则汇总

| 操作 | 实时同步 | 定时任务 | 说明 |
|------|---------|---------|------|
| 新增已发布课程 | ✅ 立即添加 | ✅ 会覆盖 | 实时更快 |
| 新增未发布课程 | ❌ 跳过 | ❌ 跳过 | 不入向量库 |
| 修改已发布课程 | ✅ 立即更新 | ✅ 会更新 | 实时更快 |
| 修改未发布课程 | ✅ 从向量库删除 | ❌ 跳过 | 实时处理 |
| 发布课程 | ✅ 立即添加 | ✅ 会添加 | 实时更快 |
| 取消发布 | ✅ 立即删除 | ❌ 跳过 | 实时处理 |
| 删除课程 | ✅ 立即删除 | ❌ 跳过 | 实时处理 |

## 六、数据一致性保障

```
实时同步（保证及时性）    定时任务（保证完整性）
         │                      │
         └──────────┬───────────┘
                    ▼
           向量库数据最终一致性
```

- **幂等性**：所有操作可重复执行不出错
- **容错性**：同步失败不影响主业务（try-catch + 日志）
- **事务**：向量库同步在 MySQL 事务提交后执行

---

## 七、注意事项

1. **性能**：实时同步单条操作影响小；定时批量建议低峰期执行
2. **错误处理**：实时失败只记录日志；定时失败下次重试
3. **优化建议**：增量同步可改为按 `update_time` 筛选最近更新的课程；添加同步失败监控告警
