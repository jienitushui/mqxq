# 学生端我的课程功能 — 技术深度解析

## 一、功能概述

学生端"我的课程"模块管理用户已加入课程的全生命周期：从加入（注册）、学习进度追踪、状态流转到退出。涉及前端列表页、学习页、个人资料页课程片段，以及后端三角色控制器（用户/管理员/教师）和跨服务状态联动。

### 功能清单

| 功能 | 前端页面/组件 | 后端端点 | 认证要求 |
|---|---|---|---|
| 我的课程列表 | MyCourses.vue | `GET /api/user/my-course/list` | `@SaCheckLogin + @SaCheckRole("用户")` |
| 状态筛选 | MyCourses.vue | 同上（status 参数） | 同上 |
| 加入课程 | CourseDetail.vue / CourseLearn.vue | `POST /api/user/my-course/join` | 同上 |
| 检查加入状态 | CourseLearn.vue | `GET /api/user/my-course/check/{courseId}` | 同上 |
| 课程学习详情 | CourseLearn.vue | `GET /api/user/my-course/detail/{courseId}` | 同上 |
| 更新学习进度 | ⚠ 未调用 | `PUT /api/user/my-course/progress` | 同上 |
| 更新学习时长 | ⚠ 未调用 | `PUT /api/user/my-course/duration` | 同上 |
| 退出课程 | ⚠ 无 UI | `DELETE /api/user/my-course/quit/{courseId}` | 同上 |
| 学习统计 | Profile 页 | `GET /api/user/my-course/statistics` | 同上 |
| 学习权限检查 | ⚠ 未调用 | `GET /api/user/course/can-study/{courseId}` | `@SaCheckLogin` |
| 购买状态检查 | CourseDetail.vue | `GET /api/user/course/purchase-status/{courseId}` | `@SaCheckLogin` |
| 管理员查看/管理 | 管理后台 | `/api/admin/my-course/*` | `@SaCheckRole("管理员")` |
| 教师查看学员 | 教师后台 | `/api/teacher/my-course/*` | `@SaCheckRole("教师")` |

### MyCourse 状态生命周期

> 完整的学习状态定义与流转图见 [公共参考-学习状态体系](../../公共参考/公共数据模型与基础配置.md#五学习状态体系my_course)。本模块涉及状态：加入课程→0(已加入)、首次观看/提交作业→1(学习中)、全部作业完成+有观看记录→2(已完成)、课程内容更新→2→1(重置)。

**触发状态转换的服务**：

| 转换 | 触发方法 | 调用方 |
|---|---|---|
| 0→1 | `checkAndStartLearning()` | CourseViewServiceImpl、HomeworkSubmissionUserController |
| 1→2 | `checkAndCompleteCourse()` | HomeworkSubmissionUserController |
| 2→1 | `resetCompletedStatusToLearning()` | ChapterServiceImpl、SectionServiceImpl、CourseHomeworkServiceImpl |

### 免费课程与付费课程的加入差异

| 场景 | canStudyCourse | joinCourse | 实际路径 |
|---|---|---|---|
| **付费课程** | 需 `status='DONE'` 的订单 | 需 `status='DONE'` 的订单 | 购买→支付→`handlePaymentSuccess` 自动创建 my_course |
| **免费课程** | 直接返回 `true`（无需订单） | ⚠ 仍需 `status='DONE'` 的订单 | 必须走 0 元下单→支付→自动创建，**无法直接加入** |

│   │   ├── ⚠ 检查 joinStatusResponse.data === false
│   │   │   但拦截器已解包 data，实际应为原始 boolean

│   │   │

### 3.2 加入课程（`POST /api/user/my-course/join`）

```
请求体: MyCourseCreateDTO { courseId(@NotNull @Min(1)), status(默认0) }
│
┌─ Sa-Token 校验: @SaCheckLogin + @SaCheckRole("用户") → userId
│
┌─ 步骤1: 参数校验
│  └── userId > 0, courseId > 0
│
┌─ 步骤2: 检查是否已加入
│  ├── myCourseDao.queryByUserIdAndCourseId(userId, courseId)
│  │   SQL: SELECT ... FROM my_course WHERE user_id=#{userId} AND course_id=#{courseId} LIMIT 1
│  └── 已存在 → "您已加入该课程"
│
┌─ 步骤3: 查找已完成订单
│  ├── ordersDao.selectByUserIdAndCourseIdDone(userId, courseId)
│  │   SQL: SELECT ... FROM orders WHERE user_id=#{userId}
│  │        AND goods_id=#{courseId} AND status='DONE'
│  │   ⚠ 无 LIMIT 1，多个 DONE 订单时行为不确定
│  └── 未找到 → "未找到该课程的有效订单，请先购买课程"
│
┌─ 步骤4: 创建 MyCourse 记录
│  ├── MyCourse { userId, courseId, orderId(来自订单), status=0, timestamps }
│  └── myCourseDao.insert(entity)
│
└─ 返回 Result<MyCourseVO>
    字段: id, userId, courseId, orderId, status, userNickname, userAvatar,
          courseName, courseCover, teacherName, createTime, updateTime
```

**⚠ 免费课程加入悖论**：`joinCourse` 必须有 `status='DONE'` 的订单，但免费课程无需购买即可 `canStudy=true`。免费课程只能通过 `purchaseCourse` 创建 0 元订单 → 支付成功 → `handlePaymentSuccess` 自动创建 my_course 记录。直接调用 `joinCourse` 对免费课程会失败。

### 3.3 支付成功自动加入（`handlePaymentSuccess`）

```
支付回调 → CoursePurchaseServiceImpl.handlePaymentSuccess(orderNo)
│
┌─ 步骤1: 查找订单
│  └── ordersDao.selectByOrderNo(orderNo)
│
┌─ 步骤2: 状态校验
│  └── status != "NOT_PAY" → 异常
│
┌─ 步骤3: 更新订单状态
│  └── status = "DONE", payTime = now
│
┌─ 步骤4: 创建 MyCourse 记录
│  ├── addToMyCourse(userId, courseId, orderId)
│  │   ├── 检查是否已存在 → 已存在则跳过
│  │   ├── MyCourse { userId, courseId, orderId, status=0, timestamps }
│  │   ├── myCourseDao.insert(entity)
│  │   └── ⚠ try-catch 吞没异常（插入失败不回滚订单状态）
│  │
│  └── ⚠ my_course 插入失败时，订单仍为 DONE 但无课程记录
│
└─ 步骤5: 递增购买数
   └── updateCourseSales(courseId)
```

### 3.4 我的课程列表（`GET /api/user/my-course/list`）

```
请求参数: MyCourseQueryDTO { pageNum(1), pageSize(10), status?, ... }
│
┌─ Sa-Token 校验 → userId
│
┌─ 步骤1: 设置查询条件
│  └── queryDTO.setUserId(userId)（强制当前用户）
│
┌─ 步骤2: PageHelper 分页
│  └── PageHelper.startPage(pageNum, pageSize)
│
┌─ 步骤3: DAO 查询（三表 JOIN）
│  └── myCourseDao.queryListByConditions(params)
│      SQL: SELECT mc.*, u.name AS userNickname, u.avatar AS userAvatar,
│                  c.title AS courseName, c.cover AS courseCover,
│                  t.name AS teacherName
│           FROM my_course mc
│           LEFT JOIN user u ON mc.user_id = u.id
│           LEFT JOIN course c ON mc.course_id = c.id
│           LEFT JOIN user t ON c.teacher_id = t.id
│           <where>
│             AND mc.user_id = #{userId}
│             [AND mc.status = #{status}]
│             [AND mc.course_id = #{courseId}]
│             [AND u.name LIKE CONCAT('%',#{userNickname},'%')]
│             [AND c.title LIKE CONCAT('%',#{courseName},'%')]
│           </where>
│           ORDER BY mc.create_time DESC
│
└─ 返回 Result<PageInfo<MyCourseVO>>
    字段: id, userId, courseId, orderId, status, userNickname, userAvatar,
          courseName, courseCover, teacherName, createTime, updateTime
```

**与前端 N+1 的矛盾**：后端列表接口已通过 JOIN 返回 `courseName/courseCover/teacherName`，但前端仍额外请求课程详情获取完整 Course 对象（含 description/price 等）。

### 3.12 自动状态转换机制

#### checkAndStartLearning（0→1）

```
触发: CourseViewServiceImpl.recordCourseView()、HomeworkSubmissionUserController
│
├── 查找 my_course 记录
├── status == 0 → 设置 status=1, 更新时间
├── myCourseDao.update()
├── ⚠ try-catch 吞没异常，失败返回 false
└── @Transactional(rollbackFor) 因异常被吞无法回滚
```

#### checkAndCompleteCourse（1→2）

```
触发: HomeworkSubmissionUserController（作业提交后）
│
├── 查找 my_course 记录
├── status == 1 → 检查完成条件
│   ├── isCourseLearningCompleted(userId, courseId)
│   │   ├── 获取课程所有章节+小节
│   │   ├── 检查观看记录: courseViewDao 是否有记录 → hasViewRecords
│   │   ├── 检查作业完成: checkHomeworkCompletion()
│   │   │   ├── 获取课程所有 CourseHomework
│   │   │   ├── ⚠ 加载用户所有 HomeworkSubmission（非按课程过滤）
│   │   │   ├── 内存中筛选匹配课程作业的提交
│   │   │   └── submittedCount >= totalHomeworks → true
│   │   │   ⚠ 无作业 → 直接返回 true
│   │   └── return hasViewRecords && homeworkCompleted
│   │
│   ├── 完成 → status=2, 更新时间
│   └── 未完成 → 不变
├── myCourseDao.update()
├── ⚠ try-catch 吞没异常
└── @Transactional 同上问题
```

#### resetCompletedStatusToLearning（2→1）

```
触发: ChapterServiceImpl/SectionServiceImpl/CourseHomeworkServiceImpl（新增内容时）
│
├── 查询课程所有 status=2 的 my_course 记录
│  ⚠ pageSize=Integer.MAX_VALUE 全量加载
├── 遍历逐个: status=1, 更新时间, myCourseDao.update()
│  ⚠ N+1 更新，应改为单条 UPDATE SQL
└── 返回重置数量
```

### 3.16 关键 MyBatis SQL 汇总

| SQL 方法 | 核心逻辑 | JOIN |

| insertBatch | foreach 批量插入 | — |

| deleteById | `WHERE id=?` | — |
| deleteBatchByIds | `WHERE id IN(...)` | — |
| queryByCourseAndUser | `WHERE course_id=? AND user_id=?` | 无 |
| queryByCourseId | `WHERE course_id=?` | 无 |

**commonWhereConditions 片段**支持：id, userId, courseId, orderId, status, teacherId(通过 c.teacher_id), userNickname(LIKE), courseName(LIKE), studentName(LIKE)。

## 五、已知问题与风险点

> 跨模块系统级问题见 [公共参考-系统级已知问题与风险清单](../../公共参考/系统级已知问题与风险清单.md)，此处仅列本模块独有问题。

| # | 问题 | 严重度 | 说明 |
|---|---|---|---|
| 1 | **前端学习进度从未持久化** | 高 | `updateLearningProgress()` 和 `updateStudyDuration()` 已定义但从未调用，`onUnmounted` 无保存逻辑，页面关闭进度全部丢失 |
| 2 | **退出课程无 UI 入口** | 高 | `quitCourse()` API 已定义但前端无任何按钮/菜单调用，用户无法退出课程 |
| 3 | **免费课程加入悖论** | 高 | `canStudy` 对免费课程返回 true，但 `joinCourse` 需 DONE 订单；免费课程必须走 0 元下单流程才能获得 my_course 记录，无直接加入路径 |
| 4 | **addToMyCourse 吞没异常** | 高 | 支付成功后创建 my_course 记录时 try-catch 吞没异常，插入失败订单仍为 DONE 但无课程记录，用户付了钱却看不到课程 |
| 5 | **checkAndStartLearning/Complete 吞没异常** | 中 | try-catch 返回 false，@Transactional 因异常不传播无法回滚，可能产生部分提交 |
| 6 | **updateStudyProgress 无状态验证** | 中 | 允许任意状态值（含 2→0 回退或跳级），无合法流转校验 |
| 7 | **resetCompletedStatus N+1 更新** | 中 | 遍历逐个 `update()`，应改为 `UPDATE my_course SET status=1 WHERE course_id=? AND status=2` |
| 8 | **auto-join 响应解包 Bug** | 中 | `fetchMyCourse` 检查 `joinStatusResponse.data === false`，但 HTTP 拦截器已解包 data 层，实际值为 boolean `false`，导致自动加入条件永远不满足 |
| 9 | **selectByUserIdAndCourseIdDone 无 LIMIT** | 中 | SQL 无 LIMIT 1，多个 DONE 订单时 DAO 返回单个对象行为不确定 |
| 10 | **checkHomeworkCompletion 全量加载提交** | 低 | 加载用户所有 HomeworkSubmission 再内存筛选，应按课程过滤 |
| 11 | **冗余数据库索引** | 低 | `uniq_user_course`(UNIQUE) 和 `idx_my_course_user_course`(INDEX) 在同一字段组合上冗余 |
| 12 | **MyCourse 类型定义不完整** | 低 | 前端 `MyCourse` 接口缺 `progress`/`lastSectionId`，`Section` 缺 `isFree`/`description`，运行时数据与类型不一致 |
| 13 | **图片错误 fallback 路径错误** | 低 | `/src/assets/default-course.svg` 是 Vite 源码路径，生产构建后不生效 |
| 14 | **CourseLearn.vue 无 TypeScript** | 低 | 整个学习页使用纯 JavaScript，与项目其他文件的 TypeScript 不一致 |
| 15 | **HomeworkList 死代码** | 低 | 加载 myCourses 数据但模板中未使用，浪费请求 |
| 16 | **AccessModal resolve 泄漏风险** | 低 | 将 Promise resolve 存储在 modal 对象上，modal 关闭不当可能导致内存泄漏 |
