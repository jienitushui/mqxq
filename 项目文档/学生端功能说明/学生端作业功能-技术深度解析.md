# 学生端作业功能 — 技术深度解析

## 一、功能概述

学生端作业模块提供作业浏览、提交、修改、撤回及提交记录查看功能，涉及前端 4 个页面、2 个后端 User 控制器、2 套 Service/DAO 体系，并与 MyCourseService 联动实现学习状态自动流转。

### 功能清单

| 功能 | 前端页面 | 后端端点 | 认证要求 |
|---|---|---|---|
| 我的作业列表 | HomeworkList.vue | `GET /api/user/homework/my-list` | `@SaCheckLogin + @SaCheckRole("用户")` |
| 课程作业列表 | HomeworkList.vue 侧栏 | `GET /api/user/homework/course/{courseId}` | 同上 |
| 作业详情 | HomeworkDetail.vue | `GET /api/user/homework/{id}` | 同上 |
| 提交作业 | HomeworkSubmit.vue | `POST /api/user/homework-submission/submit` | 同上 |
| 修改提交 | HomeworkSubmit.vue | `PUT /api/user/homework-submission/{id}` | 同上 |
| 撤回提交 | HomeworkDetail / Submissions | `DELETE /api/user/homework-submission/{id}` | 同上 |
| 上传附件 | HomeworkSubmit.vue | `POST /api/user/homework-submission/upload/{homeworkId}` | 同上 |
| 提交记录列表 | HomeworkSubmissions.vue | `GET /api/user/homework-submission/my-submissions` | 同上 |
| 查看提交详情 | HomeworkSubmissions.vue | `GET /api/user/homework-submission/{id}` | 同上 |
| 按作业查提交 | HomeworkDetail.vue | `GET /api/user/homework-submission/homework/{homeworkId}` | 同上 |
| 提交状态检查 | — | `GET /api/user/homework-submission/check/{homeworkId}` | 同上 |
| 旧路径提交 | — | `POST /api/user/homework/submit` | 同上 |
| 旧路径修改 | — | `PUT /api/user/homework/submit` | 同上 |
| 旧路径撤回 | — | `DELETE /api/user/homework/submit/{homeworkId}` | 同上 |
| 旧路径上传 | — | `POST /api/user/homework/upload/{homeworkId}` | 同上 |

> ⚠ 存在两套并行提交路径：`/api/user/homework/*`（CourseHomeworkUserController）与 `/api/user/homework-submission/*`（HomeworkSubmissionUserController），前端仅使用后者。

### 技术栈关键点

- **前端**：Vue 3 + Element Plus（el-form / el-upload / el-dialog）+ Tailwind CSS + Pinia + marked（Markdown 渲染）
- **后端**：Spring Boot 3.2 + MyBatis（PageHelper 分页）+ Sa-Token + MinIO（附件存储）+ MySQL
- **唯一约束**：`homework_submission` 表 `uniq_homework_student(homework_id, student_id)` — 每个学生每项作业仅一条提交

### 2.1 路由配置

所有作业路由位于 `/homework` 父路径，`meta.requiresAuth: true`：

| 路由名 | 路径 | 组件 | 说明 |

```

  │
  └── /homework/submissions (提交记录)
        ├── "查看作业" → /homework/:homeworkId
        └── "撤回提交" → 本页处理
```

#### 核心数据加载

```typescript
const loadHomeworkDetail = async () => {
  const id = Number(route.params.id)
  homework.value = await userApi.getHomeworkDetail(id)
  try {
    const resp = await userApi.getHomeworkSubmissionByHomework(id)
    if (resp?.id) {
      submission.value = resp       // 已提交
      hasSubmitted.value = true
      canSubmitFromApi.value = false
    }
  } catch {
    submission.value = null          // 未提交
    hasSubmitted.value = false
    canSubmitFromApi.value = true
  }
}
```

串行加载作业信息和提交状态，提交请求失败视为"未提交"。

#### 操作按钮条件

| 按钮 | 显示条件 | 可操作条件 |
|---|---|---|
| 提交作业 | `!hasSubmitted && canSubmitFromApi && !isOverdue` | 均需满足 |
| 修改提交 | `hasSubmitted && !isOverdue` | ⚠ 不检查批改状态 |
| 撤回提交 | `hasSubmitted && !isOverdue` | ⚠ 不检查批改状态 |

> ⚠ **风险**：`canModify` 和 `canWithdraw` 未检查 `submission.status`，理论上已批改的提交仍可修改/撤回（后端有批改状态校验，但前端按钮不应展示）。

#### 附件上传流程

```
用户选择文件
├── beforeUpload() 校验
│   ├── MIME 类型: pdf/doc/docx/jpeg/png/gif
│   └── 大小上限: 10MB
│
├── customUpload() 即时上传 (auto-upload=true)
│   ├── 如有旧附件 → fileApi.deleteFileByParam(旧URL) (非阻塞)
│   ├── userApi.uploadHomeworkAttachment(homeworkId, file)
│   │   POST /api/user/homework-submission/upload/{homeworkId}
│   │   Content-Type: multipart/form-data, key="file"
│   ├── 响应解析: response.msg || response.data || response.url || 直接字符串
│   └── submitForm.attachmentUrl = 解析后的URL
│
└── 删除附件: removeAttachment()
    ├── fileApi.deleteFileByParam(url)
    └── 清除本地状态
```

> ⚠ **风险**：`auto-upload=true` 意味着选择文件后立即上传到 MinIO，用户不提交表单则产生孤立文件。

> ⚠ **兼容处理**：`removeAttachment()` 中后端返回"文件删除成功"被 HTTP 客户端视为错误，前端做了特殊兼容判断。

#### 提交流程

```typescript
const submitHomework = async () => {
  await formRef.value.validate()
  await ElMessageBox.confirm('确定要提交作业吗？提交后可以在截止时间前修改。')

  if (isEdit.value) {
    // 修改提交
    const updateData = { ...existingSubmission.value, homeworkId, content, attachmentUrl, maxScore }
    await userApi.updateHomeworkSubmission(existingSubmission.value.id, updateData)  // PUT
  } else {
    // 新提交
    const submitData: HomeworkSubmission = {
      id: 0, homeworkId, studentId: 0, content, attachmentUrl,
      maxScore: homework.value.score || homework.value.maxScore,
      status: 1,       // ⚠ BUG: 应为 0（待批改），1 表示已批改
      submitTime: new Date().toISOString(),
      createTime: new Date().toISOString(),
      updateTime: new Date().toISOString(),
      createUser: 0, updateUser: 0
    }
    await userApi.submitHomework(submitData)  // POST
  }

  router.push(`/homework/${homework.value?.id}`)
}
```

> ⚠ **BUG**：新建提交时 `status: 1`，而提交表中 `status=0` 表示待批改、`status=1` 表示已批改。后端 Service 会将 status 强制设为 0，但此字段不应由前端传递。

## 三、后端执行流程

### 3.1 认证架构

| 控制器 | 路径前缀 | 类级注解 | 实际认证 |
|---|---|---|---|
| CourseHomeworkUserController | `/api/user/homework` | `@SaCheckLogin + @SaCheckRole("用户")` | 需登录 + 用户角色 |
| HomeworkSubmissionUserController | `/api/user/homework-submission` | `@SaCheckRole("用户")` | 需登录 + 用户角色（SaCheckRole 隐含登录） |

所有端点获取 `userId` 通过 `SaUtil.getLoginId()` → `StpUtil.getLoginId()`。无方法级注解覆盖。

### 3.2 作业查询接口

#### `GET /api/user/homework/my-list`（需登录）

```
请求参数: page(默认1), size(默认10), status?(默认1=已发布)
│
┌─ 步骤1: 查询用户已购课程
│  ├── myCourseDao.queryAllByLimit(condition)
│  │   SQL: SELECT course_id FROM my_course WHERE user_id = #{userId}
│  └── 如无已购课程 → 返回空分页
│
┌─ 步骤2: 按课程ID列表查询作业
│  ├── 提取 courseIds
│  ├── courseHomeworkDao.queryByParams({courseIds, status})
│  │   SQL: SELECT ... FROM course_homework
│  │        WHERE course_id IN (#{courseIds}) AND status = #{status}
│  │        ORDER BY create_time DESC
│  └── PageHelper 自动分页
│
└─ 返回 Result<PageInfo<CourseHomeworkVO>>
    字段: id, courseId, title, content, score, startTime, endTime,
          status, courseName, teacherName, submissionCount
```

#### `GET /api/user/homework/{id}`（需登录）

```
│
┌─ courseHomeworkDao.queryById(id)
│   SQL: SELECT ... FROM course_homework WHERE id = #{id}
│
└─ 返回 Result<CourseHomeworkVO>
    ⚠ 不校验作业是否已发布，未发布作业也可查看
```

### 3.3 提交作业接口

#### `POST /api/user/homework-submission/submit`（需登录）

```
请求体: HomeworkSubmissionCreateDTO { homeworkId(必填), content?, attachmentUrl? }
│
┌─ 步骤1: 校验作业
│  ├── courseHomeworkDao.queryById(homeworkId)
│  │   → 作业不存在 → 抛 MyException("作业不存在")
│  └── 获取 courseId
│
┌─ 步骤2: 课程购买权限校验（控制器层）
│  ├── courseHomeworkService.checkUserSubmissionPermission(userId, courseId)
│  │   ├── myCourseDao.queryByCourseAndUser(courseId, userId)
│  │   └── → 未购买 → 抛 MyException("您未购买该课程，无法提交作业")
│
┌─ 步骤3: 截止时间校验
│  └── homework.getEndTime().before(now) → 抛 MyException("作业已截止，无法提交")
│
┌─ 步骤4: 重复提交校验
│  ├── homeworkSubmissionDao.queryByHomeworkAndStudent(homeworkId, studentId)
│  │   → 已存在 → 抛 MyException("您已提交过该作业，请使用更新功能")
│
┌─ 步骤5: 创建提交记录
│  ├── new HomeworkSubmission: status=0, maxScore=homework.score, submitTime=now
│  ├── homeworkSubmissionDao.insert(submission)
│  │   SQL: INSERT INTO homework_submission(homework_id, student_id, content,
│  │         attachment_url, submit_time, score, max_score, teacher_comment,
│  │         grade_time, grade_user, status, create_time, create_user,
│  │         update_time, update_user) VALUES (...)
│  └── useGeneratedKeys 回填 id
│
┌─ 步骤6: 学习状态联动 (try-catch 包裹，失败不阻塞提交)
│  ├── myCourseService.checkAndStartLearning(userId, courseId)   // 0→1
│  └── myCourseService.checkAndCompleteCourse(userId, courseId)  // 1→2
│
└─ 返回 Result<String> "提交成功"
```

### 3.4 修改提交接口

#### `PUT /api/user/homework-submission/{id}`（需登录）

```
请求体: HomeworkSubmissionUpdateDTO { content?, attachmentUrl? }
│
┌─ 步骤1: 校验提交记录
│  ├── homeworkSubmissionDao.queryById(id)
│  │   → 不存在 → 抛 MyException("提交记录不存在")
│
┌─ 步骤2: 归属校验
│  └── !submission.getStudentId().equals(studentId)
│       → 抛 MyException("无权限修改该提交")
│
┌─ 步骤3: 批改状态校验
│  └── submission.getStatus() == 1
│       → 抛 MyException("作业已被批改，无法修改")
│
┌─ 步骤4: 截止时间校验
│  └── homework.getEndTime().before(now) → 抛 MyException("作业已截止，无法修改")
│
┌─ 步骤5: 更新提交记录
│  ├── 更新 content, attachmentUrl, submitTime=now, updateTime
│  └── homeworkSubmissionDao.update(submission)
│      SQL: UPDATE homework_submission
│           <set> content=#{content}, attachment_url=#{attachmentUrl},
│                 submit_time=#{submitTime}, update_time=#{updateTime} </set>
│           WHERE id = #{id}
│
└─ 返回 Result<String> "更新成功"
```

### 3.5 撤回提交接口

#### `DELETE /api/user/homework-submission/{id}`（需登录）

```
│
┌─ 步骤1: 校验提交记录 + 归属
│
┌─ 步骤2: 批改状态校验
│  └── status == 1 → 抛 MyException("作业已被批改，无法撤回")
│
┌─ 步骤3: 截止时间校验
│  └── → 抛 MyException("作业已过截止时间，无法撤回")
│
┌─ 步骤4: 硬删除
│  └── homeworkSubmissionDao.deleteById(id)
│      SQL: DELETE FROM homework_submission WHERE id = #{id}
│
└─ 返回 Result<String> "撤回成功"
```

> ⚠ **硬删除**：撤回操作物理删除记录而非软删除。因唯一约束 `uniq_homework_student`，撤回后学生可重新提交。

### 3.6 附件上传接口

#### `POST /api/user/homework-submission/upload/{homeworkId}`（需登录）

```
│
┌─ 步骤2: MinIO 上传
```

### 3.8 提交记录查询接口

#### `GET /api/user/homework-submission/my-submissions`（需登录）

```
请求参数: HomeworkSubmissionQueryDTO { pageNum, pageSize, courseId?(⚠前端传递但后端未使用), status?, startDate?, endDate? }
│
┌─ PageHelper.startPage(pageNum, pageSize)
│
┌─ homeworkSubmissionDao.querySubmissionsWithStudentInfo(params)
│   SQL: SELECT hs.*, u.username as student_name, ch.title as homework_title
│        FROM homework_submission hs
│        LEFT JOIN user u ON hs.student_id = u.id
│        LEFT JOIN course_homework ch ON hs.homework_id = ch.id
│        WHERE hs.student_id = #{studentId}
│          [AND hs.status = #{status}]
│          [AND hs.submit_time BETWEEN #{startDate} AND #{endDate}]
│        ORDER BY hs.submit_time DESC
│
└─ 返回 Result<PageInfo<HomeworkSubmissionVO>>
```

## 四、提交状态生命周期

### HomeworkSubmission 状态流转

```
                 提交作业                     教师批改
  (不存在) ──────────→ 0(待批改) ──────────→ 1(已批改)
                          │                       │
                  ┌───────┘                       │
                  │                               │
            撤回提交                        不可修改
            (硬DELETE)                     不可撤回
                  │
                  v
            (不存在) ──→ 可重新提交
```

| 操作 | 前置条件 | status 变化 |
|---|---|---|
| 提交 | 作业已发布 + 未过期 + 未重复 + 已购课程 | 新建 status=0 |
| 修改 | status=0 + 未过期 + 归属本人 | 保持 status=0 |
| 撤回 | status=0 + 未过期 + 归属本人 | 硬删除（记录不存在） |
| 批改 | 教师操作 | 0→1，填充 score/teacherComment/gradeTime |

### MyCourse 学习状态联动

提交作业时触发 MyCourseService 状态流转（try-catch 包裹，失败不阻塞）：

```
提交作业
├── tryStartLearning(userId, courseId)   // my_course.status: 0→1
│   条件: 用户已加入且有观看记录或提交记录
│
└── tryCompleteCourse(userId, courseId)  // my_course.status: 1→2
    条件: 所有作业已提交 + 有观看记录
```

> 当教师新增作业时，`CourseHomeworkServiceImpl` 调用 `myCourseService.resetCompletedStatusToLearning()`，将已完成学生（status=2）重置为学习中（status=1），因为出现了新的未完成作业。

## 八、双路径架构对比

项目存在两套并行的提交路径：

| 维度 | 旧路径（CourseHomeworkUserController） | 新路径（HomeworkSubmissionUserController） |
|---|---|---|
| 前缀 | `/api/user/homework/*` | `/api/user/homework-submission/*` |
| 提交 | `POST /submit` | `POST /submit` |
| 修改 | `PUT /submit` | `PUT /{id}` |
| 撤回 | `DELETE /submit/{homeworkId}` | `DELETE /{id}` |
| 上传 | `POST /upload/{homeworkId}` | `POST /upload/{homeworkId}` |
| Service | CourseHomeworkServiceImpl | HomeworkSubmissionServiceImpl |
| 提交时设 maxScore | ❌ 不设置 | ✅ 从作业复制 |
| 修改时刷新 submitTime | ❌ 不刷新 | ✅ 刷新为当前时间 |
| 归属校验位置 | Service 层 | Service 层 + Controller 层 |
| MyCourse 联动 | 无 | ✅ tryStartLearning + tryCompleteCourse |
| 前端使用 | ❌ 未使用 | ✅ 实际使用 |

**结论**：旧路径为早期实现，缺少 maxScore、submitTime 刷新、MyCourse 联动等逻辑。前端已切换到新路径，旧路径应视为废弃代码。

## 九、已知问题与风险点

> 跨模块系统级问题见 [公共参考-系统级已知问题与风险清单](../../公共参考/系统级已知问题与风险清单.md)，此处仅列本模块独有问题。

| # | 问题 | 严重度 | 说明 |
|---|---|---|---|
| 1 | **前端提交时发送 status=1** | 高 | HomeworkSubmit 新建提交设置 `status: 1`（已批改），与后端语义矛盾。后端 Service 强制设 0 规避，但属前端 BUG |
| 2 | **前端修改/撤回未检查批改状态** | 高 | HomeworkDetail 的 `canModify`/`canWithdraw` 仅判断 `hasSubmitted && !isOverdue`，已批改提交仍显示修改/撤回按钮（后端有二次校验） |
| 3 | **双路径并存** | 中 | CourseHomeworkUserController 的 `/submit`、`/upload` 等旧端点仍在线，缺少 MyCourse 联动和 maxScore 设置，应废弃 |
| 4 | **附件即时上传产生孤立文件** | 中 | `auto-upload=true` 导致选择文件后立即上传 MinIO，用户不提交表单则文件残留 |
| 5 | **提交记录 homeworkId 前端过滤** | 中 | HomeworkSubmissions 页面在客户端过滤 homeworkId，API 不支持此参数，大数据量时效率低 |
| 6 | **状态码映射不一致** | 中 | 4 个页面有 3 种 status 映射表，HomeworkSubmit 的映射明显错误 |
| 7 | **撤回后设置 homework.status=0** | 低 | HomeworkDetail 撤回成功后将 `homework.status = 0`，修改的是作业发布状态而非提交状态，语义错误 |
| 8 | **作业详情不校验发布状态** | 低 | `GET /api/user/homework/{id}` 不检查 `status=1`，未发布作业也能被学生查看 |
| 9 | **ContentType.DEFAULT 上传** | 低 | 所有附件以 `application/octet-stream` 存储，浏览器无法正确预览 PDF/图片等类型 |
| 10 | **hasSubmission 硬编码 false** | 低 | HomeworkList 的 `hasSubmission()` 始终返回 `false`，"查看提交"按钮永远隐藏 |
| 11 | **myCourses 加载但未使用** | 低 | HomeworkList 和 HomeworkSubmissions 均加载 `myCourses` 但模板未展示 |
| 12 | **双字段冗余** | 低 | Homework 类型中 `deadline`/`endTime` 和 `maxScore`/`score` 并存，前端需 `||` 兜底 |
| 13 | **旧路径不设 maxScore** | 低 | CourseHomeworkServiceImpl.submitHomework 创建提交时不设 maxScore，与 HomeworkSubmissionServiceImpl 行为不一致 |
| 14 | **旧路径不刷新 submitTime** | 低 | CourseHomeworkServiceImpl.updateHomeworkSubmission 不更新 submitTime，与 HomeworkSubmissionServiceImpl 行为不一致 |
