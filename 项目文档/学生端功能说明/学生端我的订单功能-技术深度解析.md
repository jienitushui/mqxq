# 学生端我的订单功能 — 技术深度解析

## 一、功能概述

学生端订单模块提供订单列表浏览、状态筛选、订单详情查看、取消/退款/支付重试等操作，涉及前端列表页、详情页、AI 聊天订单卡片，以及后端用户/管理员/教师三套 Controller 与支付回调。

### 功能清单

| 功能 | 前端页面/组件 | 后端端点 | 认证要求 |
|---|---|---|---|
| 我的订单列表 | OrderList.vue | `GET /api/user/orders/my-orders` | `@SaCheckLogin + @SaCheckRole("用户")` |
| 订单详情 | OrderDetail.vue | `GET /api/user/orders/detail/{id}` | 同上 |
| 创建课程订单 | Checkout.vue / AI 助手 | `POST /api/user/orders/create-course-order/{courseId}` | 同上 |
| 取消订单 | OrderList.vue | `PUT /api/user/orders/cancel/{orderNo}` | 同上 |
| 支付订单 | OrderList.vue | `POST /api/user/orders/pay` | 同上 |
| 按订单号查询 | 支付回调 | `GET /api/user/orders/by-order-no/{orderNo}` | 同上 |
| 退款 | OrderList.vue / OrderDetail.vue | `GET /api/alipay/refund` | ⚠ 继承类级 @SaCheckRole("用户") |
| 支付宝支付 | OrderList.vue / Checkout.vue | `GET /api/alipay/pay` | ⚠ 继承类级 @SaCheckRole("用户") |
| 支付回调 | 支付宝服务器 | `POST /api/alipay/notify` | ⚠ 类级 @SaCheckRole("用户") 阻断回调 |

| 教师订单详情 | 管理后台 | `GET /api/teacher/orders/{id}` | 同上 ⚠ 无归属校验 |

### 订单状态流转

> 完整的订单状态定义、流转图和前后端映射差异见 [公共参考-订单状态体系](../../公共参考/公共数据模型与基础配置.md#一订单状态体系)

**学生端多组件状态映射差异**：OrderList、OrderDetail、MessageContent(AI订单卡片) 三个组件对状态的展示和判断存在不一致，具体包括：
- OrderList 退款按钮检查 `order.status === 'PAID'`，但后端从不返回 PAID（直接 NOT_PAY → DONE），按钮为死代码；缺少 COMMENT_DONE 映射，AI 组件使用 CANCELLED（双写 L）而非后端的 CANCEL
- OrderDetail 定义了 PAID 状态但后端从不产生，且缺少 CANCEL 和 COMMENT_DONE 映射
- MessageContent 额外定义了 REFUND_PENDING 和 REFUNDED 状态但后端未使用

#### 数据加载流程

```
onMounted → loadOrders()
│
├── userApi.getMyOrders(searchParams)
│   → GET /api/user/orders/my-orders?page=1&size=10&status=
│
├── ⚠ 双重响应格式解包:
│   ├── 格式A: response.data?.records (Spring Boot PageHelper 分页)
│   └── 格式B: response.data?.list (旧格式兼容)
│   → orders.value = records || list || []
│   → total.value = response.data?.total || response.data?.totalCount || 0
│
├── loadStatistics()
│   ⚠ 仅基于当前页 orders 数组计算，非全局统计
│   ├── totalOrders = orders.length
│   ├── paidOrders = orders.filter(o => o.status === 'DONE').length
│   ├── unpaidOrders = orders.filter(o => o.status === 'NOT_PAY').length
│   ├── totalAmount = orders.reduce((sum, o) => sum + Number(o.coursePrice || 0), 0)
│   └── paidAmount = orders.filter(o => o.status === 'DONE').reduce((sum, o) => sum + Number(o.actualPrice || 0), 0)
│
└── ⚠ 统计数值随翻页变化，用户看到的统计不反映真实全局数据
```

### 2.3 AI 聊天中的订单卡片（MessageContent.vue）

AI 助手通过 PARAM 事件接收 `orderInfo_*` 参数，渲染为订单卡片：

| 订单状态 | 卡片样式 | 操作按钮 |
|---|---|---|
| NOT_PAY | 橙色状态标签 + 课程名+价格+时间 | "立即支付" → 支付宝 |
| PAID/DONE | 绿色状态标签 + 课程名+价格+时间 | "查看详情" → 订单详情 |
| CANCELLED/REFUNDED | 灰色状态标签 + 课程名+价格+时间 | "查看详情" |
| REFUND_PENDING | 橙色状态标签 | 无操作 |
| ERROR | 红色主题 + errorMessage | "查看我的订单" → 订单列表 |

⚠ AI 聊天卡片使用 CANCELLED（双写 L）和 REFUND_PENDING，与后端实际返回的 CANCEL 和 REFUND_DONE 不一致。

### 2.5 类型定义

```typescript
// order.ts
interface Order {
  id: number
  orderNo: string
  goodsId?: number         // 可选，后端字段名为 goodsId（沿袭电商命名）
  courseId: number
  courseName: string
  goodsImg?: string        // 可选，对应后端 courseCover
  actualPrice?: number     // 实际支付价格
  coursePrice?: number     // 课程原价
  paymentMethod?: string   // 支付方式
  status: number | string  // ⚠ 联合类型，兼容数字和字符串状态
  createTime: string
  payTime: string
  payNo: string
  updateTime: string
  userId: number
}

interface OrderStatistics {
  totalOrders: number
  paidOrders: number
  unpaidOrders: number
  totalAmount: number
  paidAmount: number
}

interface OrderSearchParams {
  page?: number
  size?: number
  status?: string | number
}

interface PaymentRequest {
  orderNo: string
  paymentMethod: string
}
```

⚠ `goodsId` 与 `courseId` 双字段命名：后端实体使用 `goodsId`（沿袭电商命名），前端 `Order` 接口同时定义两者，部分组件使用 `courseId`，部分使用 `goodsId`，存在不一致。`goodsImg` 对应后端返回的 `courseCover` 字段。Order 接口中不存在 `totalAmount` 字段，实际使用 `actualPrice` 和 `coursePrice`。

### 2.6 API 方法

```typescript
// user.ts
export const userApi = {
  createCourseOrder: (courseId: number) =>
    POST(`/api/user/orders/create-course-order/${courseId}`),
  getOrderDetail: (id: number) =>
    GET(`/api/user/orders/detail/${id}`),
  getMyOrders: (params: OrderSearchParams) =>
    GET('/api/user/orders/my-orders', params),
  getOrderByOrderNo: (orderNo: string) =>
    GET(`/api/user/orders/by-order-no/${orderNo}`),
  cancelOrder: (orderNo: string) =>
    PUT(`/api/user/orders/cancel/${orderNo}`),
  payOrder: (data: PaymentRequest) =>
    POST('/api/user/orders/pay', data),  // @RequestBody OrderPaymentDTO
}

// payment.ts
export const paymentApi = {
  alipayPay: (orderNo: string) => {
    // ⚠ 非 Axios，直接 window.location.href 重定向
    window.location.href = `http://159.75.11.181:9999/api/alipay/pay?orderNo=${orderNo}`
  },
  alipayRefund: (orderNo: string) =>
    GET('/api/alipay/refund', { params: { orderNo } }),
  alipayNotify: () => POST('/api/alipay/notify'),  // ⚠ 前端未使用
}
```

⚠ `alipayPay` 硬编码后端 IP 地址 `159.75.11.181:9999`，无法适应生产环境。URL 中仅传 orderNo，不传 totalAmount。

## 三、后端执行流程

### 3.1 Sa-Token 认证架构

> Sa-Token 认证架构详见 [认证系统指南](../公共参考/认证系统指南.md) 及 [公共参考-认证与权限体系](../../公共参考/公共数据模型与基础配置.md#二认证与权限体系sa-token)

**三套 Controller，三种角色**：

```
请求进入
│
├── 用户端: OrdersUserController
│   ├── @SaCheckLogin + @SaCheckRole("用户")
│   └── 所有关键操作均验证订单归属(userId 匹配)
│
├── 管理端: OrdersAdminController
│   └── @SaCheckRole("管理员")
│
├── 教师端: OrdersTeacherController
│   └── @SaCheckRole("教师")
│       ⚠ 详情接口无归属校验（TODO 注释）
│
└── 支付端: AliPayController
    └── ⚠ 类级 @SaCheckRole("用户") — /notify 回调被拦截
        AliPayController 在类级别标注了 @SaCheckRole("用户")，
        导致 /api/alipay/notify 端点也需用户角色认证，
        支付宝服务器回调无法通过认证，支付流程断裂
```

| 端点 | Interceptor | 注解 | 实际认证 |
|---|---|---|---|
| `/api/user/orders/*` | 拦截 | `@SaCheckLogin + @SaCheckRole("用户")` | **需登录+用户角色** |
| `/api/admin/orders/*` | 拦截 | `@SaCheckRole("管理员")` | **需登录+管理员角色** |
| `/api/teacher/orders/*` | 拦截 | `@SaCheckRole("教师")` | **需登录+教师角色** |
| `/api/alipay/*` | ⚠ 拦截 | ⚠ 类级 `@SaCheckRole("用户")` | **⚠ /notify 被阻断** |

### 3.2 我的订单列表（`GET /api/user/orders/my-orders`）

```
请求参数: OrderQueryDTO { pageNum(default 1), pageSize(default 10), userId?, goodsId?, status?, orderNo? }
│
┌─ Sa-Token 校验: @SaCheckLogin + @SaCheckRole("用户")
│
┌─ 步骤1: 构建 DAO 查询对象
│  ├── Orders condition = new Orders()
│  ├── condition.setUserId(SaUtil.getLoginId())   ← 强制当前用户
│  └── condition.setStatus(status)                 ← 仅 status 传入
│  ⚠ goodsId 和 orderNo 从 DTO 接收但被静默忽略
│  ⚠ userId 从 DTO 接收但被 SaUtil.getLoginId() 覆盖
│
┌─ 步骤2: PageHelper 分页
│  └── PageHelper.startPage(pageNum, pageSize)
│
┌─ 步骤3: DAO 查询
│  └── ordersDao.queryByUserId(condition)
│      SQL: SELECT ... FROM orders
│           WHERE user_id = #{userId}
│           [AND status = #{status}]
│           ORDER BY create_time DESC
│      ⚠ 仅支持 userId + status 过滤，goodsId/orderNo 条件未生效
│
┌─ 步骤4: 实体→VO 转换
│  └── convertToVO() → 每条记录:
│      courseDao.queryById(goodsId) → 课程名+goodsImg查找
│      ⚠ N+1 查询问题
│
└─ 返回 Result<PageInfo<OrderVO>>
    字段: id, orderNo, goodsId, courseName, goodsImg,
          actualPrice, coursePrice, paymentMethod, status, createTime, payTime, payNo
```

### 3.3 订单详情（`GET /api/user/orders/detail/{id}`）

```
请求参数: id (path variable, min=1)
│
┌─ Sa-Token 校验
│
┌─ 步骤1: DAO 查询
│  └── ordersDao.queryById(id)
│
┌─ 步骤2: 归属校验
│  └── order.getUserId() != SaUtil.getLoginId() → MyException("无权查看")
│
┌─ 步骤3: 课程信息查找
│  └── courseDao.queryById(goodsId) → courseName + goodsImg
│
└─ 返回 Result<OrderVO>
```

### 3.10 教师端订单查询

```

│   SQL: SELECT o.* FROM orders o
│        INNER JOIN course c ON o.goods_id = c.id
│        WHERE c.teacher_id = #{teacherId}
│        [AND o.status = #{status}]
│        ORDER BY o.create_time DESC
│
├── 我的收入趋势 (my-revenue)
│   SQL: SELECT DATE(o.create_time) as date, SUM(o.total_amount) as revenue
│        FROM orders o INNER JOIN course c ON o.goods_id = c.id
│        WHERE c.teacher_id = #{teacherId} AND o.status = 'DONE'
│        ⚠ DATE() 函数作用于 VARCHAR 列，依赖 MySQL 隐式类型转换
│        ⚠ 应使用 STR_TO_DATE() 或改为 DATE/TIMESTAMP 列类型
│
├── 热门课程排名 (top-courses)
│   SQL: SELECT c.title, COUNT(*) as order_count, SUM(o.total_amount) as revenue
│        FROM orders o INNER JOIN course c ON o.goods_id = c.id
│        WHERE c.teacher_id = #{teacherId} AND o.status = 'DONE'
│        GROUP BY c.id, c.title ORDER BY order_count DESC LIMIT #{limit}
│
└── 订单详情 ({id})
    ├── ordersDao.queryById(id)
    ⚠ 无归属校验 — 教师可查看任意订单详情（TODO 注释）
```

### 3.11 支付宝支付与回调

```
支付流程:
│
├── 前端: window.location.href → GET /api/alipay/pay?orderNo=xxx
│   └── ⚠ 类级 @SaCheckRole("用户")，GET 请求仅传 orderNo，不传 totalAmount
│
├── AliPayController.pay():
│   ├── 构建 AlipayClient (沙箱配置)
│   ├── AlipayTradePagePayRequest
│   ├── setReturnUrl → 前端同步回调页
│   ├── setNotifyUrl → /api/alipay/notify (异步通知)
│   └── 返回支付宝收银台 HTML
│
├── 支付宝异步通知 → POST /api/alipay/notify
│   ├── ⚠ 被 AliPayController 类级 @SaCheckRole("用户") 拦截，支付宝回调无法通过认证
│   ├── 验签: AlipaySignature.rsaCheckV1()
│   ├── 提取 trade_status + out_trade_no + trade_no
│   ├── trade_status == "TRADE_SUCCESS" →
│   │   └── AliPayController 直接处理:
│   │       ├── 幂等检查: 订单状态非 NOT_PAY → 跳过
│   │       ├── updateStatus(orderNo, "DONE")     → 先更新状态为 DONE
│   │       ├── handlePaymentSuccess(orderNo, tradeNo)  → 再调用
│   │       │   ├── 内部再次幂等检查: 状态已为 DONE（非 NOT_PAY）→ 直接 return
│   │       │   ├── ⚠ addToMyCourse 永远不会被执行 — 课程不会加入用户已购列表
│   │       │   └── ⚠ updateCourseSales 永远不会被执行 — buyCount 不会递增
│   │       ├── updatePayInfo(orderNo, tradeNo)    → 设置 payNo + payTime
│   │       └── payTime 来自 Alipay 的 gmt_payment 字段（标准格式）
│   │
│   └── 返回 "success"（支付宝要求）
│
├── 退款 → GET /api/alipay/refund?orderNo=xxx
│   ├── ⚠ 继承类级 @SaCheckRole("用户")
│   ├── AlipayTradeRefundRequest
│   ├── 仅传 orderNo 参数，不支持部分退款
│   └── 退款成功 → updateStatus(orderNo, "REFUND_DONE")
│
└── ⚠ 核心缺陷: handlePaymentSuccess 因状态已被设为 DONE 而提前退出，
    导致 addToMyCourse 和 updateCourseSales 均不执行。
    用户支付成功后课程不会自动加入已购列表，buyCount 也不会增加。
```

### 3.12 数据库表结构

> 数据库表结构详见 [数据库表结构汇总](../../公共参考/数据库表结构汇总.md)（orders）

⚠ `create_time` 和 `pay_time` 使用 VARCHAR 类型存储，依赖 Java 端写入，导致：
- MySQL 日期函数（DATE/STR_TO_DATE）需要隐式转换
- 教师收入趋势查询 `DATE(o.create_time)` 依赖隐式转换
- 排序 `ORDER BY create_time DESC` 是字符串排序而非时间排序
- payTime 来自 Alipay 的 gmt_payment 字段（标准日期格式），createTime 由后端生成

**索引**：user_id, status, order_no(UNIQUE), goods_id, (user_id + status) 联合索引

## 五、已知问题与风险点

> 跨模块系统级问题见 [公共参考-系统级已知问题与风险清单](../../公共参考/系统级已知问题与风险清单.md)，此处仅列本模块独有问题。

| # | 问题 | 严重度 | 说明 |
|---|---|---|---|
| 1 | **OrderDetail 退款为假实现** | 高 | 仅显示成功提示但未调用退款 API，用户以为已退款但实际未执行 |
| 2 | **退款按钮可见性不一致** | 中 | OrderList 仅 PAID 可退（但后端从不返回 PAID，按钮为死代码），OrderDetail DONE+PAID 可退 |
| 3 | **统计仅基于当前页** | 中 | `loadStatistics()` 仅统计当前页订单数量，用户看到的数字不反映真实全局数据 |
| 4 | **管理员统计 6 次 DB 查询** | 中 | 每次请求 6 个独立查询，无缓存，应合并或缓存 |
| 5 | **支付回调被 @SaCheckRole 拦截** | 高 | AliPayController 类级 @SaCheckRole("用户") 导致 /notify 端点需认证，支付宝回调无法通过 |
| 6 | **教师详情接口无归属校验** | 高 | 教师可查看任意用户订单详情，存在信息泄露风险 |
| 7 | **addToMyCourse 永不执行** | 高 | AliPayController 先设 DONE 再调 handlePaymentSuccess，后者因状态已非 NOT_PAY 提前退出，课程不加入已购列表 |
| 8 | **用户端筛选条件被忽略** | 中 | OrderQueryDTO 的 goodsId/orderNo 在用户端查询中被静默忽略 |
| 9 | **OrderConstants 为空** | 中 | 订单状态常量类无实际内容，所有状态字符串硬编码分散 |
| 10 | **OrderCreateDTO 未使用** | 低 | DTO 已定义但创建订单未使用，courseId 直接从路径变量取 |
| 11 | **支付成功提示不可见** | 低 | 支付宝同步回调后 `ElMessage.success` 执行，但页面已导航到订单列表，用户看不到 |
| 12 | **goToCourse 跳转错误** | 低 | 订单详情"查看课程"跳转 CourseDetail 而非 CourseLearn，已购课程应进入学习页 |
| 13 | **updateTime=createTime Bug** | 低 | OrderDetail 中将 updateTime 硬编码为 createTime |
| 14 | **goodsId/courseId 双命名** | 低 | 后端实体用 goodsId，前端同时定义 goodsId 和 courseId，组件间使用不一致 |
| 15 | **无订单超时自动取消** | 中 | NOT_PAY 订单无定时清理机制，可能无限期占用 |
| 16 | **退款仅支持全额** | 低 | alipayRefund 仅传 orderNo 参数，不支持部分退款 |
| 17 | **重复下单检查不完整** | 中 | 仅检查 DONE 和 NOT_PAY 状态，CANCEL 状态的订单允许重复购买同一课程 |
| 18 | **OrderList 退款按钮为死代码** | 中 | 退款按钮检查 order.status === 'PAID'，但后端从不返回 PAID 状态，按钮永远不渲染 |
