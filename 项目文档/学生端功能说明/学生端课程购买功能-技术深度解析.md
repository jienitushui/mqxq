# 学生端课程购买功能 — 技术深度解析

## 一、功能概述

学生端课程购买模块涵盖从课程详情页"立即购买"到支付宝支付完成、自动加入"我的课程"的完整链路，涉及前端结算页/支付页/订单管理页，以及后端订单创建、支付宝集成、异步回调、退款等核心流程。

### 功能清单

| 功能 | 前端页面/组件 | 后端端点 | 认证要求 |
|---|---|---|---|
| 发起购买 | CourseDetail.vue | — | 前端跳转 |
| 结算确认 | Checkout.vue | — | 前端页面 |
| 创建订单 | Checkout.vue | `POST /api/user/orders/create-course-order/{courseId}` | `@SaCheckLogin + @SaCheckRole("用户")` |
| 发起支付 | Payment.vue | `GET /api/alipay/pay?orderNo=` | ⚠ 拦截器排除 |
| 支付宝回调 | — | `POST /api/alipay/notify` | ⚠ 拦截器排除 |
| 退款 | OrderList.vue | `GET /api/alipay/refund?orderNo=` | ⚠ 拦截器排除 |
| 订单列表 | OrderList.vue | `GET /api/user/orders/my-orders` | `@SaCheckLogin + @SaCheckRole("用户")` |
| 订单详情 | OrderDetail.vue | `GET /api/user/orders/detail/{orderId}` | 同上 |
| 取消订单 | OrderList/Detail | `PUT /api/user/orders/cancel/{orderNo}` | 同上 |
| 按单号查询 | — | `GET /api/user/orders/by-order-no/{orderNo}` | 同上 |
| 处理支付 | — | `POST /api/user/orders/pay` | 同上 |
| 购买状态检查 | CourseDetail.vue | `GET /api/user/course/purchase-status/{courseId}` | `@SaCheckLogin` |
| AI 预下单 | AI 聊天助手 | CourseTools.prePlaceOrder | `@SaCheckLogin + @SaCheckRole("用户")` |
| 管理员订单管理 | 管理后台 | `/api/admin/orders/*` | `@SaCheckRole("管理员")` |
| 教师收入管理 | 教师后台 | `/api/teacher/orders/*` | `@SaCheckRole("教师")` |

### 购买流程全景

```
学生端购买流程:
CourseDetail.vue (立即购买)
    ↓ router.push
Checkout.vue (确认信息 → 创建订单)
    ↓ POST /api/user/orders/create-course-order/{courseId}
    ↓ router.push
Payment.vue (点击"立即支付")
    ↓ window.location.href → 支付宝页面
    ↓ 用户完成支付
    ↓
支付宝异步回调 → POST /api/alipay/notify
    ↓ 验签 → 更新订单为 DONE → 创建 my_course 记录
    ↓
用户手动返回 → OrderList.vue 查看订单状态

教师端AI预下单:
AI 聊天助手 → CourseTools.prePlaceOrder(courseId)
    ↓ purchaseCourse() → 创建 NOT_PAY 订单
    ↓ 返回 OrderInfo → 前端渲染订单卡片
    ↓ 用户点击"立即支付" → 同上支付宝流程
```

### 订单状态生命周期

> 完整的订单状态定义、流转图和前后端映射差异见 [公共参考-订单状态体系](../../公共参考/公共数据模型与基础配置.md#一订单状态体系)。本模块涉及状态：创建订单→NOT_PAY、支付回调→DONE、用户取消→CANCEL、退款→REFUND_DONE、评价→COMMENT_DONE。

## 二、前端关键逻辑

### 2.1 课程详情页购买入口（CourseDetail.vue）

```
课程详情页判断逻辑:
├── 未登录 → "登录后学习" 按钮 → router.push('/Login')
├── 已登录 + 已购买(DONE订单) → "继续学习" / "开始学习"
├── 已登录 + 未购买 + 付费课程 → "立即购买"
└── 已登录 + 未购买 + 免费课程 → "立即购买"（⚠ 仍走结算流程）
```

购买触发：
```typescript
const buyCourse = () => {
  router.push(`/orders/checkout/${course.value.id}`)
}
```

⚠ 无论免费或付费，均跳转结算页。`CourseCard.vue` 中免费课程走直接 `joinCourse` 跳过订单，两处逻辑不一致。


#### 创建订单流程

```
onMounted → getCourseDetail(courseId)
│   ├── 登录 → userApi.getCourseDetail(courseId)
│   └── 未登录 → publicApi.getCourseDetail(courseId)
│   └── 映射: title→name, cover→coverImage, ...
│
用户勾选协议 → 点击"创建订单"
├── canSubmit: agreeTerms && selectedPaymentMethod && !loading && courseInfo.value
├── !courseInfo.value → "课程信息不存在"
├── userApi.createCourseOrder(courseInfo.value.id)
│   → POST /api/user/orders/create-course-order/{courseId}
├── 成功 → "订单创建成功" → router.push(`/payment/${order.id}`)
│   ⚠ 传的是 order.id（数字），路由参数名为 orderNo
└── 失败 → "创建订单失败"
```

**⚠ 路由参数不一致**：`router.push(\`/payment/${order.id}\`)` 传递数字 ID，但路由定义 `/payment/:orderNo`，Payment.vue 读取 `route.params.orderNo` 后调用 `getOrderDetail(Number(orderId))` — 因后端 `detail/{orderId}` 接受数字 ID，碰巧能工作，但命名混乱。

#### 数据加载

```

├── userApi.getOrderDetail(Number(orderId))
│   → GET /api/user/orders/detail/{orderId}
├── 字段映射: goodsId→courseId, goodsName→courseName,
│            goodsPrice→coursePrice/actualPrice, goodsImg, payNo
└── 状态检查: 非 NOT_PAY/'0'/0 → "订单状态异常" → 跳转订单列表
```

#### 支付执行

```
handlePayment()
├── 仅支持支付宝
├── paymentApi.alipayPay(order.value.orderNo)
│   → window.location.href = "http://159.75.11.181:9999/api/alipay/pay?orderNo=XXXX"
│   → 整页硬跳转到支付宝收银台
└── ⚠ 跳转后当前页面已卸载，无回调处理
```

**⚠ 无支付完成回调**：
- 无同步回调页面处理（支付宝 returnUrl 仅跳转到 OrderList）
- 无支付状态轮询机制
- 用户需手动返回网站查看订单确认支付是否成功

## 三、后端执行流程

### 3.1 认证架构

Sa-Token 认证架构详见[认证系统指南](../公共参考/认证系统指南.md)。

本模块端点认证要求：

| 控制器 | 路径前缀 | 拦截器 | 注解 | 实际认证 |
|---|---|---|---|---|
| AliPayController | `/api/alipay` | **排除** | `@SaCheckRole("用户")` | ⚠ 拦截器排除后注解可能失效 |
| OrdersUserController | `/api/user/orders` | 拦截 | `@SaCheckLogin + @SaCheckRole("用户")` | 需登录+用户角色 |
| OrdersAdminController | `/api/admin/orders` | 拦截 | `@SaCheckRole("管理员")` | 需登录+管理员角色 |
| OrdersTeacherController | `/api/teacher/orders` | 拦截 | `@SaCheckRole("教师")` | 需登录+教师角色 |

**⚠ 支付路径认证缺陷**：`/api/alipay/**` 被整体排除在 Sa-Token 拦截器之外，意味着：
- `/api/alipay/pay` — 免登录可访问（支付宝跳转所需）
- `/api/alipay/notify` — 免登录可访问（支付宝回调所需）
- `/api/alipay/refund` — **免登录可访问**（安全隐患，任何人可退款任何订单）

### 3.3 创建订单（`POST /api/user/orders/create-course-order/{courseId}`）

```
请求参数: courseId (path variable)
│
┌─ Sa-Token 校验: @SaCheckLogin + @SaCheckRole("用户") → userId
│
┌─ 步骤1: 参数校验
│  └── userId > 0, courseId > 0
│
┌─ 步骤2: 验证课程
│  ├── courseService.queryById(courseId)
│  ├── 课程为 null → "课程不存在"
│  └── status != 1 → "该课程暂未发布"
│
┌─ 步骤3: 检查重复购买
│  ├── canStudyCourse(userId, courseId)
│  │   ├── 查找 DONE/COMMENT_DONE 订单 → 已购买
│  │   └── course.price == 0 → 免费课程也返回 true
│  └── canStudy == true → "您已购买过该课程"
│
┌─ 步骤4: 检查未支付订单
│  ├── 查询用户所有订单，筛选 courseId + status='NOT_PAY'
│  └── 存在 → "您有该课程的未支付订单，请先完成支付或取消订单"
│
┌─ 步骤5: 生成订单号
│  └── "MQXQ_ORDER_{timestamp}_{threadId}_{8位UUID}"
│
┌─ 步骤6: 创建 Orders 实体
│  ├── goodsId = courseId, goodsName = course.title
│  ├── goodsImg = course.cover, goodsPrice = course.price (BigDecimal)
│  ├── orderNo = 生成的订单号
│  ├── userId = userId
│  ├── status = "NOT_PAY"
│  ├── createTime = new Date().toString()  ← ⚠ 字符串存储
│  └── ordersDao.insert(order)
│      └── insert 失败 → "订单创建失败"
│
├─ 异常捕获
│  └── "购买课程失败：" + e.getMessage()
│
└─ 返回 Result<OrderVO>
    字段: id, orderNo, userId, goodsId, goodsName, goodsImg,
          goodsPrice, status, createTime
```

### 3.4 发起支付宝支付

> 完整执行流程详见 [支付宝支付集成功能-发起支付](支付宝支付集成功能-技术深度解析.md#34-发起支付接口get-apialipaypayordernoxxx-拦截器排除)

### 3.5 支付宝异步回调

> 完整执行流程（含验签、状态更新、buyCount 递增）详见 [支付宝支付集成功能-异步回调](支付宝支付集成功能-技术深度解析.md#35-异步回调通知接口post-apialipaynotify-拦截器排除支付宝服务器调用)

**⚠ my_course 永不创建**：`AliPayController.payNotify()` 先将订单设为 DONE 再调用 `handlePaymentSuccess()`，后者检查到订单状态非 NOT_PAY 后提前返回，`addToMyCourse()` 和 `updateCourseSales()` 永不执行。实际结果：buyCount 仅递增 1 次（非双重递增），但用户付了钱却无 my_course 记录。

### 3.6 支付成功处理（`CoursePurchaseServiceImpl.handlePaymentSuccess`）

> 完整执行流程详见 [支付宝支付集成功能-异步回调](支付宝支付集成功能-技术深度解析.md#35-异步回调通知接口post-apialipaynotify-拦截器排除支付宝服务器调用) 步骤6

关键问题：
- handlePaymentSuccess 因订单已为 DONE 而提前返回，以下操作永不执行：
  - `addToMyCourse`（用户付钱后无课程记录）
  - `updateCourseSales`（buyCount 不会二次递增）
- addToMyCourse 中 status 未设置，即使执行也会因 NOT NULL 约束失败（异常被吞没）

### 3.7 退款

> 完整执行流程详见 [支付宝支付集成功能-退款](支付宝支付集成功能-技术深度解析.md#36-退款接口get-apialipayrefundordernoxxx-拦截器排除)

**退款问题**：
- 退款 API 返回失败时仍设置 `REFUND_DONE`
- 无订单状态校验（未检查是否为 `DONE` 状态）
- 无权限校验（任何用户可退款任何订单）

### 3.8 取消订单（`PUT /api/user/orders/cancel/{orderNo}`）

```

│
┌─ 步骤1: 查询订单
│  └── ordersService.selectByOrderNo(orderNo)
│

└─ 返回 Result.success("订单已取消")
```

### 3.14 数据库表结构

> 数据库表结构详见 [数据库表结构汇总](../../公共参考/数据库表结构汇总.md)（orders）

**⚠ 时间字段以 VARCHAR 存储**，非原生 DATETIME/TIMESTAMP，使得时间范围查询依赖 MySQL 隐式转换。

## 四、前后端交互时序

### 完整购买流程

```
CourseDetail.vue → "立即购买"
│
├── router.push('/orders/checkout/{courseId}')
│
├── Checkout.vue onMounted
│   ├── GET /api/user/course/{courseId} 或 /api/public/course/{courseId}
│   └── 用户确认 → 点击"创建订单"
│       ├── POST /api/user/orders/create-course-order/{courseId}
│       │   → 创建 Orders(status=NOT_PAY)
│       └── router.push('/payment/{order.id}')
│
├── Payment.vue onMounted
│   ├── GET /api/user/orders/detail/{orderId}
│   └── 用户点击"立即支付"
│       └── window.location.href → GET /api/alipay/pay?orderNo=XXX
│           → 后端生成支付宝表单 HTML → 浏览器自动跳转支付宝
│
├── 用户在支付宝完成支付
│   │
│   ├── 支付宝异步回调 → POST /api/alipay/notify
│   │   ├── 验签
│   │   ├── 更新订单: status → DONE
│   │   ├── ⚠ buyCount + 1 (非原子)
│   │   └── handlePaymentSuccess()
│   │       ├── 再次更新订单 (冗余写入)
│   │       ├── 创建 my_course(status=0)
│   │       └── ⚠ buyCount + 1 (双重递增)
│   │
│   └── 支付宝同步跳转 → http://159.75.11.181:5173/orders/OrderList
│       └── 用户手动查看订单状态
│
└── 用户在 OrderList 看到订单状态变为"已完成"
    └── 可前往"我的课程"学习
```

### AI 预下单流程

```
AI 聊天 → 用户请求购买课程
│
├── LLM 调用 CourseTools.prePlaceOrder(courseId)
│   ├── CoursePurchaseServiceImpl.purchaseCourse()
│   ├── 创建 Orders(status=NOT_PAY)
│   └── 返回 OrderInfo → ToolResultHolder
│
├── SSE PARAM 事件 → 前端渲染订单卡片
│
└── 用户点击"立即支付" → paymentApi.alipayPay(orderNo)
    → 同上支付宝流程
```

### 取消订单流程

```
OrderList/Detail → "取消订单"
│
├── PUT /api/user/orders/cancel/{orderNo}
│   ├── 归属校验 + 状态校验(NOT_PAY)
│   └── status → CANCEL
│
└── 前端刷新列表
```

## 五、已知问题与风险点

> 跨模块系统级问题（N+1查询、全表扫描、SQL注入、退款无认证等）见 [公共参考-系统级已知问题与风险清单](../../公共参考/系统级已知问题与风险清单.md)，此处仅列本模块独有问题。

| # | 问题 | 严重度 | 说明 |
|---|---|---|---|
| 1 | **my_course 永不创建** | 高 | `AliPayController.payNotify()` 先设 DONE 再调 `handlePaymentSuccess()`，后者因状态非 NOT_PAY 提前返回，`addToMyCourse()` 永不执行，用户付钱后无课程记录（buyCount 仅递增1次，非双重递增） |
| 2 | **退款端点无认证强制** | 高 | `/api/alipay/refund` 随拦截器排除而免登录，任何人都可退款任何订单 |
| 3 | **退款无论 API 结果都标记 REFUND_DONE** | 高 | 退款 API 返回失败时仍设置 `REFUND_DONE`，与实际退款状态不一致 |
| 4 | **addToMyCourse 吞没异常** | 高 | 支付成功后创建 my_course 失败时仅记日志（且 status 未设置，INSERT 违反 NOT NULL 约束） |
| 5 | **buyCount 非原子递增** | 中 | 所有 buyCount 更新均为 read-modify-write 非原子操作，并发下丢失更新 |
| 6 | **支付回调无分布式锁** | 中 | 支付宝可能重复通知，状态检查有 TOCTOU 窗口，并发回调可能创建重复 my_course |
| 7 | **handlePaymentSuccess 提前返回** | 中 | AliPayController 已将订单设为 DONE，handlePaymentSuccess 检查到非 NOT_PAY 直接返回，所有子操作均不执行 |
| 8 | **payOrder @Transactional 自调用失效** | 中 | Spring AOP 不拦截同类内部调用，`processOrderPayment → payOrder` 事务边界不生效 |
| 9 | **MyCourseCreateDTO 构造误用** | 中 | `new MyCourseCreateDTO(goodsId, orderId)` 将 orderId 作为 status 参数传入，导致 my_course.status 值错误（仅影响 payOrder 路径） |
| 10 | **无订单超时自动取消** | 中 | NOT_PAY 订单永久保留，无定时清理，导致订单表膨胀 |
| 11 | **前端无支付完成回调/轮询** | 中 | 用户支付后无前端机制确认结果，需手动返回查看订单 |
| 12 | **前端退款功能造假** | 中 | OrderDetail.vue 的 `requestRefund` 不调用 API 仅显示成功消息 |
| 13 | **免费课程处理不一致** | 中 | CourseDetail 走完整购买流程，CourseCard 直接 joinCourse，CourseLearn 自动加入，无统一策略 |
| 14 | **订单状态双系统** | 中 | 字符串和数字状态并存，`CANCEL`/`CANCELLED`、`REFUND_DONE`/`REFUNDED` 多种拼写 |
| 15 | **Checkout→Payment 路由参数混乱** | 中 | 传 order.id 但参数名 orderNo，Payment 用此值调 detail/{id}，命名与语义不匹配 |
| 16 | **支付 URL 硬编码 IP** | 中 | `http://159.75.11.181:9999` 和 `http://159.75.11.181:5173` 硬编码，应使用环境变量 |
| 17 | **订单时间 VARCHAR 存储** | 低 | create_time/pay_time 为 VARCHAR 而非 DATETIME，时间查询依赖 MySQL 隐式转换 |
| 18 | **OrderConstants 类为空** | 低 | 订单状态等常量全部硬编码字符串，无常量定义 |
| 19 | **OrderList 统计仅当前页** | 低 | 从当前页 orders 数组计算统计，翻页后数据不反映全量 |
| 20 | **字段名前后端不一致** | 低 | 后端 goodsId/goodsName/goodsPrice，前端 courseId/courseName/coursePrice，每个页面手动映射 |
| 21 | **支付宝沙箱环境** | 低 | 使用沙箱网关和沙箱 App ID，未接入生产环境 |
| 22 | **大量 console.log 残留** | 低 | 订单/支付页面函数中大量调试日志未清理 |
