# 支付宝支付集成功能 — 技术深度解析

## 一、功能概述

支付宝支付集成模块是码趣星球平台课程购买的核心基础设施，覆盖从订单创建、支付宝收银台跳转、异步回调通知、自动开通课程到退款的完整链路。涉及前端 4 个页面、1 个专用支付 API 文件、后端 3 个 Service 及 1 个 AI 工具调用，集成支付宝沙箱环境。

### 功能清单

| 功能 | 前端页面 | 后端端点 | 认证要求 |
|---|---|---|---|
| 发起支付 | Payment.vue / OrderList / AI聊天 | `GET /api/alipay/pay?orderNo=` | ⚠ 拦截器排除 |
| 异步回调 | — (支付宝服务器调用) | `POST /api/alipay/notify` | ⚠ 拦截器排除 |
| 退款 | OrderList.vue / AI聊天 | `GET /api/alipay/refund?orderNo=` | ⚠ 拦截器排除 |
| 创建订单 | Checkout.vue / AI聊天 | `POST /api/user/orders/create-course-order/{courseId}` | `@SaCheckLogin + @SaCheckRole("用户")` |
| 我的订单 | OrderList.vue | `GET /api/user/orders/my-orders` | 同上 |
| 订单详情 | OrderDetail.vue | `GET /api/user/orders/detail/{orderId}` | 同上 |
| 取消订单 | OrderList / Detail | `PUT /api/user/orders/cancel/{orderNo}` | 同上 |
| 按单号查询 | — | `GET /api/user/orders/by-order-no/{orderNo}` | 同上 |
| 购买状态检查 | CourseDetail.vue | `GET /api/user/course/purchase-status/{courseId}` | `@SaCheckLogin` |
| AI 预下单 | ChatPage (SSE PARAM) | CourseTools.prePlaceOrder | AI ToolCallback |

### 技术栈关键点

- **前端**：Vue 3 + Element Plus + Axios（支付页直接 `window.location.href` 跳转）
- **后端**：Spring Boot 3.2 + alipay-sdk-java 4.35.79.ALL（沙箱）+ Sa-Token + MyBatis
- **沙箱环境**：网关 `https://openapi-sandbox.dl.alipaydev.com/gateway.do`，签名 RSA2
- **订单状态**：VARCHAR 字符串（NOT_PAY / DONE / CANCEL / REFUND_DONE / COMMENT_DONE）

### 2.1-2.5 学生端页面要点摘录

- **购买入口 (CourseDetail)**: 免费课程仍走完整下单流程，无"免费加入"快捷路径

### 2.6 支付 API 层（payment.ts）

```typescript
// 发起支付 — 全页跳转，不走 Axios
alipayPay(orderNo: string) {
  window.location.href = `http://159.75.11.181:9999/api/alipay/pay?orderNo=${orderNo}`
  // 注释行: http://mqxq.free.idcfengye.com/api/alipay/pay?orderNo=...
  return Promise.resolve()
}

// 退款 — 标准 Axios GET
alipayRefund(orderNo: string): Promise<Result> {
  return request.get('/api/alipay/refund', { params: { orderNo } })
}

// 异步通知 — 前端不应调用
alipayNotify(data: any): Promise<string> {
  return request.post('/api/alipay/notify', data)
}
```

> ⚠ `alipayPay` 使用硬编码 IP，绕过了 Axios 拦截器（无 token 头、无 401 处理）。但后端 `/api/alipay/**` 已从 Sa-Token 拦截器排除，所以不影响功能。

## 三、后端执行流程

### 3.1 认证架构

> Sa-Token 认证架构与拦截器配置详见 [公共参考-认证与权限体系](../公共参考/公共数据模型与基础配置.md#二认证与权限体系sa-token)

**支付模块鉴权矛盾**：`/api/alipay/**` 被 SaInterceptor 整体放行，但 AliPayController 类级标注 `@SaCheckRole("用户")`。实际效果：

| 端点 | 拦截器 | 注解 | 实际认证 |
|---|---|---|---|
| `GET /api/alipay/pay` | 放行 | `@SaCheckRole("用户")` | ⚠ 需有效 token 但无 cookie（前端跳转不带） |
| `POST /api/alipay/notify` | 放行 | `@SaCheckRole("用户")` | ⚠ 支付宝回调无法通过用户角色校验 |
| `GET /api/alipay/refund` | 放行 | `@SaCheckRole("用户")` | ⚠ 需有效 token |

> ⚠ **高风险**：支付宝异步回调（notify）由支付宝服务器发起，无法携带用户 token，理论上无法通过 `@SaCheckRole("用户")` 校验。若 Sa-Token 注解优先于拦截器，回调将失败。

### 3.3 创建订单接口

#### `POST /api/user/orders/create-course-order/{courseId}`（需登录）

```
请求参数: courseId (path)
│
┌─ 步骤1: 获取 userId
│  └── SaUtil.getLoginId() → StpUtil.getLoginId()
│
┌─ 步骤2: CoursePurchaseService.purchaseCourse(userId, courseId)
│  │
│  ├── 校验课程: queryById → 不存在/未发布 → 抛 MyException
│  ├── 重复购买: canStudyCourse() → 已有 DONE/COMMENT_DONE 订单 → 抛 "您已购买过该课程"
│  ├── 未支付检查: queryByUserId → 存在 NOT_PAY 订单 → 抛 "您有该课程的未支付订单"
│  │
│  ├── 生成订单号: "MQXQ_ORDER_{timestamp}_{threadId}_{8位UUID}"
│  ├── 创建 Orders 实体:
│  │   goodsId=courseId, goodsName=course.title, goodsImg=course.cover
│  │   goodsPrice=course.price, orderNo=生成的订单号
│  │   userId=userId, createTime=格式化当前时间, status="NOT_PAY"
│  │
│  └── ordersService.insert(order)
│      SQL: INSERT INTO orders(goods_id, goods_name, goods_img,
│            goods_price, order_no, user_id, create_time, pay_no,
│            pay_time, status) VALUES (...)
│
└─ 返回 Result<OrderVO>
    字段: id, goodsId, goodsName, goodsImg, goodsPrice,
          orderNo, userId, createTime, payNo, payTime, status
```

### 3.4 发起支付接口

#### `GET /api/alipay/pay?orderNo=xxx`（⚠ 拦截器排除）

```
请求参数: orderNo (query)
│
┌─ 步骤1: 查询订单
│  └── ordersService.selectByOrderNo(orderNo)
│      SQL: SELECT ... FROM orders WHERE order_no = #{orderNo}
│      → 不存在 → 抛 MyException("未找到订单")
│
┌─ 步骤2: 创建 AlipayClient
│  └── new DefaultAlipayClient(gatewayUrl, appId, appPrivateKey,
│        format, charset, alipayPublicKey, signType)
│
┌─ 步骤3: 构建支付请求
│  ├── AlipayTradePagePayRequest
│  ├── notifyUrl = http://159.75.11.181:9999/api/alipay/notify
│  ├── returnUrl = http://159.75.11.181:5173/orders/OrderList
│  └── bizContent:
│      { out_trade_no: orders.orderNo,     ← 商户订单号
│        total_amount: orders.goodsPrice,   ← 支付金额
│        subject: orders.goodsName,         ← 商品名称
│        product_code: "FAST_INSTANT_TRADE_PAY" }  ← PC 网页支付
│
┌─ 步骤4: 生成支付表单
│  └── alipayClient.pageExecute(request).getBody()
│      → Alipay SDK 生成 HTML 表单（自动提交到支付宝网关）
│
└─ 步骤5: 输出到浏览器
   ├── httpResponse.setContentType("text/html;charset=UTF-8")
   ├── httpResponse.getWriter().write(form)
   └── 浏览器自动跳转到支付宝收银台
```

### 3.5 异步回调通知接口

#### `POST /api/alipay/notify`（⚠ 拦截器排除，支付宝服务器调用）

```
由支付宝服务器在用户支付完成后异步调用
│
┌─ 步骤1: 读取回调参数
│  ├── trade_status = request.getParameter("trade_status")
│  └── 非 "TRADE_SUCCESS" → 返回 "success"（避免重复回调）
│
┌─ 步骤2: 验签（RSA2）
│  ├── 收集所有参数到 Map<String, String>
│  ├── AlipaySignature.getSignCheckContentV1(params) → 待签名字符串
│  ├── AlipaySignature.rsa256CheckContent(content, sign, alipayPublicKey, "UTF-8")
│  └── 验签失败 → 返回 "fail"
│
┌─ 步骤3: 提取支付信息
│  ├── out_trade_no → 商户订单号 (orderNo)
│  ├── trade_no → 支付宝交易号 (payNo)
│  └── gmt_payment → 支付时间 (payTime)
│
┌─ 步骤4: 更新订单状态
│  ├── ordersService.selectByOrderNo(orderNo)
│  ├── orders.setStatus("DONE")
│  ├── orders.setPayNo(alipayTradeNo)
│  ├── orders.setPayTime(gmtPayment)
│  └── ordersService.updateById(orders)
│      SQL: UPDATE orders SET status='DONE', pay_no=#{payNo},
│           pay_time=#{payTime} WHERE id = #{id}
│
┌─ 步骤5: 增加课程购买数 ⚠
│  ├── course = courseService.queryById(orders.getGoodsId())
│  ├── course.setBuyCount(course.getBuyCount() + 1)
│  └── courseService.update(course)
│
┌─ 步骤6: 开通课程
│  └── coursePurchaseService.handlePaymentSuccess(orderNo)
│      ├── 再次检查订单状态是否为 NOT_PAY
│      ├── 再次 setStatus("DONE") + updateById ⚠ 二次更新
│      ├── addToMyCourse(userId, courseId, orderId)
│      │   ├── myCourseDao.queryByUserIdAndCourseId(userId, courseId)
│      │   │   → 已存在 → 跳过
│      │   └── myCourseDao.insert(myCourse)
│      │       → 创建 my_course 记录 (status=0 已加入)
│      └── updateCourseSales(courseId) ⚠ 二次自增 buyCount
│          ├── course.setBuyCount(course.getBuyCount() + 1)
│          └── courseService.update(course)
│
└─ 返回 "success"（支付宝收到后停止重复回调）
```

> ⚠ **双重自增 BUG**：`buyCount` 被增加了两次 — 步骤5 在 AliPayController 中 +1，步骤6 在 CoursePurchaseServiceImpl.updateCourseSales 中又 +1。一笔支付导致 buyCount 增加 2。

> ⚠ **二次状态更新**：步骤4 将 status 设为 DONE，步骤6 handlePaymentSuccess 又将 status 设为 DONE（幂等，但冗余）。

### 3.6 退款接口

#### `GET /api/alipay/refund?orderNo=xxx`（⚠ 拦截器排除）

```
请求参数: orderNo (query)
│
┌─ 步骤1: 查询订单
│  └── ordersService.selectByOrderNo(orderNo)
│      → 不存在 → 抛 MyException("未找到订单")
│
┌─ 步骤2: 创建退款请求
│  ├── AlipayTradeRefundRequest
│  ├── bizContent:
│  │   { out_trade_no: orders.orderNo,     ← 商户订单号
│  │     refund_amount: orders.goodsPrice,  ← 退款金额(全额)
│  │     trade_no: orders.payNo,           ← 支付宝交易号
│  │     out_request_no: UUID }            ← 退款请求号
│  └── notifyUrl = aliPayConfig.notifyUrl
│
┌─ 步骤3: 执行退款
│  ├── alipayClient.execute(request)
│  │   → AlipayTradeRefundResponse
│  └── response.isSuccess() → 记录退款成功日志
│
┌─ 步骤4: 更新订单状态
│  ├── 重新查询: ordersService.selectByOrderNo(orderNo)
│  ├── dbOrder.setStatus("REFUND_DONE")
│  └── ordersService.updateById(dbOrder)
│
└─ 返回 Result.success()
```

> ⚠ **无归属校验**：退款接口不验证 userId 是否为订单所有者，任何用户可退任何订单。

> ⚠ **全额退款**：`refund_amount = orders.goodsPrice`，不支持部分退款。

> ⚠ **不删除 my_course**：退款后不删除对应的 my_course 记录，用户仍可学习课程。

> ⚠ **GET 方法退款**：违反 HTTP 幂等语义，应使用 POST/PUT。

### 3.7 AI 预下单工具（CourseTools.prePlaceOrder）

```
Spring AI ToolCallback，由 AI 对话流自动调用
│
┌─ 步骤1: 解析用户ID
│  ├── 从 ToolContext 获取 conversationId
│  ├── conversationId 格式: "{userId}_{sessionId}"
│  └── parseUserIdFromConversationId() → userId
│
┌─ 步骤2: 创建订单
│  └── coursePurchaseService.purchaseCourse(userId, courseId)
│
┌─ 步骤3: 返回 OrderInfo

```

## 四、订单状态生命周期

> 订单状态体系详见 [公共参考-订单状态体系](../公共参考/公共数据模型与基础配置.md#一订单状态体系)

### 本模块状态流转触发点

| 转换 | 触发方式 | 后端处理 |
|---|---|---|
| → NOT_PAY | 创建订单 / AI预下单 | CoursePurchaseService.purchaseCourse |
| NOT_PAY → DONE | 支付宝回调 | AliPayController.payNotify + CoursePurchaseService.handlePaymentSuccess |
| NOT_PAY → CANCEL | 用户取消 | CoursePurchaseService.cancelOrder |
| DONE → REFUND_DONE | 用户退款 | AliPayController.refund |
| DONE → COMMENT_DONE | 用户评价 | CourseCommentController |

### 退款不清理关联数据

| 关联数据 | 退款后处理 | 风险 |
|---|---|---|
| my_course 记录 | ❌ 不删除 | 用户仍可学习已退款课程 |
| course.buyCount | ❌ 不回减 | 课程销量虚高 |
| 支付宝退款 | ✅ 全额退回 | — |

## 五、前后端交互时序

### 标准购买流程

```
前端 CourseDetail.vue
│
├── GET /api/user/course/purchase-status/{courseId}
│   └── 返回 { purchased: false } → 显示"立即购买"
│
├── 用户点击"立即购买" → /orders/checkout/{courseId}
│
│   前端 Checkout.vue
│   ├── GET /api/public/course/{courseId} 或 /api/user/course/{courseId}
│   │   └── 渲染课程信息 + 价格
│   │
│   ├── 用户点击"创建订单"
│   ├── POST /api/user/orders/create-course-order/{courseId}
│   │   → CoursePurchaseService.purchaseCourse
│   │   → 生成订单号 MQXQ_ORDER_xxx
│   │   → INSERT orders (status=NOT_PAY)
│   │   → 返回 OrderVO
│   │
│   └── router.push('/payment/${order.id}')
│
│   前端 Payment.vue
│   ├── GET /api/user/orders/detail/{orderId}
│   │   → 渲染订单信息
│   │
│   ├── 用户点击"立即支付"
│   └── window.location.href = 'http://159.75.11.181:9999/api/alipay/pay?orderNo=xxx'
│       → 全页跳转
│
│   后端 AliPayController.pay()
│   ├── 查询订单 → 构建 AlipayTradePagePayRequest
│   ├── alipayClient.pageExecute(request) → 生成 HTML 表单
│   └── httpResponse.getWriter().write(form) → 浏览器渲染表单
│       → 自动提交到支付宝沙箱收银台
│
│   用户在支付宝完成支付
│
│   支付宝服务器 → POST http://159.75.11.181:9999/api/alipay/notify
│   ├── 读取 trade_status=TRADE_SUCCESS
│   ├── RSA2 验签
│   ├── UPDATE orders SET status='DONE', pay_no=xxx, pay_time=xxx
│   ├── course.buyCount += 1  (第1次)
│   └── CoursePurchaseService.handlePaymentSuccess
│       ├── UPDATE orders SET status='DONE' (第2次, 冗余)
│       ├── INSERT my_course (开通课程)

│

```

## 八、已知问题与风险点

> 跨模块系统级问题见 [公共参考-系统级已知问题与风险清单](../公共参考/系统级已知问题与风险清单.md)，此处仅列本模块独有问题。

| # | 问题 | 严重度 | 说明 |
|---|---|---|---|
| 1 | **buyCount 双重自增** | 高 | AliPayController.payNotify +1，handlePaymentSuccess.updateCourseSales +1，一笔支付 buyCount 增加 2 |
| 2 | **退款无归属校验** | 高 | `/api/alipay/refund` 不验证 userId 是否为订单所有者，任何用户可退任何订单 |
| 3 | **退款不清理 my_course** | 高 | 退款后 my_course 记录不删除，用户仍可学习已退款课程 |
| 4 | **回调端点认证矛盾** | 高 | `/api/alipay/**` 被拦截器排除，但 Controller 有 `@SaCheckRole("用户")`，支付宝回调无法携带用户 token |
| 5 | **OrderDetail 退款未实现** | 中 | `requestRefund()` 仅显示成功提示，未调用 `paymentApi.alipayRefund()`，与 OrderList 不一致 |
| 6 | **无支付状态轮询** | 中 | 支付跳转后无 polling/SSE，用户需手动返回查看订单状态 |
| 7 | **退款用 GET 方法** | 中 | `GET /api/alipay/refund` 违反 HTTP 幂等语义，应 POST/PUT |
| 8 | **全额退款无部分退款** | 中 | `refund_amount = goodsPrice` 固定全额，不支持部分退款 |
| 9 | **硬编码 IP 地址** | 中 | 前端 payment.ts 和后端 returnUrl 均硬编码 `159.75.11.181`，部署需手动改 |
| 10 | **免费课程无快捷路径** | 中 | price=0 课程仍走完整下单/支付流程，无"免费加入"快捷入口 |
| 11 | **二次状态更新** | 低 | payNotify 中先设 DONE，handlePaymentSuccess 又设 DONE（幂等但冗余） |
| 12 | **路由参数命名不一致** | 低 | Payment 路由 `:orderNo` 但代码当数字 `orderId` 使用 |
| 13 | **payOrder stub 未使用** | 低 | `userApi.payOrder()` 无参数，疑似废弃代码 |
| 14 | **统计仅当前页** | 低 | OrderList 统计栏仅计算当前页数据，非全量 |
| 15 | **状态码分散定义** | 低 | 3 个组件 3 套映射表，无集中常量 |
| 16 | **订单号无唯一索引** | 低 | orders 表 `order_no` 无 UNIQUE 约束，高并发下理论可碰撞 |
