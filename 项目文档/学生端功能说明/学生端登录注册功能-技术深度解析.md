# 学生端登录注册功能 — 技术深度解析

## 一、功能概述

学生端登录注册模块是码趣星球在线学习平台的入口级功能，涉及前端（mqxq-front）与后端（mqxq）的完整交互链路。

### 核心功能清单

| 功能 | 前端页面 | 后端端点 | 认证要求 |
|---|---|---|---|
| 图形验证码 | Login / Register | `GET /api/auth/captcha` | 否 |
| 登录 | Login.vue | `POST /api/auth/login` | 否 |
| 注册 | Register.vue | `POST /api/auth/register` | 否 |
| 邮箱验证码发送 | Register / ForgotPassword | `POST /api/auth/send-email-code` | 否 |
| 忘记密码 | ForgotPassword.vue | `POST /api/auth/forgot-password` | 否 |
| 邮箱验证 | VerifyEmail.vue | `POST /api/auth/verify-email` | 否 |
| 修改密码 | ProfileSettings | `POST /api/auth/change-password` | 是 |
| Token 刷新 | 自动 | `POST /api/auth/refresh-token` | 是 |
| 登出 | Navbar | `POST /api/auth/logout` | 是 |

### 技术栈关键点

- **前端**：Vue 3 + Element Plus + Pinia（持久化）+ Axios
- **后端**：Spring Boot 3.2 + Sa-Token 1.38（鉴权）+ MyBatis + Redis + RabbitMQ + BCrypt
- **Token 机制**：Sa-Token simple-uuid 风格，30 天有效期，Cookie 名 `mqxqtoken`

## 二、前端关键逻辑

### 2.1 登录页（Login.vue）

#### 表单字段与校验

| 字段 | 标签 | 校验规则 |
|---|---|---|
| `username` | 学生用户名 | 必填 |
| `password` | 密码 | 必填 + 最少 6 位 |
| `captcha` | 验证码 | 必填 |
| `rememberMe` | 记住我 | 无（仅保存用户名） |

#### 登录流程

```
页面挂载
├── 调用 authApi.getCaptcha() → 获取 captchaImage(base64) + captchaKey
├── 从 localStorage 恢复 rememberedUsername（记住我功能）
│
用户填写表单 → 点击登录
├── el-form.validate() 前端校验
├── 构造 loginData: { username, password, captcha, captchaKey, role:"用户" }
│   └── role 硬编码为 "用户"（学生角色）
├── 调用 authApi.login(loginData) → POST /api/auth/login
│
├── 成功（response.token 存在）
│   ├── 构建 userInfo: { userId, username, nickname, phone, avatar, roles }
│   ├── authStore.setAuth({ token, user, expiresIn })  ← 核心状态写入
│   │   ├── Pinia state 设置（accessToken/userInfo/expiresIn/tokenExpireTime）
│   │   ├── localStorage 设置 "mqxqtoken" + "user"
│   │   ├── Cookie 设置 "mqxqtoken=..." (带过期时间)
│   │   └── Pinia 持久化插件 → localStorage "mqxq-auth"（完整 state 的 JSON）
│   ├── rememberMe → localStorage 存/删 "rememberedUsername"
│   ├── 显示成功弹窗（绿色勾 + "进入学习平台" 按钮）
│   └── 用户点击 → router.push("/")
│
└── 失败
    ├── ElMessage.error 显示错误信息
    ├── 清空验证码输入
    └── 刷新验证码图片
```

### 2.2 注册页（Register.vue）

#### 表单字段与校验

| 字段 | 校验规则 | 说明 |
|---|---|---|
| `username` | 必填 + email 格式 | 邮箱即用户名 |
| `password` | 必填 + 6-20 位 | |
| `confirmPassword` | 必填 + 与 password 一致 | 自定义校验器 |
| `captcha` | 必填 + 长度 4 | 图形验证码 |
| `code` | 必填 + 长度 6 | 邮箱验证码 |
| `userType` | 硬编码 `'USER'` | 无 UI 控件 |

#### 注册流程

```
页面挂载
├── 调用 authApi.getCaptcha() → 获取验证码图片
│
步骤1: 用户输入邮箱 → blur 触发 checkEmail()
├── 调用 authApi.checkEmail(username)
│   └── ⚠ 实际请求 GET /api/auth/check-username（疑似 Bug，应调用专用邮箱检查端点）
│
步骤2: 用户点击 "发送验证码"
├── 检查 username 是否已填写
├── 调用 authApi.sendEmailCode({ username, type:"REGISTER" })
└── 启动 60 秒倒计时，按钮禁用
│
步骤3: 用户填写全部字段 → 点击注册
├── el-form.validate() 全面校验
├── 调用 authApi.register(registerForm)
│   → POST /api/auth/register { username, password, confirmPassword, captcha, captchaKey, code, userType:"USER" }
│
├── 成功 → "注册成功！请登录" → router.push("/auth/login")
└── 失败 → ElMessage.error
```

### 2.3 忘记密码页（ForgotPassword.vue）

#### 表单字段与校验

| 字段 | 校验规则 |
|---|---|
| `username` | 必填 + email 格式 |
| `code` | 必填 + `/^\d{6}$/` |
| `newPassword` | 必填 + 6-20 位 + 必须含字母和数字 `/(?=.*[a-zA-Z])(?=.*\d)/` |
| `confirmPassword` | 必填 + 与 newPassword 一致 |

#### 流程

```
用户输入邮箱 → 点击 "发送验证码"
├── 前端 email 格式校验
├── 调用 authApi.sendEmailCode({ username, type:"RESET_PASSWORD" })
└── 60 秒倒计时（onUnmounted 清理 timer）

用户填写验证码 + 新密码 → 点击 "重置密码"
├── el-form.validate()
├── 调用 authApi.forgotPassword({ username, code, newPassword, confirmPassword })
├── 成功 → resetSuccess=true，绿色勾 + "前往登录" 按钮
└── 失败 → ElMessage.error（提取 error.response?.data?.message）
```

### 2.4 邮箱验证页（VerifyEmail.vue）

四种 UI 状态：`verifying`（加载中）/ `verifySuccess`（成功）/ `verifyFailed`（失败）/ 默认（等待验证）

```
页面挂载 → 读取 route.query.token 和 route.query.email
│
├── token 存在
│   ├── 调用 authApi.verifyEmail(token) → POST /api/auth/verify-email { token }
│   ├── 成功 → verifySuccess（绿色勾 + "前往登录"）
│   └── 失败 → verifyFailed（红色叉 + 重新发送 + 返回登录）
│
├── 无 token + 有 email → 等待状态
│   ├── "重新发送验证邮件" → POST /api/auth/resend-verification-email { email }
│   └── "我已验证" → GET /api/auth/check-email-verification-status?email=...
│       ├── verified=true → verifySuccess
│       └── verified=false → 提示未验证
│
└── 无 token + 无 email → 错误提示 + 跳转注册页
```

### 2.5 Auth Store（store/modules/auth.ts）

#### State 结构

```typescript
accessToken: string | undefined
userInfo: any
expiresIn: number | undefined        // 默认 86400（24小时）
tokenExpireTime: number | undefined   // Date.now() + expiresIn * 1000
```

#### 持久化策略

Pinia 使用 `pinia-plugin-persistedstate`，key 为 `mqxq-auth`，自动序列化完整 state 到 localStorage。

**Token 四重存储**：

| 存储位置 | Key | 内容 |
|---|---|---|
| Pinia 内存 | state.accessToken | 原始 token |
| localStorage | `mqxq-auth` | 完整 state JSON（持久化插件） |
| localStorage | `mqxqtoken` | 原始 token 字符串 |
| Cookie | `mqxqtoken` | 原始 token 字符串（带过期时间） |

**Token 读取优先级**（请求拦截器）：localStorage `mqxqtoken` → Pinia `accessToken`

#### 核心 Actions

| Action | 功能 |
|---|---|
| `setAuth({token, user, expiresIn})` | 登录后核心写入：Pinia + localStorage + Cookie 三路设置 |
| `resetLoginState()` | 清空 Pinia state + 删除 localStorage 三 key（⚠ 不清 Cookie） |
| `logout()` | POST `/api/auth/logout` → resetLoginState() → 跳转登录页 |
| `initAuth()` | 启动时从 localStorage 恢复 token + 调 API 校验有效性 |
| `refreshToken()` | POST `/api/auth/refresh-token` → setToken() 更新 |
| `isTokenExpiringSoon()` | 判断 tokenExpireTime - now < 30 分钟 |

### 2.6 HTTP 拦截器（utils/http/interceptors.ts）

#### 请求拦截器 — Token 注入

**免 Token 白名单**：`/api/auth/login`、`/api/auth/register`、`/api/auth/check-username`、`/api/auth/send-email-code`、`/api/file/upload`、`/api/public/`

**Token 注入方式**（同时设置 4 个请求头）：

```typescript
config.headers['satoken'] = accessToken       // Sa-Token 框架头
config.headers['token'] = accessToken         // 通用 token 头
config.headers['mqxqtoken'] = accessToken      // 应用自定义头
config.headers.Authorization = `Bearer ${accessToken}`  // 标准 Bearer
```

多头部注入确保后端 Sa-Token 从任意位置均可识别 token。

#### 响应拦截器 — 401 处理

```
收到 401/4004 响应
├── authStore.resetLoginState()（清空 Pinia + localStorage）
├── 捕获当前路径
├── router.push({ name:'Login', query:{ redirect: currentPath } })
└── 返回 rejected promise { isAuthError:true }

⚠ 无自动 Token 刷新：401 直接登出，不尝试 refreshToken()
```

### 2.7 路由守卫（router/index.ts）

```typescript
router.beforeEach((to, _from, next) => {
  const authStore = useAuthStore()

  // 1. 设置页面标题
  if (to.meta.title) document.title = `${to.meta.title} - 码趣星球在线学习平台`

  // 2. requiresAuth: 未登录跳转登录页（带 redirect）
  if (to.meta.requiresAuth && !authStore.isAuthenticated) {
    next({ name: 'Login', query: { redirect: to.fullPath } })
    return
  }

  // 3. requiresGuest: 已登录跳转首页（防止访问登录/注册页）
  if (to.meta.requiresGuest && authStore.isAuthenticated) {
    next({ name: 'Home' })
    return
  }

  next()
})
```

| 路由 Meta | 效果 | 适用页面 |
|---|---|---|
| `requiresAuth: true` | 未登录 → 跳转登录 | 学习/作业/订单/支付/个人中心/聊天 |
| `requiresGuest: true` | 已登录 → 跳转首页 | 登录/注册/忘记密码 |
| 无标记 | 无限制 | 首页/课程列表/课程详情/公告/邮箱验证 |

## 三、后端执行流程

### 3.1 整体架构

```
Controller: CompleteUnifiedAuthController
    ↓
Service 接口: UnifiedAuthService
    ↓
Service 实现: UnifiedAuthServiceImpl (薄委托层)
    ↓
增强 Service: UnifiedAuthServiceEnhanced (实际业务逻辑)
    ↓
├── UserDao / UserRoleDao        (MyBatis 数据访问)
├── RedisUtil                     (验证码/限频/临时数据)
├── EmailUtils / RabbitMqHelper   (邮件发送)
├── SaUtil                        (BCrypt 加密 + Sa-Token 操作)
└── LoginSecurityManager          (IP 锁定 — ⚠ 当前未接入)
```

**注意**：`LoginStrategy`（策略模式：StudentLoginStrategy / TeacherLoginStrategy / AdminLoginStrategy）已定义但**未被当前登录流程调用**，角色校验在 `UnifiedAuthServiceEnhanced.login()` 中内联实现。

### 3.2 Sa-Token 认证架构

Sa-Token 认证架构详见[认证系统指南](../公共参考/认证系统指南.md)。

### 3.3 图形验证码

#### 生成流程（`GET /api/auth/captcha`）

```
Kaptcha 生成器
├── CaptchaTextCreator 生成数学运算题
│   └── 格式: "3+5=?@8"（表达式@答案）
├── 图片: 160×40px，蓝色文字，阴影扭曲
├── Redis 存储: key="login_captcha:{UUID}", value="8"(答案), TTL=300s
└── 返回 CaptchaResponse: { captchaKey=UUID, captchaImage="data:image/jpeg;base64,...", expiresIn=300 }
```

#### 验证流程（登录/注册共用 `validateCaptcha`）

```
输入验证码 captcha + captchaKey
├── Redis 读取: key="login_captcha:{captchaKey}"
├── 空值 → "验证码不能为空"
├── null  → "验证码已过期"
├── 不匹配 → "验证码错误"（equalsIgnoreCase 忽略大小写）
├── 匹配 → 删除 Redis key（一次性使用）
└── 继续后续流程
```

### 3.4 登录执行流程（`POST /api/auth/login`）

```
请求体: { username, password, captcha, captchaKey, role:"用户" }
│
┌─ 步骤1: 验证图形验证码
│  └── validateCaptcha(captcha, captchaKey) → Redis 校验 + 删除
│
┌─ 步骤2: 查找用户
│  ├── userDao.selectByUsername(username)
│  │   SQL: SELECT * FROM user WHERE username = #{username} LIMIT 1
│  └── null → 抛出 "用户名错误"
│
┌─ 步骤3: 校验密码
│  ├── SaUtil.isBc(password, user.getPassword())
│  │   内部: BCrypt.checkpw(oriPassword, encode)
│  └── 不匹配 → 抛出 "密码错误"
│
┌─ 步骤4: 检查账户状态
│  ├── user.getStatus() == 0 → 抛出 "账户已被禁用"
│  └── status=1 为正常
│
┌─ 步骤5: 校验角色权限
│  ├── userService.getUserRoleNames(user.getId())
│  │   SQL: SELECT r.role_name FROM user_role ur
│  │        LEFT JOIN role r ON ur.role_id = r.id
│  │        WHERE ur.user_id = #{userId}
│  ├── roles.contains(request.getRole()) → 校验通过
│  └── 不包含 → 抛出 "无权限访问"
│
┌─ 步骤6: 执行 Sa-Token 登录
│  ├── StpUtil.login(user.getId())
│  │   → 生成 simple-uuid token
│  │   → 写入 Sa-Token 会话存储（Redis/内存）
│  │   → is-concurrent:false → 踢掉旧会话
│  │   → is-share:true → 同账号共享 token
│  └── tokenValue = StpUtil.getTokenValue()
│
┌─ 步骤7: 构建响应
│  ├── LoginResponse {
│  │     userId, username, nickname(=name), phone, avatar,
│  │     token = tokenValue,
│  │     expiresIn = StpUtil.getTokenTimeout(),
│  │     roles = 角色名列表
│  │   }
│  └── 更新 user.updateTime = new Date()
│
└─ 返回 Result.success(loginResponse)
```

### 3.5 注册执行流程（`POST /api/auth/register`）

```
请求体: { username(email), password, confirmPassword, captcha, captchaKey, code, userType:"USER" }
│
┌─ 步骤1: 校验密码一致性
│  └── password.equals(confirmPassword) → 不一致抛异常
│
┌─ 步骤2: 验证图形验证码
│  └── validateCaptcha(captcha, captchaKey) → Redis 校验 + 删除
│
┌─ 步骤3: 验证邮箱验证码
│  ├── Redis key: "code:REGISTER:{username}"
│  ├── 精确匹配（区分大小写）code.trim().equals(storedCode)
│  └── 不匹配 → "验证码已过期" / "验证码错误"
│
┌─ 步骤4: 检查用户名可用性
│  ├── userDao.selectByUsername(username)
│  └── 已存在 → 抛出 "用户名已被使用"
│
┌─ 步骤5: 创建用户实体
│  ├── password = SaUtil.toBcPassword(password)
│  │          → BCrypt.hashpw(password, BCrypt.gensalt())
│  ├── name = 邮箱前缀(@之前) 或 "用户"（为空时）
│  ├── username = 邮箱地址
│  ├── status = 1（启用）
│  ├── avatar = 默认头像（从配置读取 noFoundPath）
│  └── createTime / updateTime = new Date()
│
┌─ 步骤6: 插入用户
│  ├── userDao.insert(user)
│  └── useGeneratedKeys=true → user.getId() 自动回填
│
┌─ 步骤7: 分配角色
│  ├── userType="USER" → roleCode="USER"
│  ├── 其他 → roleCode="TEACHER"
│  ├── roleService.getRoleEntityByCode(roleCode) → 查找角色
│  ├── 创建 UserRole { userId, roleId, timestamps }
│  ├── userRoleDao.insert(userRole)
│  └── ⚠ 角色分配失败仅记录日志，不回滚注册（用户可能无角色）
│
┌─ 步骤8: 清理验证码
│  └── redisUtil.delete("code:REGISTER:" + username)
│
└─ 返回 Result.success("注册成功")
```

### 3.6 邮箱验证码发送（`POST /api/auth/send-email-code`）

```
请求体: { username, type:"REGISTER"|"RESET_PASSWORD"|"BIND_EMAIL" }
│
┌─ 步骤1: 按类型预校验
│  ├── REGISTER: 检查用户名未注册（已存在 → "该用户名已被注册"）
│  ├── RESET_PASSWORD: 检查用户名已注册（不存在 → "该用户名未注册"）
│  └── BIND_EMAIL: 无预校验
│
┌─ 步骤2: 发送频率限制
│  ├── Redis key: "send_limit:{username}"
│  ├── 存在 → "验证码发送过于频繁，请60秒后再试"
│  └── 不存在 → 设置 key，TTL=60s
│
┌─ 步骤3: 生成验证码
│  ├── 6位随机数: String.format("%06d", new Random().nextInt(999999))
│  └── Redis 存储: key="code:{TYPE}:{username}", value=code, TTL=300s
│
┌─ 步骤4: 发送邮件（双通道）
│  ├── 主通道: RabbitMQ → mqxq.email 队列 → routing key "sendCode"
│  │   消息体: SendCodeDto(receiver, code, subject, content)
│  └── 降级通道: MQ 失败时 → threadPoolTaskExecutor 异步调用
│       emailUtils.sendSimpleMail(to, subject, content)
│
└─ 邮件主题: "码趣星球 - 注册验证码" / "密码重置验证码" / "绑定邮箱验证码"
```

### 3.7 忘记密码（`POST /api/auth/forgot-password`）

```
请求体: { username, code, newPassword, confirmPassword }
│
┌─ 步骤1: 校验密码一致性
│
┌─ 步骤2: 验证邮箱验证码
│  └── validateCode(username, code, "RESET_PASSWORD")
│      Redis key: "code:RESET_PASSWORD:{username}"
│
┌─ 步骤3: 查找用户
│  └── userDao.selectByUsername(username)
│
┌─ 步骤4: 更新密码
│  ├── SaUtil.toBcPassword(newPassword) → BCrypt 加密
│  └── userDao.updatePassword(user)
│
┌─ 步骤5: 清理验证码
│  └── redisUtil.delete("code:RESET_PASSWORD:" + username)
│
└─ 返回 Result.success("密码重置成功")
    ⚠ 不自动登录，用户需重新登录
```

### 3.8 修改密码（`POST /api/auth/change-password`）

```
需认证（Sa-Token 校验）
│
┌─ 步骤1: 校验新密码一致性
│
┌─ 步骤2: 获取当前用户
│  └── StpUtil.getLoginIdAsLong() → userId → userDao.selectById()
│
┌─ 步骤3: 验证旧密码
│  └── SaUtil.isBc(oldPassword, user.getPassword())
│
┌─ 步骤4: 更新密码
│  └── BCrypt 加密后更新
│
┌─ 步骤5: 强制登出
│  └── StpUtil.logout() → 销毁当前会话
│
└─ 返回 Result.success("密码修改成功")
```

### 3.9 Token 刷新（`POST /api/auth/refresh-token`）

```
需认证
│
├── StpUtil.renewTimeout(StpUtil.getTokenTimeout())
│   → 以当前剩余超时时间重设 token 有效期
│   ⚠ 由于 active-timeout=-1，此操作实际效果有限
│   → 如需刷新到完整 30 天，应调用 renewTimeout(2592000)
│
└── 返回 getCurrentUserInfo() → LoginResponse（含当前 token + expiresIn）
```

### 3.10 登出（`POST /api/auth/logout`）

```
需认证
│
├── StpUtil.logout()
│   → 销毁 Sa-Token 会话
│   → 清除服务端 token 记录
│
└── 返回 Result.success("退出成功")
    前端随后调用 resetLoginState() 清除本地存储
```

## 四、数据库交互

### 4.1 核心表结构

> 数据库表结构详见 [数据库表结构汇总](../../公共参考/数据库表结构汇总.md)（user / role / user_role）

### 4.2 关键 SQL

```sql
-- 按用户名查找用户
SELECT * FROM user WHERE username = #{username} LIMIT 1

-- 查询用户角色名列表
SELECT r.role_name FROM user_role ur
LEFT JOIN role r ON ur.role_id = r.id
WHERE ur.user_id = #{userId}

-- 按角色编码查找角色
SELECT * FROM role WHERE role_code = #{roleCode} LIMIT 1
```

### 4.3 Redis 键值一览

| Key 模式 | TTL | 用途 |
|---|---|---|
| `login_captcha:{UUID}` | 300s | 图形验证码答案 |
| `code:{TYPE}:{username}` | 300s | 邮箱验证码（TYPE=REGISTER/RESET_PASSWORD/BIND_EMAIL） |
| `send_limit:{username}` | 60s | 邮件发送频率限制 |
| `login_fail_limit:{ip}` | 1800s | 登录失败计数（⚠ LoginSecurityManager 未接入） |
| Sa-Token 内部 keys | 2592000s | Sa-Token 会话存储（由框架管理） |

## 五、已知问题与风险点

> 跨模块系统级问题见 [公共参考-系统级已知问题与风险清单](../../公共参考/系统级已知问题与风险清单.md)，此处仅列本模块独有问题。

| # | 问题 | 严重度 | 说明 |
|---|---|---|---|
| 1 | **LoginSecurityManager 未接入** | 高 | IP 锁定/暴力破解防护已实现但未调用，登录无频率限制 |
| 2 | **LoginStrategy 策略模式未使用** | 低 | 角色校验内联实现，策略类闲置 |
| 3 | **前端 checkEmail 调用错误端点** | 中 | `authApi.checkEmail()` 实际请求 `/api/auth/check-username`，非专用邮箱检查 |
| 4 | **登出不清 Cookie** | 中 | `resetLoginState()` 删除 localStorage 但不清 `mqxqtoken` Cookie |
| 5 | **前端无自动 Token 刷新** | 中 | 401 直接登出，不尝试 `refreshToken()` |
| 6 | **Token 刷新近乎空操作** | 低 | `renewTimeout(getTokenTimeout())` 重设为当前剩余时间，未延长 |
| 7 | **注册角色分配非原子** | 中 | 角色分配失败仅记日志，用户注册成功但可能无角色 |
| 8 | **Token 四重存储冗余** | 低 | Pinia + localStorage(mqxq-auth) + localStorage(mqxqtoken) + Cookie |
| 9 | **邮箱验证码区分大小写** | 低 | `validateCode` 精确匹配 vs 图形验证码 `equalsIgnoreCase` |
| 10 | **验证码随机范围偏移** | 低 | `nextInt(999999)` 范围 [0,999999)，永远不产生 999999 |
