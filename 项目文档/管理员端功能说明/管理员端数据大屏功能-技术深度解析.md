# 管理员端数据大屏功能 — 技术深度解析

## 一、功能概述

管理员端数据大屏模块是管理员登录后的**默认首页**（`path: '/'`），提供平台级核心指标概览、13张 ECharts 图表（饼图×6 + 折线图×4 + 柱状图×3），以及"统计仪表板"数字指标页面。管理员端与教师端共用同一个 `DashboardServiceImpl`，但管理员端看全平台数据，教师端仅看个人课程数据。

### 管理员端 vs 教师端大屏对比

| 对比维度 | 管理员端 | 教师端 |
|---|---|---|
| 基础路径 | `/api/admin/dashboard` | `/api/teacher/dashboard` |
| 角色校验 | `@SaCheckRole("管理员")` | `@SaCheckRole("教师")` |
| 概览VO | `AdminDashboardOverviewVO`（23字段） | `TeacherDashboardOverviewVO`（20字段） |
| 数据范围 | **全平台** | **仅当前教师课程** |
| 身份获取 | 不需要取当前用户ID | 通过 `SaUtil.getLoginId()` 取 teacherId |
| 饼图数量 | 6 | 2 |
| 折线图数量 | 4 | 3 |
| 柱状图数量 | 3 | 2 |
| 端点总数 | 14 | 8 |
| SQL聚合 | 仅 `getTotalRevenue()` | 3个端点走SQL聚合 |
| 内存聚合 | **大量全量加载+Stream** | 同样大量，但略好 |

#### ECharts 图表配置

使用 **ECharts 5.6.0 + vue-echarts 7.0.3**，按需引入，与教师端注册方式完全一致。

三种图表工厂函数：

| 工厂函数 | 图表类型 | 关键配置 |
|---|---|---|
| `createPieOption` | 饼图 | `radius: '50%'`，左侧垂直图例，emphasis shadowBlur |
| `createLineOption` | 折线图 | `smooth: true`，`areaStyle: {}`（面积填充），支持自定义 formatter |
| `createBarOption` | 横向柱状图 | Y轴类别名，X轴数值，柱上 label，金额加 `¥` 前缀 |

每个图表容器高度固定 400px，使用 `autoresize` 自适应。数据为空时显示 `<n-empty description="暂无数据" />`。

#### ⚠ 客户端二次计算

- **用户统计**：遍历 API 返回数组，按 `userTypeCode`（ADMIN/TEACHER/USER）累加到对应分类
- **收入统计**：与订单统计共用同一接口 `/api/admin/orders/statistics`，从 `recentOrders` 数组中筛选 `status === 'DONE'` 累加 `goodsPrice`，计算 `totalOrderValue / recentOrdersCount` 得平均金额

### 3.3 概览（`GET /api/admin/dashboard/overview`）

```
│
┌─ Sa-Token 校验: @SaCheckRole("管理员")
│
┌─ 步骤1: 用户统计（⚠ 全量查询 + Java过滤）
│  ├── userDao.queryAllByLimit(new User()) → .size() 得 totalUsers
│  ├── userRoleDao.queryAllByLimit(new UserRole()) → Java Stream groupingBy(roleId)
│  │   ├── 硬编码: roleId=2 → 教师数 (totalTeachers)
│  │   └── 硬编码: roleId=3 → 学员数 (totalStudents)
│  └── 今日新增: 遍历用户列表，Calendar 取今天 00:00:00，createTime.after(todayStart)
│
┌─ 步骤2: 课程统计（⚠ 全量查询 + Java过滤）
│  ├── courseDao.queryAllByLimit(new Course()) → .size() 得 totalCourses
│  └── status==1 → publishedCourses
│
┌─ 步骤3: 订单统计（⚠ 全量查询 + Java过滤）
│  ├── ordersDao.queryAllByLimit(new Orders()) → .size() 得 totalOrders
│  ├── "DONE".equals(o.getStatus()) → completedOrders
│  └── 今日新增: 遍历订单列表，解析 createTime（支持两种日期格式）
│
┌─ 步骤4: 收入统计
│  ├── ordersDao.getTotalRevenue()  ✅ 唯一SQL聚合
│  │   SQL: SELECT COALESCE(SUM(goods_price), 0) FROM orders WHERE status='DONE'
│  └── calculateAdminTodayRevenue()  ⚠ 内存过滤（遍历全量订单）
│
┌─ 步骤5: 学习统计（⚠ 全量查询 + Java过滤）
│  ├── myCourseDao.queryAllByLimit(new MyCourse())
│  ├── status==1 → studyingRecords, status==2 → completedRecords
│  └── completionRate = completedRecords / totalLearningRecords * 100
│
┌─ 步骤6: 浏览统计（⚠ 全量查询 + Java过滤）
│  ├── courseViewDao.queryAllByLimit(new CourseView())
│   ├── .size() → totalViews
│   └── userId 去重 → uniqueVisitors
│
┌─ 步骤7: 内容统计（⚠ 6次全量查询）
│  ├── courseHomeworkDao.queryAllByLimit → totalHomeworks
│  ├── homeworkSubmissionDao.queryAllByLimit → totalSubmissions
│  ├── courseCommentDao.queryAllByLimit → totalComments
│  ├── announcementsDao.queryAllByLimit → totalAnnouncements
│  ├── chapterDao.queryAllByLimit → totalChapters
│  └── sectionDao.queryAllByLimit → totalSections
```

## 五、已知问题与风险点

> 跨模块系统级问题见 [公共参考-系统级已知问题与风险清单](../../公共参考/系统级已知问题与风险清单.md)，此处仅列本模块独有问题。

| # | 问题 | 严重度 | 说明 |
|---|---|---|---|
| 1 | **概览一次查8+张表** | 极高 | `getAdminOverview()` 一次调用全量查 user/user_role/course/orders/my_course/course_view/course_homework/homework_submission/course_comment/announcements/chapter/section 共12张表，几乎将核心业务数据全部加载到JVM |
| 2 | **教师收入排行N+1查询** | 高 | `getAdminTopTeachers()` 对每个教师循环调用 `getRevenueByTeacherId()` + `courseDao`，教师数多时极慢 |
| 3 | **roleId硬编码** | 高 | 角色统计硬编码 roleId=2 为教师、roleId=3 为学员，若角色表结构调整即失效，应通过 role_name 动态查找 |
| 4 | **订单状态硬编码映射** | 中 | 订单状态分布中5种状态名硬编码在Java中（CANCEL→已取消等），与数据库无关联，新增状态需改代码 |
| 5 | **管理员端无专属SQL** | 中 | 所有管理员端查询复用通用 `queryAllByLimit` 方法，无针对管理员统计场景的聚合SQL，导致只能全量加载 |
| 6 | **统计仪表板收入客户端计算** | 中 | 收入统计与订单统计共用同一API，前端从 `recentOrders` 数组筛选DONE状态累加，应在后端完成 |
| 7 | **统计仪表板用户统计客户端分组** | 中 | 用户统计按 `userTypeCode` 在前端累加，后端应直接返回分类计数 |
| 8 | **两套独立统计体系** | 低 | 同时存在"数据大屏"（dashboard，14端点）和"统计仪表板"（statistics，11端点），数据范围和口径可能不一致 |
| 9 | **日期填充逻辑重复** | 低 | 管理员端和教师端大屏的趋势数据日期填充代码几乎相同，可抽取为公共函数 |
| 10 | **默认首页冗余** | 低 | `home/index.vue`（模板演示页，硬编码数据）已无角色使用但仍保留 |
| 11 | **无慢查询保护** | 低 | 全量查询无 LIMIT 保护，极端情况下可能返回百万级数据导致OOM |
| 12 | **概览接口响应过重** | 低 | 单个 `/overview` 返回23个字段，内部涉及12次全量DAO查询，应拆分为多个轻量端点或异步加载 |
| 13 | **课程创建趋势有日期补零但其他趋势没有** | 低 | `getAdminCourseCreationTrend` 初始化所有日期为0（确保无数据日期也返回），但其他3个趋势端点不做此处理，前端依赖日期填充兜底 |
