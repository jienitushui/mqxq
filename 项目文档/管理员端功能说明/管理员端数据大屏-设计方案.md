# 管理员端数据大屏设计方案

## 一、核心指标卡片（顶部展示）

### 1.1 平台整体指标
- **总用户数**：`COUNT(user)`
- **总教师数**：`COUNT(user INNER JOIN user_role WHERE role_id = 2)`
- **总学员数**：`COUNT(user INNER JOIN user_role WHERE role_id = 3)`
- **总课程数**：`COUNT(course)`
- **已发布课程数**：`COUNT(course WHERE status = 1)`
- **总订单数**：`COUNT(orders)`
- **已完成订单数**：`COUNT(orders WHERE status = 'DONE')`
- **平台总收入**：`SUM(orders.goods_price WHERE status = 'DONE')`
- **今日新增用户**：`COUNT(user WHERE DATE(create_time) = CURDATE())`
- **今日新增订单**：`COUNT(orders WHERE DATE(create_time) = CURDATE())`
- **今日收入**：`SUM(orders.goods_price WHERE status = 'DONE' AND DATE(pay_time) = CURDATE())`

### 1.2 学习相关指标
- **总学习记录数**：`COUNT(my_course)`
- **学习中记录数**：`COUNT(my_course WHERE status = 1)`
- **已完成记录数**：`COUNT(my_course WHERE status = 2)`
- **课程完成率**：`已完成记录数 / 总学习记录数 * 100%`
- **总浏览量**：`COUNT(course_view)`
- **独立访客数**：`COUNT(DISTINCT course_view.user_id)`

### 1.3 内容相关指标
- **总作业数**：`COUNT(course_homework)`
- **总作业提交数**：`COUNT(homework_submission)`
- **总评论数**：`COUNT(course_comment)`
- **总公告数**：`COUNT(announcements)`
- **总章节数**：`COUNT(chapter)`
- **总小节数**：`COUNT(section)`

## 四、后端接口设计

### 管理员端接口（设计方案）
```
GET /api/admin/dashboard/overview             # 平台核心指标概览
GET /api/admin/dashboard/user-stats           # 用户统计数据
GET /api/admin/dashboard/course-stats         # 课程统计数据
GET /api/admin/dashboard/order-stats          # 订单统计数据
GET /api/admin/dashboard/learning-stats        # 学习统计数据
GET /api/admin/dashboard/revenue-stats         # 收入统计数据
GET /api/admin/dashboard/trends                # 趋势数据（支持日期范围）
GET /api/admin/dashboard/top-teachers          # 教师收入排行
GET /api/admin/dashboard/top-courses           # 热门课程排行
```

> **实际实现与设计方案的差异**：最终实现将上述粗粒度接口拆分为 14 个细粒度端点，详见 [管理员端数据大屏功能-技术深度解析](./管理员端数据大屏功能-技术深度解析.md#三后端执行流程)。主要变化：
> - `user-stats` → 拆分为 `/user-role-distribution` + `/user-status-distribution` + `/user-registration-trend`
> - `course-stats` → 拆分为 `/course-category-distribution` + `/course-status-distribution` + `/course-creation-trend`
> - `order-stats` → 拆分为 `/order-status-distribution` + `/order-count-trend` + `/order-revenue-trend`
> - `learning-stats` → 独立为 `/learning-status-distribution`
> - `revenue-stats` → 并入 overview（totalRevenue 字段）
> - `trends` → 拆分为 4 个独立趋势端点（用户注册/订单金额/订单数量/课程创建）
> - `top-courses` → 拆分为 `/top-courses-by-views` + `/top-courses-by-revenue`

## 五、数据库查询示例

### 1. 用户角色分布
```sql
SELECT
    r.role_name,
    COUNT(ur.user_id) AS count
FROM user_role ur
INNER JOIN role r ON ur.role_id = r.id
GROUP BY r.id, r.role_name;
```

### 2. 课程分类分布
```sql
SELECT
    cs.name AS categoryName,
    COUNT(c.id) AS courseCount
FROM course c
INNER JOIN course_subject cs ON c.subject_id = cs.id
GROUP BY cs.id, cs.name;
```

### 3. 教师收入排行
```sql
SELECT
    u.id AS teacherId,
    u.name AS teacherName,
    COUNT(DISTINCT c.id) AS courseCount,
    COUNT(DISTINCT mc.user_id) AS studentCount,
    SUM(o.goods_price) AS totalRevenue,
    AVG(cc.score) AS avgRating
FROM user u
INNER JOIN course c ON u.id = c.teacher_id
LEFT JOIN orders o ON c.id = o.goods_id AND o.status = 'DONE'
LEFT JOIN my_course mc ON c.id = mc.course_id
LEFT JOIN course_comment cc ON c.id = cc.course_id
WHERE u.id IN (SELECT user_id FROM user_role WHERE role_id = 2)
GROUP BY u.id, u.name
ORDER BY totalRevenue DESC
LIMIT 10;
```
