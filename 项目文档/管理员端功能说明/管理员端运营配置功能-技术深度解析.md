# 管理员端运营配置功能 - 技术深度解析

> 码趣星球(mqxq)在线教育平台 · 管理员端运营配置模块技术文档
>
> 涵盖范围：轮播图管理、公告管理、公告分类管理

## 一、功能概述

管理员端"运营配置"功能在系统菜单中被归入**"内容管理"**分类（`ContentManagement`），包含三个子模块：

| 子模块 | 菜单Code | 路由路径 | 前端页面 | 说明 |
|--------|----------|---------|---------|------|
| 公告管理 | `PmsAnnouncement` | `/pms/announcement` | `pms/announcement/index.vue` | 公告 CRUD + 发布/撤回 + 批量删除 |
| 公告分类 | `PmsAnnouncementCategory` | `/pms/announcement-category` | `pms/announcement-category/index.vue` | 分类 CRUD + 唯一性校验 |
| 轮播图管理 | `PmsCarousel` | `/pms/carousel` | `pms/carousel/index.vue` | 轮播图 CRUD + 图片上传 + 批量删除 |

**未实现的运营配置模块**：友情链接、广告配置、系统设置/字典配置——项目中无对应前后端代码。

### 涉及的数据库表

| 表名 | 说明 | 记录量级 | 物理删除 | 逻辑删除 |
|------|------|---------|---------|---------|
| `carousel` | 首页轮播图 | 小 (~50) | ✅ DELETE | is_deleted字段(但未使用) |
| `announcements` | 公告详情 | 中 (~1000) | ✅ DELETE | 无 |
| `announcement_categories` | 公告分类 | 小 (~20) | ✅ DELETE | 无 |

### 接口总览

| Controller | 路径前缀 | 鉴权 | 接口数 |
|-----------|---------|------|-------|
| CarouselController | `/api/admin/carousel` | `@SaCheckRole("管理员")` | 6 |
| AnnouncementsController | `/api/admin/announcements` | `@SaCheckRole("管理员")` | 8 |
| AnnouncementCategoriesController | `/api/admin/announcement-categories` | `@SaCheckRole("管理员")` | 6 |
| CarouselPublicController | `/api/public/carousel` | 无（免登录） | 3 |
| AnnouncementsPublicController | `/api/public/announcements` | `@SaCheckRole("用户")` | 5 |
| AnnouncementCategoriesPublicController | `/api/public/announcement-categories` | `@SaCheckRole("用户")` | 2 |

## 二、前端关键逻辑

### 2.1 路由与权限

运营配置的三个子模块路由均通过 `settings.js` 中的 `adminPermissions` 动态注入，教师角色(`teacherPermissions`)不包含这些菜单。

**`src/settings.js` 菜单定义**（第211-253行）：
```js
{
  code: 'ContentManagement',
  name: '内容管理',
  type: 'MENU',
  icon: 'i-carbon:content-delivery-network',
  order: 3,
  children: [
    { code: 'PmsAnnouncement', name: '公告管理', path: '/pms/announcement',
      component: '/src/views/pms/announcement/index.vue' },
    { code: 'PmsAnnouncementCategory', name: '公告分类', path: '/pms/announcement-category',
      component: '/src/views/pms/announcement-category/index.vue' },
    { code: 'PmsCarousel', name: '轮播图管理', path: '/pms/carousel',
      component: '/src/views/pms/carousel/index.vue' },
  ],
}
```

权限分发逻辑（`src/store/helper.js`）：`role === '管理员'` → `adminPermissions`（含内容管理），`role === '教师'` → `teacherPermissions`（不含）。

### 2.2 轮播图管理页面

**文件**：`vue-naive-admin/src/views/pms/carousel/index.vue`（约773行）

#### 页面结构

- **搜索区域**：按"图片地址"/"链接地址"搜索 + 搜索/重置按钮
- **数据表格**：`n-data-table` 远程分页，列：选择框、ID、图片预览（缩略图）、图片地址（可点击新窗口打开）、链接地址（可点击打开）、排序值（可排序）、创建时间、操作（查看/编辑/删除）
- **批量操作**：批量删除按钮（需勾选行）
- **新增/编辑弹窗**（800px）：
  - 图片上传（`n-upload`，action=`/api/public/files/image`，限1张，PNG/JPG/JPEG/GIF/WebP，建议尺寸 1920×600，最大 5MB）
  - 手动输入图片地址（备选方式）
  - 链接地址（可选）
  - 排序值（0-9999，`n-input-number`）
  - 实时图片预览
- **查看详情弹窗**（700px）：展示全部字段 + 图片预览

#### 核心状态与函数

```js
// 表单数据
const formData = ref({ id: null, carouselUrl: '', linkUrl: '', sort: 0 })

// 表单验证规则
const formRules = {
  carouselUrl: [
    { required: true, message: '请输入图片地址', trigger: 'blur' },
    { pattern: /^https?:\/\/.+\.(jpg|jpeg|png|gif|webp)$/i, message: '请输入有效的图片地址', trigger: 'blur' }
  ],
  sort: [
    { required: true, message: '请输入排序值', trigger: 'blur', type: 'number' },
    { type: 'number', min: 0, max: 9999, message: '排序值必须在0-9999之间', trigger: 'blur' }
  ]
}

// 关键函数
loadData()          // 加载分页数据 → api.getList(params)
handleCreate()      // 新增 → api.create(data)
handleUpdate()      // 编辑 → api.update(id, data)
handleDelete(id)    // 单条删除 → api.delete(id)
handleBatchDelete() // 批量删除 → api.batchDelete(selectedIds)
handleView(row)     // 查看详情 → api.getDetail(id)
handleSearch()      // 搜索 → 重置页码后 loadData()
handleReset()       // 重置 → 清空搜索条件后 loadData()
```

#### API封装

**文件**：`vue-naive-admin/src/views/pms/carousel/api.js`

```js

export default {

```

> **注意**：前端定义了 `batchDelete` API，但后端 `CarouselController` 中**没有对应的批量删除接口**，调用会返回 404。

### 2.3 公告管理页面

**文件**：`vue-naive-admin/src/views/pms/announcement/index.vue`（约729行）

#### 页面结构

- **搜索区域**：按"公告标题"搜索 + 按"分类"下拉筛选
- **数据表格**：`n-data-table` 远程分页，列：选择框、ID、公告标题、分类名称（根据 categoryId 匹配）、发布时间、创建时间、操作（查看/编辑/删除）
- **批量操作**：批量删除按钮
- **查看详情弹窗**（700px）：标题、分类名称、发布时间、创建时间、内容（灰色背景框内展示）
- **新增/编辑弹窗**（800px）：
  - 公告标题（文本输入）
  - 公告分类（下拉选择，`n-select` filterable，从 `/api/admin/announcement-categories/all` 加载）
  - 公告内容（`n-input` type=textarea，8行）
  - 发布时间（`n-date-picker`，datetime 类型）

#### 核心状态与函数

```js
// 表单数据
const formData = ref({
  id: null, categoryId: undefined, title: '', content: '', publishDate: null
})

// 分类选项
const categoryOptions = ref([])   // 从 api.getCategories() 加载

// 表单验证规则
const formRules = {
  title: [
    { required: true, message: '请输入公告标题', trigger: 'blur' },
    { max: 255, message: '标题长度不能超过255个字符', trigger: 'blur' }
  ],
  categoryId: [
    { required: true, message: '请选择公告分类', trigger: ['change', 'blur'],
      validator: (rule, value) => {
        if (!value && value !== 0) return new Error('请选择公告分类')
        return true
      }
    }
  ],
  content: [
    { required: true, message: '请输入公告内容', trigger: 'blur' }
  ]
}

// 提交前数据格式化
// publishDate: ISO字符串截取前19位 → "2025-01-07 15:30:00"
// categoryId:  强制转为 Number 类型
```

#### 特殊前端逻辑

1. **分类名称映射**：表格中分类列通过 `categoryId` 在 `categoryOptions` 中查找对应 `label` 显示
2. **编辑时类型强制转换**：`formData.value.categoryId = Number(row.categoryId)`
3. **提交前双重校验**：即便 `formRef.value.validate()` 已通过，仍手动校验必填字段
4. **调试信息残留**：编辑弹窗中有 `console.log('当前categoryId:', ...)` 调试代码

#### API封装

**文件**：`vue-naive-admin/src/views/pms/announcement/api.js`

```js
import { request } from '@/utils'
export default {
  getList:       (params) => request.get('/api/admin/announcements/page', { params }),
  getDetail:     (id) => request.get(`/api/admin/announcements/${id}`),
  create:        (data) => request.post('/api/admin/announcements', data),
  update:        (id, data) => request.put(`/api/admin/announcements/${id}`, data),
  delete:        (id) => request.delete(`/api/admin/announcements/${id}`),
  batchDelete:   (ids) => request.delete('/api/admin/announcements/batch', { data: ids }),
  publish:       (id) => request.put(`/api/admin/announcements/${id}/publish`),
  withdraw:      (id) => request.put(`/api/admin/announcements/${id}/withdraw`),
```

> - 前端 `publish` 使用 `PUT`，后端 `publishAnnouncement` 使用 `POST`
> - 前端 `withdraw` 使用 `PUT`，后端 `withdrawAnnouncement` 使用 `POST`
> - 这两个接口调用时会因 HTTP 方法不匹配返回 405

```js
const formRules = {
```

#### 特殊前端逻辑

1. **删除安全提示**：删除时若后端返回 HTTP 409，显示"该分类下还有公告，无法删除"
   - 但后端 `deleteCategory()` 实际并未检查关联公告（有 TODO 注释），所以 409 永远不会触发
2. **创建唯一性提示**：创建时若后端返回 HTTP 409，显示"分类名称已存在，请使用其他名称"
   - 后端确实在 `createCategory()` 中校验名称唯一性，但抛出的是 `MyException` 而非返回 409 状态码

## 三、后端执行流程

### 3.1 轮播图管理

#### Controller层：CarouselController

**路径**：`com.jieni.mqxq.controller.admin.CarouselController`
**前缀**：`/api/admin/carousel`
**鉴权**：`@SaCheckRole("管理员")`（类级别），所有接口仅管理员可访问
**跨域**：`@CrossOrigin`（其他运营配置 Controller 无此注解）

| # | HTTP方法 | 路径 | 方法名 | 功能 | 入参 | 出参 |
|---|---------|------|--------|------|------|------|
| 1 | POST | `/` | createCarousel | 创建轮播图 | `@Valid CarouselCreateDTO` | `Result<CarouselVO>` |
| 2 | PUT | `/{id}` | updateCarousel | 更新轮播图 | `@PathVariable @Min(1) id` + `@Valid CarouselUpdateDTO` | `Result<CarouselVO>` |
| 3 | GET | `/{id}` | getCarouselById | 查询详情 | `@PathVariable @Min(1) id` | `Result<CarouselVO>` |
| 4 | DELETE | `/{id}` | deleteCarousel | 删除轮播图 | `@PathVariable @Min(1) id` | `Result<Void>` |
| 5 | GET | `/page` | getCarouselsByPage | 分页查询 | `@Valid CarouselPageQueryDTO` | `Result<PageInfo<CarouselVO>>` |
| 6 | GET | `/list` | getAllCarousels | 全量列表 | 无 | `Result<List<CarouselVO>>` |

#### DTO 结构

**CarouselCreateDTO**：
```java
@NotBlank  String carouselUrl    // 图片地址（必填）
           String linkUrl        // 链接地址（可选）
@Min(0)    Integer sort          // 排序值（默认0）
```

**CarouselUpdateDTO**：
```java
           String carouselUrl    // 图片地址
           String linkUrl        // 链接地址
@Min(0)    Integer sort          // 排序值
@Min(0)    Integer isDeleted     // 删除状态（0/1）
```

**CarouselPageQueryDTO**：
```java
@Min(1)    Integer pageNum = 1   // 页码
@Min(1)@Max(100) Integer pageSize = 10  // 每页数量
           Integer isDeleted     // 删除状态筛选
```

#### Service层：CarouselServiceImpl

**路径**：`com.jieni.mqxq.service.impl.content.CarouselServiceImpl`

**创建轮播图** (`createCarousel`)：
```
1. BeanUtils.copyProperties(createDTO, carousel) → DTO转Entity
2. 设置默认值：isDeleted=0, sort默认=0
3. 填充时间：createTime=now, updateTime=now
4. 填充操作人：createUser=SaUtil.getLoginId(), updateUser=同上
5. carouselDao.insert(carousel) → 入库（自增主键回填）
6. convertToVO(carousel) → 返回
```

**更新轮播图** (`updateCarousel`)：
```
1. carouselDao.queryById(id) → 验证存在性
2. BeanUtils.copyProperties(updateDTO, carousel) → 构建更新实体
3. 设置 updateTime=new Date(), updateUser=SaUtil.getLoginId()
4. carouselDao.update(carousel) → 动态SET更新（仅非空字段）
5. getCarouselById(id) → 重新查询返回
```

**删除轮播图** (`deleteCarousel`)：
```
1. carouselDao.queryById(id) → 验证存在性
2. carouselDao.deleteById(id) → 物理删除(DELETE FROM carousel WHERE id=?)
```

**分页查询** (`pageQueryCarousels`)：
```
1. 构建查询条件：默认 isDeleted=0（仅未删除），可按删除状态筛选
2. PageHelper.startPage(pageNum, pageSize)
3. carouselDao.queryAllByLimit(condition) → 排序：sort ASC, create_time DESC
4. PageInfo转换 → BeanUtils.copyProperties + stream().map(convertToVO)
```

**全量列表** (`getAllCarousels`)：
```
1. carouselDao.queryAllByLimit(new Carousel()) → 无条件查询全部
2. stream().map(convertToVO) → 转换返回
```

#### 公共接口：CarouselPublicController

**路径**：`com.jieni.mqxq.controller.publicapi.CarouselPublicController`
**前缀**：`/api/public/carousel`
**鉴权**：无（免登录，WebConfig 排除 `/api/public/**`）

| # | HTTP方法 | 路径 | 方法名 | 功能 |
|---|---------|------|--------|------|
| 1 | GET | `/list` | getEnabledCarouselList | 启用的轮播图（按sort升序） |
| 2 | GET | `/{id}` | getCarouselById | 轮播图详情 |
| 3 | GET | `/homepage` | getHomepageCarousel | 首页轮播图（limit截取） |

**getHomepageCarousel** 业务逻辑：
```
1. 调用 getEnabledCarouselList() → 获取 isDeleted=0 的全部轮播图
2. Java层排序：carousels.sort((c1,c2) -> sort1.compareTo(sort2))  // 升序
3. subList(0, limit) → 截取前 limit 条
```

### 3.2 公告管理

#### Controller层：AnnouncementsController

**路径**：`com.jieni.mqxq.controller.admin.AnnouncementsController`
**前缀**：`/api/admin/announcements`
**鉴权**：`@SaCheckRole("管理员")`（类级别）

| # | HTTP方法 | 路径 | 方法名 | 功能 | 入参 | 出参 |
|---|---------|------|--------|------|------|------|
| 1 | POST | `/` | createAnnouncement | 创建公告 | `@Valid AnnouncementCreateDTO` | `Result<AnnouncementVO>` |
| 2 | PUT | `/{id}` | updateAnnouncement | 更新公告 | `@PathVariable id` + `@Valid AnnouncementUpdateDTO` | `Result<AnnouncementVO>` |
| 3 | DELETE | `/{id}` | deleteAnnouncement | 删除公告 | `@PathVariable id` | `Result<Void>` |
| 4 | GET | `/{id}` | getAnnouncement | 查询详情 | `@PathVariable id` | `Result<AnnouncementVO>` |
| 5 | GET | `/page` | getAnnouncementPage | 分页查询 | `AnnouncementPageQueryDTO` | `Result<PageInfo<AnnouncementSimpleVO>>` |
| 6 | **POST** | `/{id}/publish` | publishAnnouncement | 发布公告 | `@PathVariable id` + `AnnouncementPublishDTO` | `Result<AnnouncementVO>` |
| 7 | **POST** | `/{id}/withdraw` | withdrawAnnouncement | 撤回公告 | `@PathVariable id` | `Result<AnnouncementVO>` |
| 8 | DELETE | `/batch` | batchDeleteAnnouncements | 批量删除 | `@Valid AnnouncementBatchDeleteDTO` | `Result<Void>` |

#### DTO 结构

**AnnouncementCreateDTO**：
```java
@NotNull @Positive  Integer categoryId    // 分类ID（必填）
@NotBlank @Size(1,100)  String title       // 标题（必填，1-100字符）
@NotBlank @Size(1,10000) String content     // 内容（必填，1-10000字符）
                     Date publishDate       // 发布时间（可选，空=草稿）
```

**AnnouncementUpdateDTO**：
```java
@Positive           Integer categoryId    // 分类ID
@Size(1,100)        String title           // 标题
@Size(1,10000)      String content         // 内容
                    Date publishDate        // 发布时间
```

**AnnouncementPublishDTO**：
```java
Date publishDate    // 发布时间（可选，空=当前时间）
```

**AnnouncementSearchDTO**：
```java
@NotBlank @Size(1,50)  String keyword      // 搜索关键词
@Min(1)               Integer page = 1
@Min(1) @Max(50)      Integer size = 10
```

**AnnouncementBatchDeleteDTO**：
```java
@NotEmpty  List<@Positive Integer> ids    // 公告ID列表
```

#### VO 结构

**AnnouncementVO**（完整信息）：
```java
Integer id, categoryId, createUser, updateUser
String categoryName, title, content
Date publishDate, createTime, updateTime
Boolean isPublished    // 计算字段：publishDate != null
```

**AnnouncementSimpleVO**（列表简化，不含 content）：
```java
Integer id, categoryId
String categoryName, title
Date publishDate, createTime
Boolean isPublished
```

#### Service层：AnnouncementsServiceImpl

**路径**：`com.jieni.mqxq.service.impl.content.AnnouncementsServiceImpl`
**依赖注入**：`AnnouncementsDao` + `AnnouncementCategoriesDao`

**创建公告** (`createAnnouncement`)：
```
1. announcementCategoriesDao.queryById(createDTO.getCategoryId()) → 校验分类存在性
2. DTO转Entity：设置categoryId, title(.trim()), content, publishDate
3. 填充时间：createTime=now, updateTime=now
4. 填充操作人：createUser=createUserId, updateUser=同上
5. announcementsDao.insert(announcement)
6. convertToVO(announcement, category) → 返回含categoryName + isPublished
```

**更新公告** (`updateAnnouncement`)：
```
1. announcementsDao.queryById(id) → 校验公告存在性
2. 若 categoryId 非空 → 校验分类存在性
3. 选择性更新：categoryId/title/content/publishDate（非空才更新）
4. 设置 updateTime, updateUser
5. announcementsDao.update(existingAnnouncement) → 动态SET更新
6. 重新查询 + convertToVO → 返回
```

**发布公告** (`publishAnnouncement`)：
```
1. announcementsDao.queryById(id) → 校验存在性
2. 若 publishDate != null → 抛异常"公告已发布，不能重复发布"
3. publishDate = publishDTO.publishDate != null ? publishDTO.publishDate : new Date()
4. announcementsDao.publishAnnouncement(id, publishDate) → UPDATE SET publish_date=?
5. 重新查询 + convertToVO → 返回
```

**撤回公告** (`withdrawAnnouncement`)：
```
1. announcementsDao.queryById(id) → 校验存在性
2. 若 publishDate == null → 抛异常"公告未发布，无需撤回"
3. announcementsDao.withdrawAnnouncement(id) → UPDATE SET publish_date=NULL
4. 重新查询 + convertToVO → 返回
```

**分页查询** (`getAnnouncementPage`)：
```
1. 构建查询条件：title(LIKE模糊), categoryId(精确)
2. PageHelper.startPage(page, size)
3. announcementsDao.queryAllByLimit(condition) → 排序：create_time DESC
4. stream().map(convertToSimpleVO) → 列表转换（每条查一次分类名称）
5. PageInfo复制 → 返回
```

**VO转换关键差异**：
- `convertToVO(entity, category)`：含 content + categoryName + isPublished
- `convertToSimpleVO(entity)`：**不含 content**，需额外查 `announcementCategoriesDao.queryById(categoryId)` 获取分类名称 → **N+1查询**

### 3.4 MyBatis映射要点

#### CarouselDao.xml

- 排序规则：`ORDER BY sort ASC, create_time DESC`
- 通用查询：`Base_Where_Clause` 支持 carouselUrl/LIKE、linkUrl/LIKE、isDeleted/精确
- 物理删除：`DELETE FROM carousel WHERE id = #{id}`
- 动态更新：`<set>` 标签仅更新非空字段
- 批量操作：提供 `insertBatch` 和 `insertOrUpdateBatch`（ON DUPLICATE KEY UPDATE）

#### AnnouncementsDao.xml

- 双字段片段：`Base_Column_List`（含content）vs `Simple_Column_List`（不含content）
- 已发布条件片段：`Published_Where_Clause` = `publish_date IS NOT NULL` + 可选分类/标题筛选
- 发布/撤回：直接 UPDATE publish_date（设值/置NULL）
- 搜索：`WHERE publish_date IS NOT NULL AND (title LIKE '%keyword%' OR content LIKE '%keyword%')`
- 批量删除：`<foreach>` 实现 IN 删除
- 统计：`countPublished`、`countSearchPublished` 分别用于已发布和搜索计数

#### AnnouncementCategoriesDao.xml

- 排序规则：`ORDER BY create_time DESC`
- 名称查询：`queryByName` 使用 `LIMIT 1` 确保返回单条
- 存在性检查：`existsByName` 返回 `COUNT(1) > 0`
- 全量查询：`queryAll` 无分页条件

## 五、已知问题与风险点

> 跨模块系统级问题见 [公共参考-系统级已知问题与风险清单](../../公共参考/系统级已知问题与风险清单.md)，此处仅列本模块独有问题。

### 🔴 严重

| # | 问题 | 位置 | 影响 |
|---|------|------|------|
| 1 | **公告发布/撤回接口 HTTP 方法不匹配** | 前端用 `PUT`，后端用 `POST` | `publish` 和 `withdraw` 两个接口调用必然返回 405，功能完全不可用 |
| 2 | **公告分类删除未校验关联公告** | `AnnouncementCategoriesServiceImpl.deleteCategory()` 第147行 `// TODO` | 删除分类后，`announcements.category_id` 成为悬空外键，关联公告的分类名称显示为空 |
| 3 | **轮播图批量删除接口缺失** | 前端 `api.batchDelete` → `DELETE /api/admin/carousel/batch`，后端无此端点 | 批量删除功能不可用，返回 404 |

### 🟠 高

| # | 问题 | 位置 | 影响 |
|---|------|------|------|
| 4 | **公告列表 N+1 查询** | `AnnouncementsServiceImpl.convertToSimpleVO()` 第473行：每条公告查一次分类名称 | 分页查询 10 条公告产生 11 次 SQL（1次分页 + 10次分类查询），数据量大时性能差 |
| 5 | **CarouselVO 泄露 isDeleted 字段** | `CarouselVO` 包含 `isDeleted` 字段并返回给前端 | 前端不应看到内部删除标记；且 `updateDTO` 可直接修改 `isDeleted` 状态（无权限控制） |
| 6 | **CarouselUpdateDTO 可修改 isDeleted** | `CarouselUpdateDTO.isDeleted` 字段仅 `@Min(0)` 校验 | 管理员可通过更新接口将 isDeleted 改为任意值（如设为1实现"假删除"再恢复），绕过正常的删除/恢复流程 |
| 7 | **公告分类批量删除接口缺失** | 前端 `api.batchDelete` → 后端无对应端点 | 批量删除功能不可用 |
| 8 | **公告搜索无分页计数** | `searchPublishedAnnouncements` 使用 PageHelper 分页但 `AnnouncementsDao.xml` 中 `countSearchPublished` 未被 PageHelper 引用 | PageHelper 可能自动生成 count SQL，但搜索条件中的 `LIKE '%keyword%'` 在 content（LONGTEXT）字段上效率极低 |
| 9 | **CarouselController 多余 @CrossOrigin** | `CarouselController` 有 `@CrossOrigin`，其他5个 Controller 无 | 不一致的跨域配置，全局已有 CORS 处理时此注解多余或冲突 |

### 🟡 中

| # | 问题 | 位置 | 影响 |
|---|------|------|------|
| 10 | **前端公告标题验证不一致** | 前端 `max: 255`，后端 `@Size(1, 100)` | 前端允许255字符但后端拒绝超100字符，边界场景报错 |
| 11 | **前端公告分类验证不一致** | 前端 `description max: 1000`，后端无 @Size 限制 | 前端限制更严但后端无限制，或后端允许超长文本入库 |
| 12 | **公告内容搜索性能风险** | `content` 字段类型为 `longtext`，LIKE 模糊搜索 | 在大文本字段上做 `LIKE '%keyword%'` 无法使用索引，数据量大时极慢 |
| 13 | **轮播图公共接口无鉴权泄露详情** | `CarouselPublicController.getCarouselById` 免登录可查任意轮播图详情 | 包括已标记 `isDeleted=1` 的轮播图，可能泄露下架内容 |
| 14 | **公告分类创建唯一性异常类型** | 后端抛 `MyException`（默认500），前端期望 HTTP 409 | 前端对 409 的友好提示永远不会触发，用户看到的是通用错误信息 |
| 15 | **公告管理页面调试代码残留** | `pms/announcement/index.vue` 中有 `console.log` 调试输出 | 生产环境泄露内部信息 |

### 🔵 低

| # | 问题 | 位置 | 影响 |
|---|------|------|------|
| 16 | **轮播图全量列表接口无分页** | `getAllCarousels()` → `queryAllByLimit(new Carousel())` | 数据量大时一次返回全部记录，但轮播图数据量通常较小 |
| 17 | **公共接口鉴权策略不一致** | `CarouselPublicController` 免登录，`AnnouncementsPublicController` 需 `@SaCheckRole("用户")` | 同为 `/api/public/**` 路径但鉴权要求不同，设计不统一 |
| 18 | **公告分类批量删除传参格式不统一** | 分类 `batchDelete` 传 `{ data: { ids } }`，公告传 `{ data: ids }` | 前端 API 封装风格不一致，增加维护成本 |
| 19 | **CarouselServiceImpl 排序逻辑在 Java 层** | `getEnabledCarouselList` 在 Java 中 `carousels.sort()` 而非 SQL `ORDER BY` | 数据已从数据库查出，Java 层排序无性能优势且增加代码复杂度 |
