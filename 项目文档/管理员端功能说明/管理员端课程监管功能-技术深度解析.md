# 管理员端课程监管功能 - 技术深度解析

> 码趣星球(mqxq)在线教育平台 · 管理员端课程监管模块技术文档

> 涵盖范围：课程管理(上下架)、评论管理(审核/隐藏)、浏览记录管理、用户课程管理(强制退出)、章节/小节/分类管理、作业监管

## 一、功能概述

管理员端"课程监管"功能分布在系统菜单的**"课程管理"**（`CourseManagement`）和**"数据分析"**（`DataAnalysis`）两大分组下，共9个子模块、9个后端Controller、约70个API接口。

### 核心监管能力

| 监管维度 | 说明 | 关键操作 |
|---------|------|---------|
| 课程上下架 | 管理员直接发布/取消发布任意课程 | `publish` / `unpublish`，不受教师权限限制 |
| 课程删除 | 管理员可删除已发布课程（教师不可） | `deleteCourseByAdmin`，无发布状态限制 |
| 评论审核 | 显示/隐藏切换，非独立审批流 | `toggleStatus`(0↔1)、批量隐藏/显示/删除 |
| 内容审查 | 章节CRUD + 小节发布状态管理 | 小节 `PATCH /{id}/status` |
| 作业监管 | 强制发布/取消发布教师作业 | `forcePublish` / `forceUnpublish` + 批量操作 |
| 用户课程管理 | 强制用户退出课程 + 学习统计 | `forceQuit` / `batchQuit` |
| 浏览记录管理 | 查看/删除平台浏览记录 | 分页查询 + 批量删除 |

## 三、后端执行流程

### 3.1 课程管理（CourseAdminController → CourseServiceImpl）

#### Controller层

**路径**：`com.jieni.mqxq.controller.admin.CourseAdminController`
**前缀**：`/api/admin/course`
**鉴权**：`@SaCheckRole("管理员")`（类级别）

| # | HTTP | 路径 | 方法名 | 功能 | 入参 |
|---|------|------|--------|------|------|
| 1 | GET | `/page` | pageCourses | 分页查询(标题/分类/教师/状态) | `CoursePageQueryDTO` |
| 2 | GET | `/{id}` | getCourseDetail | 课程详情 | `@PathVariable id` |
| 3 | POST | `/` | createCourse | 创建课程(指定teacherId) | `CreateCourseDTO` |
| 4 | PUT | `/{id}` | updateCourse | 更新课程 | `UpdateCourseDTO` |
| 5 | **PUT** | `/{id}/publish` | **publishCourse** | **发布课程(上架)** | `@PathVariable id` |
| 6 | **PUT** | `/{id}/unpublish` | **unpublishCourse** | **下架课程** | `@PathVariable id` |
| 7 | DELETE | `/{id}` | deleteCourse | 删除课程 | `@PathVariable id` |
| 8 | GET | `/statistics` | getStatistics | 课程统计 | 无 |

#### Service层管理员方法

**发布课程** (`publishCourseByAdmin`)：
```
1. courseDao.queryById(id) → 校验课程存在性
2. canPublishCourse(courseId) → 检查信息完整性
   - title 非空 && description 非空 && cover 非空
3. 构建 Course: status=1, publishTime=new Date(), updateUser=adminId
4. courseDao.update(updateCourse) → 状态更新
5. courseVectorSyncService.addCourseToVectorStore(publishedCourse) → 同步ES向量库
```

**下架课程** (`unpublishCourseByAdmin`)：
```
1. courseDao.queryById(id) → 校验存在性
2. 构建 Course: status=0, updateUser=adminId
3. courseDao.update(updateCourse) → 状态更新
4. courseVectorSyncService.deleteCourseFromVectorStore(courseId) → 从ES向量库删除
```

**管理员删除课程** (`deleteCourseByAdmin`)：
```
1. courseDao.queryById(id) → 校验存在性
2. courseDao.deleteById(courseId) → 物理删除（与教师不同，无发布状态限制）
3. courseVectorSyncService.deleteCourseFromVectorStore(courseId) → 从ES向量库删除
```

> **管理员 vs 教师差异**：
> - 管理员可直接删除已发布课程，教师不可（教师需先下架）
> - 管理员可发布/下架任意课程，教师只能操作自己的课程
> - 管理员无教师ID校验（`!course.getTeacherId().equals(teacherId)`）

**课程统计** (`getCourseStatistics`)：
```
1. courseDao.queryAllByLimit(new Course()) → 全量查询（全表扫描！）
2. Java Stream: totalCount = allCourses.size()
3. Java Stream: publishedCount = filter(status==1).count()
4. unpublishedCount = totalCount - publishedCount
5. 返回 CourseStatisticsVO(totalCount, publishedCount, unpublishedCount)
```

> ⚠️ **全表扫描反模式**：统计方法查询全部课程后在JVM中用Stream统计，应使用 `SELECT status, COUNT(*) FROM course GROUP BY status` 替代。

**分页查询管理员** (`pageCoursesForAdmin`)：
```
1. 构建 Course condition: title(LIKE)/status(精确)/subjectId(精确)/teacherId(精确)
2. PageHelper.startPage(pageNum, pageSize)
3. courseDao.queryAllByLimit(condition) → SQL排序: (动态ORDER BY)
4. stream().map(convertToListVO) → VO转换
5. ⚠️ 注意：CourseListVO中无teacherName字段，管理员列表中教师只显示ID
```

### 3.2 评论管理（CourseCommentAdminController → CourseCommentServiceImpl）

#### Controller层

**路径**：`com.jieni.mqxq.controller.admin.CourseCommentAdminController`
**前缀**：`/api/admin/comment`
**鉴权**：`@SaCheckRole("管理员")`（类级别）

| # | HTTP | 路径 | 方法名 | 功能 |
|---|------|------|--------|------|
| 1 | GET | `/list` | getCommentsPage | 分页查询(courseId/userId/status/keyword) |
| 2 | GET | `/{id}` | getCommentDetail | 评论详情 |
| 3 | **PUT** | `/{id}/toggle-status` | **toggleCommentStatus** | **切换显示/隐藏** |
| 4 | **PUT** | `/batch-hide` | **batchHideComments** | **批量隐藏** |
| 5 | **PUT** | `/batch-show` | **batchShowComments** | **批量显示** |
| 6 | DELETE | `/{id}` | deleteComment | 删除评论 |
| 7 | DELETE | `/batch-delete` | batchDeleteComments | 批量删除 |
| 8 | GET | `/statistics` | getCommentStatistics | 评论统计 |
| 9 | GET | `/course-rating-rank` | getCourseRatingRank | 评分排行 |

#### Service层管理员方法

**切换评论状态** (`toggleCommentStatus`)：
```
1. courseCommentDao.queryById(commentId) → 校验存在性
2. newStatus = (comment.getStatus() == 1) ? 0 : 1  // 1=显示 → 0=隐藏，0=隐藏 → 1=显示
3. comment.setStatus(newStatus); comment.setUpdateTime(new Date())
4. courseCommentDao.update(comment) → 逐字段UPDATE
5. 返回状态文本 "显示" 或 "隐藏"
```

**批量隐藏/显示** (`batchHideComments` / `batchShowComments`)：
```
1. 遍历 commentIds 列表：
   - courseCommentDao.queryById(id) → 逐条查询
   - comment.setStatus(0或1); comment.setUpdateTime(new Date())
   - courseCommentDao.update(comment) → 逐条UPDATE
2. 返回成功数量
```

> ⚠️ **N×N+1 查询**：批量操作逐条 queryById + update，应使用 `batchUpdateStatus(ids, status)` SQL（DAO中已有此方法但未被调用）。

**评论统计** (`getCommentStatisticsForAdmin`)：
```
1. courseCommentDao.queryAll() → 全量查询（全表扫描！）
2. Java Stream 统计：
   - totalComments = allComments.size()
   - visibleComments = filter(status==1).count()
   - hiddenComments = filter(status==0).count()
   - todayComments = filter(createTime >= 今天0点).count()
   - averageRating = filter(status==1).mapToInt(score).average()
3. 返回 CommentStatisticsVO
```

> ⚠️ **全表扫描**：加载全部评论到JVM后用Stream统计，应使用SQL聚合查询。

**管理员分页查询** (`getCommentsPageForAdmin`)：
```
1. 构建 params: courseId/userId/status/keyword
2. PageHelper.startPage(page, size)
3. courseCommentDao.queryForAdmin(params) → 3表LEFT JOIN
4. convertPageInfo → VO转换
```

**`queryForAdmin` SQL**（3表JOIN）：
```sql
SELECT cc.id, cc.course_id, cc.teacher_id, cc.user_id,
       cc.score, cc.content, cc.status, cc.create_time, cc.update_time,
       c.title AS course_name,
       u.name AS user_nickname,
       u.avatar AS user_avatar
FROM course_comment cc
LEFT JOIN course c ON cc.course_id = c.id
LEFT JOIN user u ON cc.user_id = u.id
WHERE [动态条件]
  AND (cc.content LIKE #{keyword}
       OR u.name LIKE #{keyword}
       OR c.title LIKE #{keyword})
ORDER BY cc.create_time DESC
```

**评分排行SQL** (`getCourseRatingRank`)：
```sql
SELECT c.id AS courseId, c.title AS courseName,
       COUNT(cc.id) AS commentCount,
       ROUND(AVG(cc.score), 2) AS averageRating
FROM course_comment cc
INNER JOIN course c ON cc.course_id = c.id
WHERE cc.status = 1
GROUP BY c.id, c.title
HAVING commentCount > 0
ORDER BY averageRating DESC, commentCount DESC
LIMIT #{limit}
```

**总体学习统计** (`getOverallStudyStatistics`)：
```
1. myCourseDao.queryListByConditions(空参数) → 全量查询（全表扫描！）
2. Java Stream: uniqueUsers, uniqueCourses, totalEnrollments, completionRate
```

**用户学习统计** (`getUserStudyStatistics`)：
```
1. 构建queryDTO: userId, pageNum=1, pageSize=Integer.MAX_VALUE ← 全量加载！
2. myCourseDao.queryListByConditions(params) → 全量查询
3. Java Stream: totalCourses, completedCourses, studyingCourses
```

**课程完成判定逻辑** (`isCourseLearningCompleted`)：
```
1. 查询课程所有章节 → chapterDao.queryAllByLimit
2. 查询课程所有小节 → sectionDao.queryAllByLimit
3. 查询用户浏览记录 → courseViewDao.queryAllByLimit
4. 查询课程所有作业 → courseHomeworkDao.queryByParams
5. 查询用户提交记录 → homeworkSubmissionDao.queryAllByLimit
6. 综合判定: 有浏览记录 && 所有作业已提交 → 已完成
```

> ⚠️ **6次全表扫描**：完成判定方法对一张 my_course 记录触发了6次数据库查询，且多数为 `queryAllByLimit`（无分页条件）。

## 五、已知问题与风险点

### 🔴 严重

| # | 问题 | 位置 | 影响 |
|---|------|------|------|
| 1 | **全表扫描+Java Stream统计反模式** | `getCourseStatistics()`、`getCommentStatisticsForAdmin()`、`getOverallStudyStatistics()` | 加载全部数据到JVM内存后用Stream统计，数据增长后导致OOM和慢查询。应使用SQL `GROUP BY` 聚合 |
| 2 | **批量评论操作N+1查询** | `batchHideComments()`/`batchShowComments()` 逐条 queryById+update | DAO中已有 `batchUpdateStatus(ids, status)` SQL但未被调用。100条评论产生200次SQL |
| 3 | **课程删除无级联清理** | `deleteCourseByAdmin()` 物理删除course记录 | 未清理关联的chapter、section、course_comment、course_view、my_course、course_homework、homework_submission等7张关联表数据，产生大量悬空外键 |
| 4 | **强制退出课程无业务检查** | `myCourseDao.deleteById(id)` 直接物理删除 | 不检查学习进度、不处理作业提交记录、不处理已完成订单关系，可能导致数据不一致 |

### 🟠 高

| # | 问题 | 位置 | 影响 |
|---|------|------|------|
| 5 | **课程完成判定6次全表扫描** | `isCourseLearningCompleted()` 对每条 my_course 记录触发6次DAO查询 | 批量检查完成状态时性能极差，且多数使用 `queryAllByLimit`（无分页） — 系统级风险见 [公共参考-全表扫描反模式](../../公共参考/系统级已知问题与风险清单.md#三8-全表扫描--java-stream-反模式) |
| # | 问题 | 位置 | 影响 |
|---|------|------|------|
| 6 | **管理员分页查询不填充教师名称** | `pageCoursesForAdmin()` 返回的 `CourseListVO` 无teacherName | 管理员课程列表中教师列只显示ID数字，用户需自行对应教师 |
| 7 | **评论统计全表加载** | `getCommentStatisticsForAdmin()` → `courseCommentDao.queryAll()` | 加载全表评论（含content长文本）到内存仅做计数统计，浪费内存和带宽 |
| 8 | **批量删除评论逐条操作** | `batchDeleteComments()` 逐条 deleteById | DAO中有 `batchDelete(ids)` SQL但未被调用，应使用批量DELETE |
| 9 | **管理员可绕过发布前置检查** | `publishCourseByAdmin` 仍调用 `canPublishCourse()` 检查 | 管理员本应有更高权限，但发布仍受title/description/cover非空约束，如果需要强制发布绕过检查则需修改逻辑 |
| 10 | **user统计 pageSize=Integer.MAX_VALUE** | `getUserStudyStatistics()` 中 `queryDTO.setPageSize(Integer.MAX_VALUE)` | 一次性加载用户所有课程记录，数据量大时可能OOM |

### 🟡 中

| # | 问题 | 位置 | 影响 |
|---|------|------|------|
| 11 | **评论关键词搜索注入风险** | `queryForAdmin` 中 `params.put("keyword", "%" + keyword + "%")` + XML中 `LIKE #{keyword}` | Service层已拼接`%`，XML中又用`#{}`，导致实际搜索`%keyword%`变成`%%keyword%%`，前缀`%%`不影响结果但多余；若改用`${}`则有SQL注入风险 |
| 12 | **课程创建时向量库同步时机不当** | `createCourseByAdmin()` 中 `courseVectorSyncService.addCourseToVectorStore(course)` | 新建课程默认 status=0(未发布)，未发布课程不应同步到向量库（学生搜索不应看到未发布课程） |
| 13 | **CommentVO字段冗余** | `convertToVO()` 中 nickname/avatar 同时映射自 userName/userAvatar | VO中有 nickname/avatar 和 userName/userAvatar 两套字段，语义重复 |
| 14 | **checkTeacherCoursePermission 使用 createUser** | `CourseCommentServiceImpl` 第838行 `course.getCreateUser().equals(teacherId)` | 应使用 `course.getTeacherId()` 而非 `createUser`（管理员创建课程时 createUser=adminId≠teacherId） |
| 15 | **课程管理页面无批量操作** | 前端 `pms/course/index.vue` 无批量发布/下架/删除按钮 | 管理员需逐条操作大量课程，效率低 |

### 🔵 低

| # | 问题 | 位置 | 影响 |
|---|------|------|------|
| 16 | **评论批量删除返回值不一致** | `batchDeleteComments` 返回 Integer（成功数），`batchHideComments` 返回 Integer | 但 `deleteCommentByAdmin` 返回 void，接口风格不统一 |
| 17 | **课程统计重复查询** | `getCourseStatistics()` 全量查询后再 Stream 分组 | 应使用 `SELECT COUNT(*) FROM course WHERE status IN (0,1) GROUP BY status` |
| 18 | **教师名称批量填充仍为循环查询** | `fillTeacherNames()` 逐个 `userDao.queryById(teacherId)` | 虽然用Map缓存了结果避免了重复查同一教师，但仍是一个教师一次查询，应使用批量IN查询 |
| 19 | **浏览记录统计全量加载** | `/api/admin/course-view/statistics` | 与其他统计接口一致的全表扫描问题 |
| 20 | **CourseHomeworkDao SQL注入风险** | `CourseHomeworkDao.xml` 中 `${params.orderBy}` | 与之前文档中记录的一致，`orderBy` 使用 `${}` 拼接存在SQL注入风险 |
