# 管理员端用户管理功能 — 技术深度解析

## 一、功能概述

管理员端用户管理模块提供用户 CRUD、角色分配、状态启用/禁用、密码重置、批量删除等功能，以及角色管理的独立 CRUD。涉及前端用户管理和角色管理两个页面、后端两个控制器及三套 Service/DAO 体系（User + Role + UserRole）。

### 功能清单

| 功能 | 前端页面/组件 | 后端端点 | 认证要求 |
|---|---|---|---|
| 用户列表（分页） | pms/user/index.vue | `GET /api/admin/users/list` | `@SaCheckRole("管理员")` |
| 用户详情 | pms/user/index.vue | `GET /api/admin/users/{id}` | `@SaCheckRole("管理员")` |

| 删除用户 | pms/user/index.vue | `DELETE /api/admin/users/{id}` | `@SaCheckRole("管理员")` |
| 批量删除用户 | pms/user/index.vue | `DELETE /api/admin/users/batch` | `@SaCheckRole("管理员")` |

### RBAC 架构

```
┌─────────────┐     ┌───────────────┐     ┌─────────────┐
│    user      │     │   user_role    │     │    role      │
├─────────────┤     ├───────────────┤     ├─────────────┤
│ id (PK)     │◄────│ user_id (FK)  │────►│ id (PK)     │
│ username    │     │ role_id (FK)  │     │ role_name   │
│ password    │     │ id (PK)       │     │ role_code   │
│ name        │     └───────────────┘     └─────────────┘
│ phone       │            多对多关联
│ avatar      │
│ status      │
└─────────────┘
```

### 用户类型判定优先级

| 优先级 | 角色名匹配 | userType | code |
|---|---|---|---|
| 最高 | "ADMIN" 或 "管理员" | 管理员 | ADMIN |
| 中 | "TEACHER" 或 "教师" | 教师 | TEACHER |
| 最低(默认) | 其他 | 用户 | USER |

#### 与用户管理页的差异

- 无批量删除按钮和选择列

- 多"创建时间"和"更新时间"两列

#### ⚠ update 调用参数不一致

```javascript
// index.vue 中调用:
api.update(formData.id, formData)  // 传了两个参数

// api.js 中定义:
update: data => request.put(`/api/admin/role/${data.id}`, data)  // 只用第一个参数 data
```

第二个参数被忽略，功能不影响（id 在 data 中已有），但属于代码冗余/误导。

### 3.3 用户列表查询（`GET /api/admin/users/list`）

```
请求参数: UserQueryDTO {
  pageNum: @Min(1), 默认1,
  pageSize: @Min(1) @Max(100), 默认10,
  keyword?: String,
  userType?: String (ADMIN/TEACHER/USER)
}
│
┌─ Sa-Token 校验: @SaCheckRole("管理员")
│
┌─ 步骤1: PageHelper 分页
│  └── PageHelper.startPage(pageNum, pageSize)
│
┌─ 步骤2: 条件查询
│  ├── userType 非空 → userDao.queryByKeywordAndType(keyword, userType)
│  │   SQL: SELECT u.* FROM user u
│  │        LEFT JOIN user_role ur ON u.id = ur.user_id
│  │        LEFT JOIN role r ON ur.role_id = r.id
│  │        <where>
│  │          [AND (u.username LIKE %keyword% OR u.name LIKE %keyword% OR u.phone LIKE %keyword%)]
│  │          AND r.role_code = #{userType}
│  │        </where>
│  │        GROUP BY u.id
│  │        ORDER BY u.create_time DESC
│  │
│  └── userType 为空 → userDao.queryByKeyword(keyword)
│       SQL: SELECT * FROM user
│       <where>
│         AND (username LIKE %keyword% OR name LIKE %keyword% OR phone LIKE %keyword%)
│       </where>
│       ORDER BY create_time DESC
│
┌─ 步骤3: Entity → VO 转换（⚠ N+1 查询）
│  └── convertToUserVo(): 每条用户记录
│      └── userRoleService.getUserRoleNames(userId)
│          → SQL: SELECT r.role_name FROM user_role ur LEFT JOIN role r ... WHERE ur.user_id = #{userId}
│          → 赋值 roleList 字段
│
└─ 返回 Result<PageInfo<UserVo>>
```

### 3.4 创建用户（`POST /api/admin/users/create`）

```
请求参数: CreateUserDTO {
  username: @NotBlank @Size(3-20) @Pattern(^[a-zA-Z0-9_]+$),
  password?: @Size(6-20), 默认 "123456",
  name: @NotBlank @Size(max=50),
  phone?: @Pattern(^1[3-9]\d{9}$),
  avatar?: String,
  roles?: List<String>, 默认 ["USER"]
}
│
┌─ Sa-Token 校验: @SaCheckRole("管理员")
│
┌─ 步骤1: 用户名唯一性校验
│  └── userDao.selectByUsername(username)
│      → 非空 → MyException("用户名已存在")
│
┌─ 步骤2: 手机号唯一性校验
│  └── userDao.queryAllByLimit(condition={phone})  ⚠ 非典型做法
│      → 非空 → MyException("手机号已被使用")
│
┌─ 步骤3: 构建实体
│  ├── status = 1（默认启用）
│  ├── 密码处理:
│  │   ├── 未提供密码 → 使用默认 "123456"
│  │   └── SaUtil.toBcPassword(password) → BCrypt.hashpw(password, BCrypt.gensalt())
│  ├── createUser = updateUser = SaUtil.getLoginId()
│  └── createTime = updateTime = new Date()
│
┌─ 步骤4: 插入用户
│  └── userDao.insert(user)
│
┌─ 步骤5: 分配角色
│  ├── roles 为空 → 默认 ["USER"]
│  └── assignRolesToUser(userId, roleCodes)
│      ├── 对每个 roleCode:
│      │   ├── roleService.getRoleEntityByCode(roleCode)
│      │   │   → roleDao.queryByRoleCode(roleCode)
│      │   └── userRoleDao.insertUserRole  ⚠ N+1
│      │       SQL: INSERT INTO user_role (user_id, role_id, create_time, update_time)
│      │            SELECT #{userId}, r.id, NOW(), NOW()
│      │            FROM role r WHERE r.role_code = #{roleCode}
│      └── 返回用户详情
│
└─ 返回 Result<UserDetailVO>
```

### 3.5 更新用户（`PUT /api/admin/users/update`）

```
请求参数: UpdateUserDTO {
  id: @NotNull @Min(1),
  name?: @Size(max=50),
  phone?: @Pattern(^1[3-9]\d{9}$),
  avatar?: String,
  roles?: List<String>
}
│
┌─ Sa-Token 校验: @SaCheckRole("管理员")
│
┌─ 步骤1: 存在性检查
│  └── userDao.queryById(id) → null → MyException("用户不存在")
│
┌─ 步骤2: 部分字段更新（仅更新非空字段: name, phone, avatar）
│  ├── updateUser = SaUtil.getLoginId()
│  └── userDao.update(user)
│
┌─ 步骤3: 角色重置（仅当 roles 非空时）
│  └── userRoleService.resetUserRoles(userId, roleCodes)
│      ├── 先删: removeUserRolesByUserId(userId) → DELETE FROM user_role WHERE user_id = #{userId}
│      └── 后增: assignRolesToUser(userId, roleCodes) → INSERT ... SELECT ... FROM role WHERE role_code IN (...)
│
└─ 返回 Result<Void>
```

### 3.6 删除用户（`DELETE /api/admin/users/{id}`）

```
│
┌─ Sa-Token 校验: @SaCheckRole("管理员")
│
┌─ 步骤1: 存在性检查
│
┌─ 步骤2: 删除角色关联
│  └── userRoleService.removeUserRolesByUserId(id)
│      → DELETE FROM user_role WHERE user_id = #{userId}
│
┌─ 步骤3: 删除用户
│  └── userDao.deleteById(id)
│
└─ 返回 Result<Void>

⚠ 硬删除：用户及其角色关联永久删除，无法恢复
⚠ 不检查用户是否有关联订单/课程等业务数据
```

### 3.7 批量删除（`DELETE /api/admin/users/batch`）

```
请求参数: BatchDeleteDTO { ids: @NotNull @NotEmpty List<Integer> }
│
┌─ 步骤1: 先删角色关联
│  └── userRoleService.batchRemoveUserRolesByUserIds(ids)
│      → DELETE FROM user_role WHERE user_id IN (...)
│
┌─ 步骤2: 批量删除用户
│  └── userDao.deleteBatch(ids)
│      → DELETE FROM user WHERE id IN (...)
│
└─ 返回 Result<Void>
```

### 3.8 重置密码（`PUT /api/admin/users/reset-password/{id}`）

```
│
┌─ Sa-Token 校验: @SaCheckRole("管理员")
│
┌─ 步骤1: 存在性检查
│
┌─ 步骤2: 加密默认密码
│  └── SaUtil.toBcPassword("123456") → BCrypt.hashpw("123456", BCrypt.gensalt())
│
┌─ 步骤3: 更新密码
│  └── userDao.update({ id, password })
│
└─ 返回 Result<Void>

⚠ 默认密码硬编码 "123456"
⚠ ⚠ 前端无二次确认弹窗，容易误触
```

│
┌─ 步骤2: 更新状态

### 3.10 用户类型统计（`GET /api/admin/users/statistics`）

```
│
├── userDao.getUserTypeStatistics()
│   SQL: SELECT r.role_code AS userTypeCode, COUNT(DISTINCT u.id) AS count
│        FROM role r
│        LEFT JOIN user_role ur ON r.id = ur.role_id
│        LEFT JOIN user u ON ur.user_id = u.id
│        WHERE r.role_code IN ('ADMIN', 'TEACHER', 'USER')
│        GROUP BY r.role_code
│
└── 映射为 List<UserStatisticsVO>
    { userTypeCode: "ADMIN", userTypeName: "管理员", count: N }
```

### 3.11 角色管理端点

#### RoleController 详析

**基础路径**: `/api/admin/role`
**系统内置角色（不可删除）**: ADMIN, USER, TEACHER
**后端端点数**: 7（前端 api.js 定义 10 个，其中 batchDelete/getPermissions/assignPermissions 无后端实现）

| 操作 | 端点 | 关键逻辑 |
|---|---|---|
| 全量列表 | `GET /list` | `roleDao.queryAll()` → 不分页 |

## 四、前后端交互时序

### 用户列表加载

```
pms/user/index.vue onMounted
│
├── loadRoles()
│   └── GET /api/admin/role/list → 全量角色列表 → 赋值 roleOptions
│
└── loadData()
    └── GET /api/admin/users/list?pageNum=1&pageSize=10&keyword=&userType=
        └── 后端: PageHelper + queryByKeyword/queryByKeywordAndType
            └── convertToUserVo (⚠ N+1: 每条用户查角色名)
        → 赋值 tableData + pagination.itemCount
```

### 创建用户

```
用户点击"新增用户" → 填写表单 → 确定
│
├── 前端验证: username/name/password 必填
├── 构造: { username, password, name, phone, roles: [selectedRole] }
│
├── POST /api/admin/users/create
│   └── 后端:
│       ├── 校验用户名唯一 → 校验手机号唯一
│       ├── BCrypt 加密密码（默认 123456）
│       ├── insert user
│       └── 分配角色（INSERT INTO user_role SELECT FROM role WHERE role_code=?）
│
└── 成功 → 关闭弹窗 → loadData() 刷新列表
```

### 编辑用户

```
用户点击"编辑" →
│
├── GET /api/admin/users/{id}
│   → 获取 UserDetailVO（含 roleList, userType, userTypeCode）
│   → 回填 formData（取 roleList[0] 作为当前角色）
│
├── 修改表单 → 确定
│
├── PUT /api/admin/users/update
│   body: { id, name, phone, roles: [selectedRole] }
│   └── 后端:
│       ├── 部分更新 name/phone
│       └── resetUserRoles（先删后增角色关联）
│
└── 成功 → 关闭弹窗 → loadData() 刷新
```

### 状态切换

```
用户点击 NSwitch 开关
│
├── PUT /api/admin/users/status
│   body: { id, status: 0/1 }
│   └── 后端: 存在性检查 → 更新 status 字段
│
└── 成功 → 刷新列表（失败则恢复开关状态）
```

### 批量删除

```
用户选择多行 → 点击"批量删除"
│
├── DELETE /api/admin/users/batch
│   body: { ids: [1, 2, 3] }
│   └── 后端:
│       ├── 先删 user_role 关联
│       └── 再删 user 记录
│
└── 成功 → 清空 selectedRowKeys → loadData() 刷新
```

## 五、已知问题与风险点

> 跨模块系统级问题见 [公共参考-系统级已知问题与风险清单](../../公共参考/系统级已知问题与风险清单.md)，此处仅列本模块独有问题。

| # | 问题 | 严重度 | 说明 |
|---|---|---|---|
| 1 | **用户列表 N+1 查询** | 高 | `convertToUserVo()` 对每条用户单独调 `getUserRoleNames`，10条记录产生10次额外查询，应改为 JOIN 查询 |
| 2 | **删除用户不检查关联业务数据** | 高 | 删除用户时不检查是否有关联订单(my_course/orders)，可能导致孤立数据或外键约束异常 |
| 3 | **角色撤销功能失效** | 高 | `UserRoleServiceImpl.getRoleCodeByRoleId()` 返回空字符串（TODO），导致 `revokeRoleFromUser` 中 `roleCode.equals("")` 始终 false，撤销角色功能实际不可用 |
| 4 | **手机号唯一性无 DB 约束** | 中 | 仅 Service 层通过 `queryAllByLimit` 检查，并发下可能创建重复手机号用户，且检查方式非典型（应用专用 selectByPhone 方法） |
| 5 | **用户名唯一性无 DB 约束** | 中 | 仅 Service 层检查，并发下可能创建重名用户 |
| 6 | **默认密码硬编码** | 中 | 重置密码硬编码 "123456"，前端无二次确认弹窗，误触即重置，且返回消息暴露默认密码值 |
| 7 | **角色分配先删后增风险** | 中 | `resetUserRoles` 采用"先删全部角色→再重新插入"模式，若插入失败则用户失去所有角色，应使用事务+差异更新 |
| 8 | **前端手机号无校验** | 中 | 用户管理表单中手机号无格式校验（后端有 `@Pattern`），前端可输入任意格式 |
| 9 | **前端角色字段非必填** | 中 | 创建用户时角色下拉非必填（依赖后端默认 "USER"），但管理员意图通常是需要明确指定角色的 |
| 10 | **角色管理 update 调用导致 URL 错误** | 高 | `api.update(formData.id, formData)` 传 `formData.id`（数字）作为第一个参数，但 api.js 定义 `update: data => request.put(\`/api/admin/role/${data.id}\`, data)` 期望接收对象取 `data.id`，数字的 `.id` 为 `undefined`，导致请求 URL 变为 `/api/admin/role/undefined`，角色更新功能实际不可用。应改为 `api.update(formData)` |
| 11 | **UserRoleDetailMap 映射过时** | 低 | UserRoleDao.xml 的详情映射引用了 user 表的 nickname/email 字段，但 User 实体类无此字段，说明映射已过时 |
| 12 | **预留接口无后端实现** | 中 | 前端 role/api.js 定义了 `batchDelete`(DELETE /api/admin/role/batch)、`getPermissions`(GET /api/admin/role/${id}/permissions)、`assignPermissions`(PUT /api/admin/role/${id}/permissions) 三个函数，但后端 RoleController 无对应端点，调用将返回 404 |
| 13 | **用户类型筛选参数可能不匹配** | 低 | 前端 `userType` 值为 ADMIN/TEACHER/USER，后端 UserQueryDTO 的 userType 字段是否直接与 SQL 中 `r.role_code` 匹配需确认 |
| 14 | **角色代码唯一性无 DB 约束** | 低 | role_code 仅 Service 层校验，并发下可能创建重名代码的角色 |
| 15 | **编辑用户 payload 包含后端忽略的字段** | 低 | 编辑用户时 `handleSubmit` 将 `formData.user` 展开（含 username/password）连同 `roles` 发送给 `PUT /api/admin/users/update`，但 `UpdateUserDTO` 无 username 和 password 字段，这些字段被 Spring 静默忽略。前端编辑表单虽隐藏密码输入，但新增时的 password 残留在 formData.user 中未被清除 |
| 16 | **用户表单缺少 avatar 字段** | 低 | `CreateUserDTO` 和 `UpdateUserDTO` 均支持 `avatar` 字段，但前端新增/编辑弹窗无头像输入，avatar 始终为空 |
